# V2.2 机床式蓝图预设重构

- 日期：2026-08-31 14:41
- 类型：新功能增加（预设文件，不含代码改动）

## 一、改动摘要

| 文件 | 改动 |
|------|------|
| `测试预设/Night Voyage 全能进阶核心预设 V2.2.nvpreset.json` | 新建。79 节点 / 113 边的机床式蓝图预设 |
| `测试预设/validate_v22.py` | 新建。结构校验脚本（对齐 blueprint_executor.rs 的 validate_graph 语义） |

核心变化（V2.1 → V2.2）：

1. **机床式结构**：思维链与正文改为「总纲（纯纪律）+ 工位（mutex/group 选项）」模式。总纲不再复述任何工位内容（消解 V2.1 的 status_read/todo_read 与 cot_framework 双重指令问题）。
2. **三铁律下放**：core_identity 从锁定硬编码（is_locked:true）瘦身为纯引擎定位（4 行，解锁）。玩家主权归代理站、客观独立归阻力站、尺度归边界站——消除铁律与 proxy_full/bdry_avoid/res_low 三门的正面冲突。
3. **新增工位**：
   - 清点站 mutex 三档（精简/标准/深度，深度档含范文骨架）
   - 清点增强 group（潜文本识别/防全知/情节纵深；anti_spoil 从独立节点降格为此组选项，消解与 cot 第一步第 5 条的冗余）
   - 推演站 mutex 三档（快速/标准/深度；深度档含身体细节≥2处、依据标注、二次校验）
   - 输出前自检固定件（priority 62，填 V2.1 预留的阶段四槽位；三查：完整性/越权/一致性）
   - 合规强化 group（去欧化/反套话/禁AI腔/内心戏配额）——五预设分析的「防AI八股味」共性
   - 镜头结构 mutex 三选（三拍焦点式/顺叙流/模块化剧情——吸收可待的模块化防雷同机制）
   - **视角让渡 mutex**（锁定/在场让渡/全域让渡）——用户需求：允许 NPC 或世界书角色在合适时机主动进入视角。让渡时机/时长/合法性/判定期四条硬约束；预演在思维链反应清单中标注（总纲与推演深度档各含一条预演指令），执行规则全部在正文段
4. **字数档按预算重算**：16384 token − thinking(~2000) − 附加字段(~500) ≈ 6900 中文字上限。新四档：短打 400-800 / 适中 800-1500 / 长篇 1500-3000 / 自判 400-3000（删除 V2.1 的 5000-8000+ 超预算档与 long/unlimited 重叠）
5. **写指令并入 schema description**（用户决策）：status_write/todo_write/options_rules 三个节点删除，其规则全数并入对应 schema 字段 description（单一真相源；description 经 response_format 与 build_structured_json_directive 双通道到达模型）。
6. **脏边清理**：删除 V2.1 的 group_gate 非法 `out` 端口直连边（e_48 模式）；V2.2 中 4 处同类脏边（census_extra/status/compliance/extra 四个 group 的 `out` 直连）在自查中发现并删除，汇合收敛由 find_merge_node 的共同后继机制承担。
7. **采样参数**：frequency_penalty 0.15→0.3、presence_penalty 0.05→0.15（草稿 §五-5 建议区间起步值），顶层与节点同步。
8. **multiplayer_rules 重写**：聚焦逐人拆解与逐人镜头纪律，新增「本轮放弃发言」处理；输入格式与编译器注入的 MultiplayerProtocol 块保留分工。
9. **output_rules 补 JSON 格式防线**：第 4 条明确输出契约（text/thinking 字位、单一 JSON 对象、禁止 JSON 外文本）。

## 二、改动动机

用户主导的预设调优：V2.1 存在十项已确认毛病（三铁律硬编码冲突、双重指令、anti_spoil 冗余、多人块重叠、todo 点击歧义、脏边、格式防线缺失、预算超限、档位重叠、平行线冲突），本轮以机床式重构一次性消解，并按用户要求「提示词写的精细，每个角度都需要考虑到」——每个工位指令均含执行时机、输入、产出物、边界与禁止项。
