## 业务摘要

SQLite 保持唯一物理存储权威，新增 `.nv.ts` 作为外部分发与 AI 交互载体：

- **依赖**：`Cargo.toml` 引入 `oxc_parser` / `oxc_ast` / `oxc_allocator` / `oxc_span`（0.110，纯 Rust、无动态 C 依赖，不引 Node.js）。
- **新增 `src-tauri/src/services/blueprint_codec.rs`**：
  - **导出（Graph → .nv.ts）**：分区互斥的无损策略——初始状态节点走 `definePreset({ state, __stateNodeId, __statePosition })`、工具定义节点走 `Tools.define`（以 tool_name 为键）、分支节点走 `flow.branch`、宏走 `Macro.define(name, { __id, ... })`；其余全部节点、全部连线与评论逐字进入 `export const nvFragment`，并以 `nodeOrder` 记录原图节点顺序，导入时据此重组，连顺序都无损。DSL 节点的信封（id/position）经 `__nodeId` / `__position` 保留键往返。
  - **导入（.nv.ts → Graph）**：`oxc_parser` 解析 TypeScript AST，只接受字面量表达式（对象/数组/字符串/数字/布尔/null/无插值模板/一元负数），未知顶层语句、未知调用、非字面量、计算键、展开语法一律显式报错（C2）；组装后经真实 `BlueprintGraph` 模型反序列化校验。
  - **自动排版**：缺少坐标的 DSL 节点按连线做最长路径分层（x = 层 × 300，y = 层内序 × 170），即 Dagre 的核心分层思想的纯 Rust 实现；碎片节点坐标不动。
- **MCP 端点**（`src/mcp/tools.rs`）：`nv_preset_export_code(presetId)`（读 presets → 编译代码）与 `nv_preset_import_code(presetId, code)`（前向编译 → 走与编辑器保存相同的 `normalize_blueprint_graph` 归一化校验 → 写回 → 广播 `blueprint:refreshed` 事件，spec §4），并注册进 `all_tools()`。

## 成文说明（与工单字面的偏差）

- **Dagre**：未引入 dagre.js 或其 Rust 移植，落地为同名核心算法（分层拓扑排版）；图的合法性不依赖交叉最小化细节，视觉间距为固定步长。
- **唯一归一化点**：`ToolDefinitionConfig.parameters_schema` 在代码侧以对象呈现（`parameters`），导入时压回紧凑 JSON 字符串——语义等价、空白不保留；其余全部数据逐值无损，由 round-trip 不动点测试锁定。
- **Cargo.lock 未提交**：同工单 01–04 的既定处理（本机 MEM0 垫片导致与上游无关的 lock 漂移）；oxc 版本约束已写入 Cargo.toml，用户侧首次构建自动解析锁定。
