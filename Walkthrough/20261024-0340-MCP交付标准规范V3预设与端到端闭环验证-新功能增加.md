## 2. 改动动机

解决架构规范与验收要求：
1. **严格禁止脚本修改蓝图（用户硬约束）**：严禁使用 `.ps1`、Python 或直接修改 SQLite 修改蓝图和预设，必须暴露 MCP 工具标准接口并经由真实执行链路交付。
2. **终结 V2.2 遗留废案与伪智能体反模式**：以全新 V3.0 宏化智能体与契约驱动预设替换旧版包含 MutexGate 伪智能体的 V2.2 预设，提供权威的标准落地样本。
3. **闭环全链路质量保障**：将宏展开、UI数据契约静态门禁、智能体工具白名单、审阅打回循环与熔断机制在同一真实预设中联合测试并全部通过。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 预设导入解析与执行全部在 Rust 后端完成，前端只消费结果 |
| C2 Zero-Fallback Errors | √ | 契约不匹配、宏定义非法、连线缺少引脚等均直接硬性报错，无静默回退 |
| C3 Responsiveness | √ | 预设解析与编译均为纯内存操作，异步化调度 |
| C4 AI UI Isolation | √ | UI 布局配置挂载至沙箱规范 `rpg_hud_v3` |
| C5 Mobile Frontend Independence | √ | 前端双端独立，本工单验证核心预设对双端统一生效 |
| C6 Project Cache Location | √ | 工具链构建使用 `.cache` 目录，无系统盘写入 |
| C7 PC/Android Coverage | √ | 导入的 V3.0 预设在 PC 与移动端执行引擎中完全通用 |
| C8 MCP-Only Acceptance | √ | 新增 `nv_preset_import` MCP 工具并使用真实测试验证 |
| C9 MCP Rolling Development | √ | 按需敏捷补充 `nv_preset_import` 工具并当场测试验证 |
| C10 MCP Demo Front-Mount | √ | 对应预设管理界面的「导入预设」按钮功能，共享相同业务服务 |
| C11 No Hardcoded Data | √ | 预设数据源自标准 json 资产，消除所有硬编码奇幻 RPG 数值假定 |
