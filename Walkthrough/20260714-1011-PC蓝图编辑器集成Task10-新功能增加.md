## 关键设计决策

### 决策 1：状态管理用 `createStore` + `produce`（非 `createSignal` 整对象替换）

`graph` 是嵌套结构（nodes/edges 数组），用 `createStore` 可实现细粒度更新：
- 节点移动：`setGraph('nodes', prev => prev.map(...))` 只 patch 移动节点的 position
- 节点配置更新：`setGraph('nodes', prev => prev.map(...))` 只 patch 编辑节点的 config
- 删除节点：`setGraph(produce(g => { g.nodes = ...; g.edges = ...; }))` 原子更新 nodes + edges

若用 `createSignal` + 整对象替换，每次节点移动会让所有边重渲染（边端点查找读 `props.graph`）。`createStore` 配合 SolidJS `<For>` 按引用追踪，单节点移动只 patch 该节点。

### 决策 2：保存 payload 构造（`buildBlueprintUpdatePayload`）

后端 `presets_update` SQL 用 `COALESCE(?, blueprint_graph)`，省略 `blueprint_graph` 字段会保留旧值。但其他字段（name/description 等）是 NOT NULL，省略会报错。因此 `buildBlueprintUpdatePayload(detail, blueprintGraph)` 从已加载的 `PresetDetail` 复制全部字段，仅覆盖 `blueprintGraph`，确保 payload 完整。

未复用 `CompletionPresetArea.buildPresetUpdatePayload`，因为该函数不含 `blueprintGraph` 字段，且其设计目标是"从表单状态构造"，与本场景"从已加载 detail 复制 + 覆盖单字段"语义不同。

### 决策 3：旧预设自动迁移（SubTask 10.5）

`onMount` 加载预设后检查 `detail.preset.blueprintGraph`：
- 非空：`JSON.parse` 后用 `produce` 灌入 store（splice 替换 nodes/edges 数组，保留 store 标识）
- 空字符串/不存在：构造 `LegacyPresetForMigration` → 调用 `migrateToBlueprint` → 灌入 store → 立即 `presetsUpdate` 持久化迁移结果 → `setDirty(false)`（已保存）

迁移失败（`result.ok === false`）时回退到空图（Start→End）并 toast 报错（C2 零回退：错误可见，不静默）。

### 决策 4：`handleUpdateNode` 的 `Partial<NodeConfig>` 转换

`NodeConfigPanel.onUpdate` 签名为 `(nodeId, Partial<NodeConfig>)`，但实际始终传入完整的 `{ type, config }` 变体（节点配置组件不会只改 type 不改 config）。因此 `handleUpdateNode` 内部 `cast updates as NodeConfig`，用 `{ id, position, ...patch }` 构造新节点。这是类型系统对判别联合的局部更新限制所致，运行时安全。

### 决策 5：App.tsx 入口集成用 `Show` + accessor 回调

```tsx
<Show when={editingPresetId()} fallback={<PresetPicker />}>
  {(id) => <BlueprintEditor presetId={id()} onClose={() => setEditingPresetId(null)} />}
</Show>
```

`Show` 的回调形式 `{(id) => ...}` 中 `id` 是 `Accessor<number>`，确保 `editingPresetId` 变化时 BlueprintEditor 收到最新值。`fallback` 渲染预设卡片网格，点击卡片 `setEditingPresetId(preset.id)` 切换到编辑器。

### 决策 6：`(graph as BlueprintGraph).version = 2` 类型断言

SolidJS `createStore` 的顶层字段（`graph.version`）不能直接 `setGraph('version', 2)`（store setter 路径不支持字面量字段重赋值），也不支持 `graph.version = 2`（store 是只读代理）。用 `produce` 内部 `(graph as BlueprintGraph).version = 2` 绕过 store 只读保护，因为 `version` 是固定值 2，无响应式需求。

### 验收方式

1. **类型检查**：`npx tsc --noEmit` 退出码 0（真实输出见上）
2. **BlueprintEditorProps 接口**：`{ presetId: number; onClose?: () => void }`
3. **状态管理**：`createStore<BlueprintGraph>` 持有 graph；`createSignal` 持有 selectedNodeId / hiddenNodeIds / isDirty / isLoading / isSaving / error / presetDetail；`createStore<ViewTransform>` 持有视图变换
4. **节点 CRUD**：`handleAddNode`（生成唯一 ID + 视图中心位置 + `defaultConfigForType`）、`handleDeleteNode`（过滤 nodes + 关联 edges）、`handleUpdateNode`（map 替换匹配节点）、`handleNodeMove`（map patch position）
5. **边 CRUD**：`handleEdgeCreate`（生成唯一 ID + push）、`handleEdgeDelete`（filter）
6. **加载生命周期**：`onMount` → `presetsGet` → 解析 `blueprintGraph` 或迁移 → `setGraph(produce(...))`
7. **保存序列化**：`handleSave` → `JSON.stringify({ version, nodes, edges })` → `buildBlueprintUpdatePayload` → `presetsUpdate`
8. **App.tsx 入口**：`case 'workspace'` 渲染预设卡片网格，点击卡片 `setEditingPresetId`，`Show` 切换到 `<BlueprintEditor presetId={id()} onClose={...} />`
9. **旧预设迁移**：`buildLegacyPresetForMigration` 映射 PresetDetail → LegacyPresetForMigration（含 blocks / semanticGroups / 采样参数），`migrateToBlueprint` 返回 graph 后自动 `presetsUpdate` 持久化

### 预期效果

- 用户切换到 `workspace` tab → 看到预设卡片网格（含"蓝图"标签标记已有 blueprint_graph 的预设）
- 点击卡片 → 进入蓝图编辑器，加载该预设的 graph（或自动迁移旧预设）
- 拖拽节点 / 连线 / 编辑配置 → 标记 isDirty，toolbar 显示"未保存"标签
