## 2. 改动动机

解决跑团与游戏机制中三大核心痛点：
1. **记忆与状态膨胀**：旧版将所有历史数据直接塞入 Prompt 导致 Token 随轮次指数膨胀；现通过状态双轨制（数据容器单实例快照持久化 + Schema 倒序滑动硬裁剪 $N \ge 1$）锁定历史 Token 开销为常数。
2. **模型幻觉算数**：旧版让大模型直接修改背包与金币，容易出现凭空生财、死而复生、负重超载等幻觉；现通过 Rust 后端确定性原子运算器（`Calculator`）与多重门禁（`ConditionGate`）强制实行客观规则，不足即阻断。
3. **UI 样式污染与视口杂乱**：旧版每轮对话输出大量状态卡片导致气泡流严重冗余；现通过 Shadow DOM 物理隔离常驻 HUD，由事件驱动原地毫秒级局部刷新，气泡流仅保留正文叙事与思考。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 背包数值加减乘除、负重与金币门禁校验、倒序滑动裁剪算法、D20 CSPRNG 骰点与 Aho-Corasick 禁词扫描全部在 Rust 后端实现，前端仅负责纯渲染与轻量 IPC 交互 |
| C2 Zero-Fallback Errors | √ | 非法 retention_depth（如 <1、0、非数字）严格报错阻断，门禁不足时显式返回拦截回执，无静默吞错或兜底伪成功 |
| C3 Responsiveness | √ | 数据库存取、ToolCall 调度、HUD 增量补丁广播全异步；前端使用细粒度 SolidJS Signal 原地更新 HUD，无主线程阻塞 |
| C4 AI UI Isolation | √ | 常驻 HUD 容器强制挂载在 Shadow DOM（`attachShadow({ mode: 'open' })`）内部运行，内置玄青主题与自定义 CSS 限制在 Shadow Root 内，绝不外溢污染 SolidJS 宿主 |
| C5 Mobile Frontend Independence | √ | PC 端（`src/`）与移动端（`src-mobile/`）严格代码隔离，各自独立实现 `PersistentHudContainer` 与 `MobilePersistentHud`、`AgentDebugDrawer` 与 `MobileAgentDebugModal`，无任何 UI 耦合与 cross-import |
| C6 Project Cache Location | √ | 数据库持久化及数据容器状态均保存在项目指定 SQLite 路径，无向 C 盘或系统目录写入缓存 |
| C7 PC/Android Coverage | √ | 5 大新蓝图节点与常驻 HUD、调试泳道在 PC 与 Mobile 端双端全覆盖落地 |
