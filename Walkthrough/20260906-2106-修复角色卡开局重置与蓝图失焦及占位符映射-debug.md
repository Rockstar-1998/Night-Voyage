# 修复角色卡开局重置与蓝图失焦及占位符映射 Walkthrough

## 改动摘要

本记录针对以下三个核心缺陷进行了双端前端与 Rust 后端的系统性修复：

1. **BUG 1（编辑角色卡开局输入框重置状态）**：
   - `src/components/CharacterSidebar.tsx`（PC 端）：将 `formData().baseSections` 与 `formData().firstMessages` 的循环渲染由 `<For>` 全面重构为 `<Index>`，通过稳定下标追踪 DOM，避免每次输入触发字符串/对象引用变化引起的整行 DOM 销毁重建（解决了滚动条跳顶与 `resize-y` 高度丢失问题）。
   - `src-mobile/components/characters/CharacterDrawer.tsx`（移动端）：同步将 `baseSections()` 与 `firstMessages()` 的 `<For>` 重构为 `<Index>`，确保移动端输入体验一致稳定。

2. **BUG 2（蓝图分支节点选项编辑首字失焦）**：
   - `src/components/blueprint/nodes/MutexGateNode.tsx`（PC 端）：将选项列表的 `<For each={props.config.options}>` 重构为 `<Index each={props.config.options}>`，消除击键更新选项文本时整行 DOM 被判定为新项而销毁导致的即时失焦。
   - `src/components/blueprint/nodes/GroupGateNode.tsx`（PC 端）：同上，将 `props.config.options` 的 `<For>` 重构为 `<Index>`。
   - `src-mobile/components/blueprint/MobileNodeConfigForms.tsx`（移动端）：将 `GateForm` 中的 `props.config.options` 重构为 `<Index>`，保证触控端编辑分支选项时不失焦。

3. **BUG 3（`{{ player_character.name }}` 等占位符未映射为实际值）**：
   - `src-tauri/src/services/prompt_compiler.rs`：
     - 新增 `normalize_st_placeholder_macros`，将 `<user>`、`{{user}}`、`{{user_name}}`、`{{player}}`、`{{player_name}}`、`{{player_character}}` 规范化为 `{{ player_character.name }}`，将 `<char>`、`{{char}}`、`{{char_name}}`、`{{character}}` 规范化为 `{{ character.name }}`。
     - 新增 `render_opening_template` 函数，支持开局消息在会话创建期以角色与玩家角色名、描述进行 minijinja 模板渲染。
     - 在 `PromptTemplateRenderContext` 中扩充 `char` 与 `user` 作为 `character` 与 `player_character` 的直接别名，并在 `render_prompt_template` 与 `validate_prompt_template_syntax` 中自动规范化酒馆方言占位符。
   - `src-tauri/src/commands/conversations.rs`：
     - 在 `conversations_create` 中，插入开局消息前先查询主机角色与玩家角色的名称及描述，调用 `render_opening_template` 将其预渲染为实际姓名后再插入 `messages` 表，确保聊天界面（`messages_list` / `UiMessage`）展示已解析文本。
   - `src-tauri/src/db/mod.rs`：
     - 在 `init_pool` 数据库初始化阶段新增 `repair_unrendered_opening_messages` 异步修复函数，自动扫描历史会话中残留未渲染占位符的开场消息并完成就地修正。

## 改动动机

- **BUG 1**：SolidJS 的 `<For>` 依靠引用比对。当数组元素是基本类型 `string` 时，每次修改产生新字符串，`<For>` 会认为旧节点已被替换并销毁重建整个 DOM 节点，导致输入框高度重置、滚动条瞬间归零。`<Index>` 按稳定下标追踪，仅下发数据信号通知输入框更新，DOM 实例得以保持。
- **BUG 2**：分支门节点配置更新触发深拷贝，导致 options 内的对象引用变更，`<For>` 同样判定为全新元素而替换 DOM，造成输入第一个字符时光标焦点立即丢失。
- **BUG 3**：此前版本只在向 LLM 编译发送 Prompt 时于内存中动态渲染开场 Block，但在会话创建并持久化开局消息到 `messages` 表时直接存入了原始未渲染文本。前端聊天界面读取 `messages` 表，导致用户肉眼直接看到 `{{ player_character.name }}` 等占位符。此外，许多社区角色卡采用 `<user>` / `{{user}}` 等非标准 Jinja 语法，需要统一转译。

## 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 占位符解析与渲染完全由 Rust 后端负责，前端只负责稳定渲染已有消息和表单输入 |
| C2 Zero-Fallback Errors | √ | 模板渲染严格校验（Strict 模式），宏规范化显式转换，失败显式上抛无静默吞错 |
| C3 Responsiveness | √ | 前端细粒度 `<Index>` 追踪避免多余 DOM 销毁和回流，后端异步渲染和启动修复不阻塞 UI |
| C4 AI UI Isolation | √ | 未修改或触碰 AI 渲染沙箱层 |
| C5 Mobile Frontend Independence | √ | PC 端（`src/`）与移动端（`src-mobile/`）代码严格物理隔离，各自独立维护对应组件 |
| C6 Project Cache Location | √ | 构建与运行时缓存全部位于 `D:\data\Night Voyage\.cache` 与 `D:\software_cache`，严禁写入系统盘 |
| C7 PC/Android Coverage | √ | BUG 1 与 BUG 2 均同时修复 PC 端与移动端组件，BUG 3 后端命令与修复逻辑双端完全共享 |
