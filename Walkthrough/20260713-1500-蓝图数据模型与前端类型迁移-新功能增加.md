## 改动动机

蓝图编辑器的运行时执行架构（spec v2）需要一个**与前端类型对齐**的 Rust 数据模型作为图执行器（Task 2）的输入输出契约。Task 1 定义该契约；Task 7 在前端镜像该契约并实现从旧 preset 数据到蓝图图的迁移函数，使旧 preset 可自动迁移到新蓝图格式。

## 关键设计决策

### Task 1：NodeConfig 用内部标签 enum

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "type", content = "config", rename_all = "snake_case")]
pub enum NodeConfig {
    Start,
    End,
    Prompt(PromptConfig),
    SchemaField(SchemaFieldConfig),
    MutexGate(MutexGateConfig),
    GroupGate(GroupGateConfig),
    ModeSwitch(ModeSwitchConfig),
    SamplingParams(SamplingParamsConfig),
}

pub struct BlueprintNode {
    pub id: String,
    #[serde(flatten)]
    pub config: NodeConfig,        // 把 type+config 合并到节点 JSON 顶层
    pub position: Position,
}
```

让 NodeConfig 单枚举同时承载类型判别 + 配置载荷，**从结构上消除"NodeType 与 NodeConfig 变体错配"的无效状态**（符合 guardrails "无效状态不可表达"）。Start/End 用 unit 变体（任务允许），序列化为 `{"type":"start"}` 无 config 字段，匹配 spec JSON。

### Task 1：字段命名用 snake_case（与 spec JSON 对齐）

任务说明要求"struct 必须 `rename_all = "camelCase"`"，但 spec JSON 全程使用 snake_case（`is_locked` / `block_type` / `field_name` / `db_mapping` / `max_tokens` / `top_p` / `gate_id` / `source_port` 等）。任务更高级约束"**保证序列化格式与 spec 给出的 JSON 完全一致**"优先级更高，因此所有 struct 使用默认 snake_case（无 `rename_all`）。`NodeType` / `NodeConfig` 变体用 `rename_all = "snake_case"`。

### Task 1：version 字段用 deserialize_with 校验

```rust
#[serde(deserialize_with = "deserialize_blueprint_version")]
pub version: i32,
```

反序列化时强制 `== 2`，缺失字段由 serde 的 required-field 检查报错。两个错误路径都有可读信息。

### Task 7：双命名约定

| 类型类别 | 命名风格 | 理由 |
|---------|---------|------|
| 图存储类型（BlueprintGraph / BlueprintNode / BlueprintEdge / 所有 *Config / Position / GateOption） | snake_case | 与 spec JSON 完全一致，JSON.parse/stringify 无需转换层。后端 Rust 反序列化时也是 snake_case，无需 `rename_all` |
| 运行时 IPC 类型（GateSelection / BlueprintExecutionContext / CompiledBlock / CompiledSamplingParams / BlueprintExecutionResult） | camelCase | 匹配项目后端 `#[serde(rename_all = "camelCase")]` IPC 约定 |
| 迁移输入类型（LegacyPresetForMigration / LegacyBlock / LegacySemanticGroup） | camelCase | 匹配现有 `src/lib/backend/types.ts` 中的 PresetSummary / PresetPromptBlock 字段命名 |

### Task 7：判别联合实现 BlueprintNode

```typescript
export type BlueprintNode = NodeConfig & { id: string; position: Position };
```

`NodeConfig` 是判别联合（discriminated union），`type` 字段作为判别式，TypeScript 可正确窄化 `config`。`BlueprintNode` 用交叉类型扩展。

### Task 7：MutexGateConfig / GroupGateConfig 不含 selected 字段

运行时选择状态存于 `conversation_gate_selections` 表（Task 3 已实现），不存图里。图执行器（Task 2）从 context.gateSelections 读取。

### Task 7：ChainSegment 抽象统一处理多出口节点

migration.ts 中定义 `ChainSegment` 抽象（head + tails[]），统一处理：
- ModeSwitch 三出口（全部连到同一下游节点）
- MutexGate/GroupGate 多出口（每个 option 一个出口）
- 普通节点单出口

迁移规则：
1. blocks 按 priority 排序 → Prompt 节点链
2. 同 exclusiveGroupKey 的 2+ blocks → MutexGate（每个 block 连到对应 `out_{block.id}` 出口）
3. structuredOutputSchema → SchemaField 节点（db_mapping 按字段名推断：world_variables/plot_summary）
4. semanticGroups → GroupGate（multiple）/ MutexGate（single）
5. 采样参数 → SamplingParams 节点（全 null 时跳过）
6. ModeSwitch 紧跟 Start 之后，三出口全部连到同一下游节点（旧 preset 不区分模式）
7. 链路顺序：Start → ModeSwitch → Prompts/MutexGates → SchemaFields → SemanticGates → SamplingParams → End
