# 蓝图输入框失焦修复 + 蓝图保存 debug 日志

## 改动摘要

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/components/blueprint/NodeConfigPanel.tsx` | 修改 | **焦点修复**：`renderConfig(node())` 函数调用改为 `<Switch>`/`<Match>` 结构，避免每次 config 变化（每次按键）重新挂载组件导致 input 失焦 |

## 改动动机

### 问题 1：蓝图编辑器无法保存

用户报告"蓝图编辑器依然无法保存"。保存链路（前端 `handleSave` → `presetsUpdate` → 后端 `presets_update` 命令 → `PresetService::update`）的错误传播经调查是正确的（无静默吞异常），但需要加详细日志定位具体失败点。

**方案**：创建隔离的 `debug_preset_save.rs` 模块，提供覆盖保存链路每一步的日志函数。业务代码调用这些函数，不直接写 `dbg_eprintln!`，日后清除时只需删除 debug 文件和调用点。

日志覆盖的关键步骤：
- 入口（id/name/blueprint_graph 长度）
- 每个参数校验（name/category/temperature/max_output_tokens/top_p/top_k/penalty/response_mode/thinking/beta_features）
- blueprint_graph JSON 校验
- blocks/semantic_groups/stop_sequences/provider_overrides 校验
- 事务开始
- 预设存在性检查
- blocks 加载
- 锁定块检查
- 仓库 update
- blocks 替换
- 事务提交
- 成功/失败

### 问题 2：输入框打一个字就失焦

**根因**：`NodeConfigPanel` 第 263 行 `{renderConfig(node())}` 是函数调用。在 SolidJS 中，`node()` 是 `<Show>` callback 的 accessor。每次用户在 input 中输入：
1. `onInput` → `props.onUpdate` → 更新 graph store
2. `selectedNode()` memo 重算 → `NodeConfigPanel` 的 `props.node` 变化
3. `<Show>` callback 内部 `node()` 变化 → `{renderConfig(node())}` 表达式重新执行
4. `renderConfig` 返回新的 JSX 元素 → SolidJS `insert` 用新 DOM 替换旧 DOM
5. **input 被重新挂载 → 焦点丢失**

移动端的 `MobileNodeConfigForm` 也有同样问题：`const node = props.node` 是非响应式快照（SolidJS 组件函数只执行一次），加上 `switch` 返回新 JSX，导致表单不更新+失焦。

**修复**：改用 `<Switch>`/`<Match>` 结构。`<Match when={node().type === 'constant'}>` 只在 node **type** 变化时重新挂载组件；config 变化时只更新 props，组件实例保持不变，input 保持焦点。

## 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 前端只做渲染+配置编辑；保存逻辑在后端 |
| C2 Zero-Fallback Errors | √ | debug 日志只记录不吞异常；所有 `map_err` 在记录后原样传播错误（`|e| { log(e); e }`）；焦点修复不涉及错误处理 |
| C3 Responsiveness | √ | `<Switch>`/`<Match>` 是 SolidJS 细粒度响应式，不额外创建 signal |
| C4 AI UI Isolation | √ | 不涉及 |
| C5 Mobile Frontend Independence | √ | PC 和移动端各自独立修复，零 UI 代码互引 |
| C6 Project Cache Location | √ | 不涉及缓存写入 |
| C7 PC/Android Coverage | √ | 双端同步修复焦点问题 |
