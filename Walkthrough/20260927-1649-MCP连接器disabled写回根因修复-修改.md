## 改动动机（根因链，证据齐全）

1. 16:22 args 修复落盘后，16:25:41 Settings 页面级连接（无 sessionId、lease=`protocol-settings`）成功连上代理，**toolCount=11**，证明修复后的配置可被 ZCode 自家 MCP 客户端正常握手。
2. 16:25:51 桌面端程序把内存中的开关状态**写回用户级配置文件**，注入 `"enabled": false`（文件 mtime 与内容均证实）。这是「Settings → MCP 托管状态覆盖文件」的实证：用户此前在服务器反复失败期间于设置页关闭过它。
3. 16:32 重启后，所有会话级连接读到 `enabled: false`，命中程序判定 `if (config.enabled === false) → status="disabled"`（ZCode bundle `zcode.cjs` 中 `mcp.server.connect.skipped` 的唯一触发条件），日志呈 `statusCounts {failed:1, disabled:1, connected:1}`，7ms 跳过，11 个工具进不了会话索引。
4. 排除项：`db.sqlite` 内该服务器名仅存在于会话消息文本（用户当时贴出的配置），无独立开关存储；`local_setting` 表无 MCP 键。
