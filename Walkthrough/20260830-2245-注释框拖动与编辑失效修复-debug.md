# 蓝图编辑器：注释框不能拖动 / 不能写注释 修复

- 日期：2026-08-30 22:45
- 类型：debug
- 任务层级：前端（PC + 移动端）

## 改动摘要

用户验收反馈：注释框不能拖动、不能写注释。排查出三个独立根因，全部修复：

| # | 根因 | 修复 | 文件 |
|---|------|------|------|
| 1 | **渲染漏 transform**：注释框 `<g>` 未应用 `comment.position`（`<rect>` 也没有 x/y），注释框永远画在图坐标 (0,0)（画布左上角）。拖动其实在更新 store，但渲染不消费位置 → 视觉上"拖不动"；编辑输入框按存储位置定位 → 出现在远离可见框的地方 → "写不了"。 | 注释框 `<g>` 补 `transform={translate(comment.position.x, comment.position.y)}`，与节点同模式 | PC `BlueprintCanvas.tsx` + 移动端 `MobileBlueprintCanvas.tsx`（两端同 bug） |
| 2 | **pointer capture 劫持 dblclick**：`handleCommentPointerDown` 对 svg 根 `setPointerCapture` 后，pointerup 被重定向到 svg 根，浏览器派生的 click/dblclick 落在 svg 根而非注释框 `<g>`，`onDblClick` 永远不会触发 → 双击编辑输入框永不出现。 | 移除 `onDblClick` 依赖，改为 pointerdown 内手动双击判定（同框两次按下、400ms 内、位移 <6px）；已在编辑同一框时二次双击不重置输入中的文字 | PC `BlueprintCanvas.tsx` |
| 3 | **点击别处丢输入**：编辑注释时点击画布其他位置走 `cancelCommentEditing()` 直接丢弃，且 pointerdown 的 `preventDefault` 抑制了 input 的 blur，`onBlur` 提交也不会触发。 | 背景 / 节点 / 端口 / 连线四类 pointerdown 入口统一改为 `commitCommentEditing()`（点击别处 = 提交），仅 Esc 保留取消语义 | PC `BlueprintCanvas.tsx` |

移动端注释框编辑走底部编辑栏（受控输入即时落 store），本就无 #2/#3 问题，仅修 #1。

## 改动动机

首版实现只验证了类型与构建，未在真实应用中手点交互，导致三处交互层缺陷漏检。本次修复后已重新构建，交由用户实测验收。
