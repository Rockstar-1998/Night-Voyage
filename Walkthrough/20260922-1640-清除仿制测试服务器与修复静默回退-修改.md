## 2. 改动动机

**仿制链路的危害是结构性的**：它自带一套与 Rust 后端同构但独立演化的规则实现，其"全通过"结论只对该 JS 副本成立，对真实应用零证伪力；而它产出的 snake_case 数据一旦进入真实库，会让真实运行时无法反序列化。保留它等于保留一个持续输出假阳性结论、并污染真实数据源的装置。

**静默回退的危害是不可观测**：游戏状态在提示词编译期被静默丢弃后，模型与玩家都无从感知，表现为数值凭空重置；前端 HUD 的静默空面板同理——失败与"确实没有状态"在界面上完全不可区分。这与项目"永不假死、零静默回退"的硬目标直接冲突。

**诊断依据（证据链闭合）**：真实库 `session_states.state_json` 为 snake_case（`"unit_weight": 2.0`）且 `flags.blueprint_in_effect` 为布尔 `true`；Rust `DataContainer`/`InventoryItem` 为 `#[serde(rename_all = "camelCase")]`，`unitWeight` 无 `#[serde(default)]`，`flags` 为 `HashMap<String, String>`。故 `serde_json::from_str::<DataContainer>` 必然失败。**判定性反证**：若该行不存在，`load_session_state` 返回 `DataContainer::default()`（含 hp/mp/gold/weight 共 7 项默认值），HUD 反而会渲染出数值条；而实际界面数值条为零，唯一对应的是解析失败的 Err 分支。

## 5. 已知限制或后续待办

1. **真实库仍存有不合契约的行**：`session_states` 仅一行（`session_id = 1`，对应 `CP2077_TRPG`），内容为 9-18 由已删除脚本写入的 snake_case JSON。清除前已备份整库至 `D:\software_cache\night-voyage-backups\night-voyage-20260922-155700.sqlite3`（483,328 字节）。**该行不应由外部脚本修复**——应用自身的 `session_game_state_reset`（调试抽屉"重置初始状态"按钮）会经 `save_session_state` 以 serde 序列化重写为合规 camelCase，属唯一合规修复路径。
2. **第三处静默回退（已记录未修）**：`src-tauri/src/services/agent_runtime.rs:88-89` 的 `serde_json::from_str(arguments_json).unwrap_or(Value::Object(Map::new()))` 会把 ToolCall 参数解析失败静默降级为空参数对象。未在本轮修复的原因是：调试抽屉允许提交空参数串，直接改为硬错误会改变该入口的既有可用性，需与入口的前端校验一并设计。
3. **沙箱导致的构建路径约束**：本环境的进程级写入过滤会拒绝 `rustc`/`link.exe` 覆盖既有产物（`os error 5` / `LNK1104`），因此**不能复用 `src-tauri/target` 中已存在的同指纹产物**，必须使用全新 target 目录。既有 `src-tauri/target` 仍为 15.52 GB。
4. **遗留废弃目录**：`D:\software_cache\nv-agent-target`（1.43 GB，未完成的构建输出）因沙箱禁止工作区外写删而无法由本次会话移除，需手工删除。本次产出目录 `src-tauri/target-agent` 为 2.53 GB。
5. **GUI 进程存活限制**：本次工具会话会在每次调用结束时回收其进程树，`Start-Process` 与 WMI 创建进程（被安全策略拦截）均无法让客户端跨调用存活。现场验收需由用户侧启动客户端。
