## 六、修复过程中新发现的上报项（按 Violation Stop Rule 上报，未擅自修复）

1. **director_actor.rs:151-152 parameters_schema 静默回退（存量代码，非本次 hunk 列项）**
   - 风险点：`serde_json::from_str(&schema_json).unwrap_or_else(|_| json!({"type":"object","properties":{}}))`——契约 parameters_schema 非法 JSON 时静默以空 schema 注册，模型侧拿到的工具签名与蓝图声明不符，且无人知晓。
   - 影响范围：所有声明了非法 parameters_schema 的蓝图 ToolDefinition 契约；编译期无感，故障表现为模型侧调用参数失真。
   - 建议的修正方向：在 blueprint_executor 契约收集处对非法 schema 硬错（与 InvalidStepBudget/InvalidToolRounds 同策略），或归一化校验阶段拒绝非法 JSON。
2. **MobilePresetBlueprintEntry.tsx 存量引用 `src/lib/backend`（架构灰区，非本次引入）**
   - 风险点：移动端入口 import `'../../../src/lib/backend'`（presetsGet/presetsList 等一批绑定），与「移动端独立项目、仅经各自绑定层访问后端」的 C5 目录隔离口径存在张力；本次修复未新增此类引用，但也未清理存量。
   - 影响范围：src-mobile 全部经 `../../../src/lib/backend` 取数的模块；双 Vite 构建可编译，属治理问题而非运行缺陷。
   - 建议的修正方向：列独立治理工单，把被移动端消费的绑定逐步下沉/复制到 `src-mobile/lib/backend` 本地层，最终消除跨项目 import。
