# 移动端 Provider 设置 TSC 类型错误修复

## 1. 改动摘要

### 任务范围内的修复（B1/B2/B3 + D21-D24）

**`src-mobile/components/settings/ApiProviderDrawer.tsx`**

- **行 2（D21）**：删除未使用的 `AlertTriangle`、`CheckCircle2` import，保留 `Save, Trash2, X, RefreshCw`。
- **行 48-88（B1/B2）**：重构 `handleSave`，原先用单一 `payload` 对象（`baseUrl: ... || undefined`、`apiKey: ... || undefined`）展开传给 `providersUpdate`/`providersCreate`，导致 `baseUrl: string | undefined` 不兼容后端要求的 `baseUrl: string`（TS2345）。

    - create 路径：`apiKey: trimmedApiKey`（后端 `apiKey: string` 必传，调用前已校验非空）
  - 未使用 `?? ''` / `as any` 等兜底掩盖空值。

**`src-mobile/components/settings/SettingsTab.tsx`**

- **行 2（D22）**：删除未使用的 `Save, Trash2, CheckCircle2, AlertTriangle, RefreshCw` import，保留 `ChevronRight, Globe, Palette, Plus, ChevronLeft`。
- **行 3（D23/D24）**：删除未使用的 `ProviderKind` 类型 import 和 `providersCreate, providersUpdate, providersDelete, providersTest` 4 个后端封装调用 import，仅保留 `ApiProviderSummary`。
- **行 135（B3）**：将 `provider.models.join(', ') || '未配置模型'` 改为 `provider.modelName || '未配置模型'`。
  - 原因：后端 `ApiProviderSummary`（`src-tauri/src/models/mod.rs:20-31`）只有 `model_name: String`，无 `models` 数组字段。PC 端 `src/components/settings/ApiProviderManager.tsx:130` 同样使用 `provider.modelName`，两端行为一致。

## 5. 已知限制或后续待办

1. **`ApiProviderDrawer.tsx` handleTest 仍用 `as any`**（行 109 附近，未在本次任务范围）：`const payload: any = props.provider ? {...} : {...}`，且未传 `modelName`，与 PC 端 `providersTest` 签名（要求 `baseUrl/apiKey/modelName` 均为 `string`）不符。`as any` 掩盖了潜在类型错误，违反 C2 精神，但属本次任务范围外的预存问题，未改动。建议后续单独修复，移除 `any` 并补全 `modelName`。
2. **`ApiProviderDrawer.tsx` modelName 的 `'<empty>'` 哨兵值**：`modelName().trim() || '<empty>'` 在用户未填模型名时会向后端写入字面量 `<empty>`，后续 LLM 调用会失败。这是预存行为，本次未改动（不在任务范围）。建议后续改为显式校验或后端拒绝哨兵值。
3. **移动端通过 `../../../src/lib/backend` 引用 PC 前端目录的 Tauri 封装**：这是项目既有的共享 backend command wrapper 架构（非 UI 代码耦合，guardrails 允许「共享层只通过 Rust 后端」）。但 import 路径穿过 `src/` 目录，未来若 PC 前端重组目录会影响移动端构建。建议评估是否抽出到独立的 `shared/` 目录，但属架构调整，需用户批准，不在本次范围。
