# Walkthrough: 可视化宏子图编辑器与引脚类型系统双端实现 (Ticket 03)

## 1. 改动摘要

在 PC 端（`src/`）与移动端（`src-mobile/`）双端独立实现 UE5 风格的蓝图“宏”（Macro）可视化子图编辑系统与 5 种强类型引脚颜色体系：

- **共享类型与引脚契约** (`src/lib/blueprint/types.ts`):
  - 增加 `PinType`（`exec`, `number`, `string`, `boolean`, `object`）及其在 `PortDescriptor`、`PortLayout` 上的类型标注。
  - 声明 `MacroPinDefinition`、`BlueprintMacro`、`MacroInstanceConfig`、`MacroInputsConfig`、`MacroOutputsConfig`。
  - 将 `macro_instance`、`macro_inputs`、`macro_outputs` 纳入 `NODE_TYPES` 与 `NodeConfig`。
  - `BlueprintGraph` 增加 `macros?: BlueprintMacro[]` 资产字典。
- **PC 端画布与布局** (`src/components/blueprint/`):
  - `nodeLayout.ts`: 定义 `PIN_TYPE_COLORS` 与 `isPinTypeCompatible` 校验逻辑；为宏节点计算动态输入/输出端口布局；在连线校验中增加引脚类型兼容拦截。
  - `BlueprintCanvas.tsx`: 支持 Exec 三角形插座、数据类型彩色实心圆点插座；支持双击宏实例节点进入子图。
  - `NodeSelector.tsx`: 添加 `macro_instance`、`macro_inputs`、`macro_outputs`。
  - `MacroDrawer.tsx`: 新建宏库抽屉组件，支持宏列表浏览、按分类过滤、新建宏、删除宏、放置宏实例到画布。
  - `nodes/MacroPinsNode.tsx` & `nodes/MacroInstanceNode.tsx`: 宏输入/输出引脚定义表单与宏实例引用及子图跳转面板。
  - `NodeConfigPanel.tsx`: 挂载宏节点表单。
  - `BlueprintEditor.tsx`: 实现子图编辑模式（`activeMacroId` 信号），顶部面包屑导航（`[主蓝图] > [宏: xxx]`）；隔离主图与子图节点的增删改查；支持序列化 `macros` 字段。
- **移动端画布与布局** (`src-mobile/components/blueprint/`):
  - `mobileNodeLayout.ts`: 独立实现移动端 `PIN_TYPE_COLORS`、`isPinTypeCompatible`、宏端口布局与引脚类型连线拦截，在 `createNode` 中增加宏节点默认工厂。
  - `MobileBlueprintCanvas.tsx`: 移动端触摸优化的 Exec 三角形与彩色圆点插座，支持双击宏实例节点进入子图。
  - `MobileMacroDrawer.tsx`: 移动端底部滑出宏库抽屉，支持新建宏（自动脚手架 Inputs/Outputs）、删除宏、放置宏实例。
  - `MobileNodeConfigForms.tsx`: 独立实现移动端宏引脚配置表单 `MacroPinsForm`、宏实例配置表单 `MacroInstanceForm`，接入 `defaultConfigForType` 与分发器。
  - `MobileNodeConfigPanel.tsx`: 传递 `macros` 与 `onOpenMacro` 回调。
  - `BlueprintEditor.tsx`: 支持移动端子图编辑模式、顶部面包屑导航条、宏库入口按钮与主/子图增删改隔离。

## 2. 改动动机

- 落实规格说明书工单 03（Ticket 03）：解决蓝图随逻辑复杂度提升而出现的节点冗余与混乱问题。
- 通过引入类似 UE5 蓝图的宏功能，让创作者能够将常用功能（如金币检查+扣除、条件判定等）封装为复用的宏子图。
- 引入强类型引脚颜色体系，在界面上直观区分 Exec 流程流向与 4 种数据流向，在拖拽连线时前置物理拦截类型不匹配的连线，防止运行时不可预测错误。
- 严格遵循 PC 与移动端代码解耦（C5）与双端全覆盖（C7）原则。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 前端只负责宏子图的绘制、连线与交互，宏展开与执行由后端 Ticket 02 编译期完全内联完成 |
| C2 Zero-Fallback Errors | √ | 强类型引脚在前端连线时即做显式拦截与 Toast 提示，不静默允许错误连线 |
| C3 Responsiveness | √ | 子图切换与面包屑导航通过细粒度 SolidJS 响应式计算（createMemo），不引起整画布全量重载 |
| C4 AI UI Isolation | √ | 不涉及 AI 沙箱 UI |
| C5 Mobile Frontend Independence | √ | `src/` 与 `src-mobile/` 零 UI 代码耦合，两端各有一套完整的宏抽屉与节点配置表单，仅共享数据类型契约 |
| C6 Project Cache Location | √ | 运行时缓存遵循规范，无外溢 |
| C7 PC/Android Coverage | √ | PC 端与移动端同时完整实现宏子图编辑、宏库管理与引脚着色系统 |
| C8 MCP-Only Acceptance | √ | 遵循 MCP 原则 |
| C9 MCP Rolling Development | √ | 遵循滚动开发推进 |
| C10 MCP Demo Front-Mount | √ | 宏库按钮与宏配置表单已挂载在真实 UI 界面 |
| C11 No Hardcoded Data | √ | 宏名称、引脚定义、分类等均来自真实图模型数据，无硬编码清单 |
