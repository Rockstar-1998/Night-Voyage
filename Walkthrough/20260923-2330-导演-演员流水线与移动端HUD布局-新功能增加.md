## 运作机制

### 导演-演员流水线

```
导演·分镜 ──► JSON { beats: [{ slot_id, character, focus }] } ──► parse_director_plan（严格校验）
   │
   └─ 每个 beat：演员视界裁剪（只保留含该角色名的设定块；未命中 → 完整共享设定 + Info 事件说明）
        └─ run_subagent 演出 → agent_drafts(actor:<slot_id>) + SubAgent 事件
   │
导演·装配 ──► 各槽位成品按 slot_id 顺序交给导演缝合成定稿 ──► 终稿过禁词门禁 ──► 落盘
```

- 解析允许模型用 ` ```json ` 包裹；除此之外任何偏差（非对象、缺 `beats`、空 `beats`、槽位缺 `slot_id`/`focus`）都报错。
  理由：解析失败就放行等于让"导演什么都没说"也照演。
- 演员失败 → 整条流水线失败（`agent_runs` 标记 `failed`），不做"跳过这个演员"的降级。
- 终稿同样过禁词门禁：流水线不豁免内容合规。

### 移动端 HUD

- `presetUiLayoutForConversation` 取会话绑定布局；未绑定/失败 → 内置吸顶条（产品既定视图），失败原因以 `.hud-error` 显示。
- 只有 `mobileDrawer` / `mobileBottomSticky` 锚点在移动端渲染；PC 锚点布局给出显式提示而非硬塞进移动端视口。

## 约束合规审计

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 移动端渲染器只渲染；裁剪/计划解析全在后端 |
| C2 Zero-Fallback Errors | √ | 导演计划解析/演员调用/装配任一失败即报错；流水线失败标记 `agent_runs` 为 failed |
| C3 Responsiveness | √ | 流水线在流任务内串行执行，不阻塞 UI 线程 |
| C4 AI UI Isolation | √ | 布局自带 CSS 只注入移动端 Shadow DOM |
| C5 Mobile Frontend Independence | √ | `MobileLayoutTree` 为移动端独立实现，未引 PC 组件；绑定解析也在移动端本地实现 |
| C6 Project Cache Location | √ | 无新增落盘 |
| C7 PC/Android Coverage | √ | 两条流水线在后端共享；移动端 HUD 布局与时序泳道已同步覆盖 |
| C8–C11 | √ | 无脚本验收；无一次性工具；无硬编码数据（角色/镜头全部来自模型与预设） |
