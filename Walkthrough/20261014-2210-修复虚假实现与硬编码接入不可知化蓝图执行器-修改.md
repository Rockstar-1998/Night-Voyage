# 修复虚假实现与硬编码接入不可知化蓝图执行器

## 1. 改动摘要

本次改动彻底消除了中间件与前端桥接器中的伪造分支与业务硬编码，完成了与 Rust 后端 `agent_runtime` 同构的**不可知化蓝图拓扑执行器（Agnostic Blueprint Graph Evaluator）**，驱动真实 SQLite 数据库中的蓝图资产完成所有工具执行、条件判定与状态持久化：

- **`src/lib/backend/browserBridge.ts`**:
  - 拔除第 86 行业务特化的 `args.command === 'buy_item'` 分支；
  - 统一为不可知化的状态突变白名单判定：`const stateMutatingCommands = ['session_tool_call_execute', 'session_game_state_save', 'session_game_state_reset', 'action_bridge_invoke'];`，只要任何引起游戏状态或蓝图执行的命令发生，自动通知 HUD 状态变更，彻底解耦游戏玩法语义；
  - `action_bridge_invoke` 移除一切对具体业务参数的预设伪造，严格透传至后端/中间件。
- **`scripts/sqlite_ipc_middleware.mjs`**:
  - **彻底清除业务特化假实现**: 根除原先硬编码的 `buy_item` 伪造字典、硬编码的矮人铁匠格罗姆、硬编码的物品单价表与伪造背包；
  - **构建与 Rust 同构的不可知化蓝图拓扑执行器 `executeBlueprintToolPlan`**:
    1. 根据会话 ID (`session_id`) 查询 `conversations.preset_id`，并从 `presets.blueprint_graph` 解析出完整拓扑图；
    2. 在蓝图节点中动态寻找 `type === 'ToolDefinition'` 且 `config.name === toolName` 的入口契约节点；若未找到，根据 C2 严格抛出 `蓝图未定义契约工具: ${toolName}`；
    3. 校验调用参数与 `parameters_schema` 的数据类型与必填约束；
    4. 沿节点的出边端口（`out` / `pass`）在拓扑图中递归遍历执行：
       - `ConditionGate`: 对会话状态字段进行原子数值/集合比较（如 `>=`、`<=`、`==`、`in`）。若不满足门禁，立即阻断并抛出 `block_reason`，确保容器零修改；
       - `Calculator`: 对金币、生命值等进行原子数学运算（如 `add`、`subtract`、`multiply`），或对容器/背包执行原子变更（`append`、`remove`）；
       - `Inspector`: 真实读取 SQLite `session_states`，返回当前变量容器内容（如背包清单）；
       - `Writer`: 将运算结果原子写回 SQLite `session_states`；
       - `ToolReturn`: 提取终态模板并进行变量插值（如 `成功购买 {item}，花费 {price} 金币`），返回标准执行回执；
  - **ActionBridge 真实数据库查询**:
    - `get_character_detail`: 真实执行 `SELECT * FROM character_cards WHERE id = ?`；
    - `create_world_book_entry`: 根据会话关联的 `world_book_id`，真实插入 `world_book_entries` 表；
    - `query_world_book_entries`: 根据会话关联的 `world_book_id`，真实进行 SQL `LIKE` 模糊匹配检索；
    - 白名单未注册工具严格显式报错（C2 零静默回退）；
  - **真实 MCP 暴露列表**: `mcp_tool_names` 严格对齐 Rust 后端 `all_tools()`（包括 `nv_db_info`, `nv_conversations_list`, `nv_session_state_*` 等），严禁一次性私有工具。

## 2. 改动动机

- 用户在 `/code-review` 中明确指出：不可知化核心（Agnostic Core）的核心要义是**引擎底座不得包含任何游戏/业务特化硬编码**。代码中绝不能出现特定游戏名（如格罗姆、铁铸长剑、特化的 buy_item 逻辑）。业务逻辑与玩法数值只能存在于预设蓝图（Blueprint Graph）资产中。
- 此前中间件存在假实现兜底和硬编码分支，违反了核心约束 C11（No Hardcoded Data）、C2（Zero-Fallback Errors）和不变量 I1（不可知化核心数据驱动）。
- 必须实现通用的蓝图执行逻辑，使得修改蓝图资产节点即可直接改变执行行为，零代码修改，真正做到数据驱动与真实数据库持久化。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
