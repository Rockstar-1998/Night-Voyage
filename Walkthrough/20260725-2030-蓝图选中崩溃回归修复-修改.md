# [修改] 蓝图编辑器节点选中崩溃回归修复

## 1. 改动摘要

用户报告「节点无法被选中了」。经代码审查：

- `BlueprintCanvas.tsx` 工作区纯净（与 HEAD 一致），画布选中链路
  `handleNodePointerDown → props.onNodeSelect(node.id) → setSelectedNodeId`
  未被本次会话任何改动触及，逻辑完好。
- 在「SchemaField 节点扩展」轮中重写了 `SchemaFieldNode.tsx`，新增对
  `display` / `required` / `context_included` 三个字段的访问（第 171/182
  行直接读 `props.config.display.default_expanded`）。
- **回归**：旧预设（扩展字段加入前保存进 DB 的蓝图）的 schema_field 节点
  `config` 中**没有 `display` 字段**。选中该节点时
  `props.config.display.default_expanded` 抛
  `Cannot read properties of undefined (reading 'default_expanded')`，
  整个编辑器 React/Solid 树崩溃，用户侧表现为「点节点没反应 / 选不中」。

修复文件：

| 文件 | 改动 |
|------|------|
| `src/components/blueprint/nodes/SchemaFieldNode.tsx` | `display`/`required`/`context_included` 全部加运行时兜底（`??` 默认值）；新增 `display` 局部变量统一读取 |
| `src/components/blueprint/nodeLayout.ts` | `autoLayout` 节点 y 从 `startY = -totalHeight/2`（负值，可能跑到视口上方外）改为正数顶部边距（`TOP_MARGIN=40` + `COLUMN_VPAD=20`）起排，确保任何 pan offset 下节点都在可见区 |

## 2. 改动动机

- **Zero-Fallback（C2）**：旧数据缺字段不应导致渲染崩溃，应安全兜底为合理默认值。
- 选中链路本身未坏，坏的是「选中 schema_field 节点时面板组件崩溃」，属于扩展新字段时未兼容存量数据。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 仅前端 UI 兜底，无后端调用 |
| C2 Zero-Fallback Errors | √ | 旧数据缺字段不再崩溃，安全兜底 |
| C3 Responsiveness | √ | 仅加 `??` 短路，无额外计算 |
| C4 AI UI Isolation | √ | 不涉及 |
| C5 Mobile Frontend Independence | √ | 仅改 PC 端 SchemaFieldNode；移动端 SchemaFieldForm 仍是 JSON 文本框，不受影响 |
| C6 Project Cache Location | √ | 不涉及 |
| C7 PC/Android Coverage | √ | autoLayout 改动同时影响 PC/mobile 两端调用方（移动端 mobileNodeLayout 有独立 autoLayout 实现，未改） |

## 4. 验收记录

- 构建命令：`npx tsc --noEmit`（PC）、`npx tsc --noEmit -p tsconfig.mobile.json`
- 预期效果：类型通过，旧数据 schema_field 节点选中不再崩溃
- 实际结果：两端 tsc 均通过（无错误输出）
- **未能端到端复现**：sandbox 无 Tauri 运行时，无法在真实环境点击验证选中行为。

## 5. 已知限制 / 待办

- sandbox 无法跑 Tauri，未做浏览器端到端点击验证。需在用户真实环境确认：
  - 若现象为「点某个 schema_field 节点崩 / 选不中」→ 本次兜底应已修复。
  - 若现象为「点**任意**节点都没反应（包括 prompt/start 等非 schema 节点）」→ 说明是画布层问题，但代码审查中画布选中链路完好未被改动，需进一步信息：哪端（PC/移动）？点哪类节点？选中后右侧面板是否出现？节点是否高亮？
- 移动端 `mobileNodeLayout.ts` 有自己的 `autoLayout` 实现（独立副本），本次只修了 PC 端 `nodeLayout.ts` 的 `autoLayout`；若移动端需要同样的正数边距，应同步修改移动端副本。
