## 改动动机

工单 03 第 1 项残余：导演-演员是全仓最后一处硬编码流水线——分镜数由导演结构化输出在运行时决定，其扇出拓扑无法用线性接力计划表达，故在工单 03 落地时留证待 FanOut 节点设计拍板。本阶段为计划 IR 新增 FanOut 节点种类，把扇出本身表达为图语义，导演-演员与剧本流水线自此共用同一个计划 IR 与同一个拓扑执行器，硬编码编排清零。

## 设计决策（codebase-design 词汇）

- **Module 与 Interface 不变**：`graph_orchestrator` 这个 Module 的 Interface 保持原样——调用方仍然是「计划编译（资产 → `OrchestrationPlan`）→ `execute_orchestration_plan` + 阶段执行闭包 seam」这一条路径。没有新建平行流水线模块，没有给 Interface 增加新的执行入口或方法面；FanOut 是该 Module **Implementation 内部**的深化：`PlanNode` 新增 `kind: PlanNodeKind` 字段（`Standard` / `DirectorPlan` / `FanOutActors`），`NodeInput` 新增 `FanOutBeats` / `FanOutAssembly` 两种装配方式，执行器游走循环内部处理。
- **Seam 由假想变真实**：工单 03 落地时计划 IR 只有一个 Adapter（`compile_scriptwriter_plan`），「资产 → 计划」这条 Seam 只有一个实现，按技能判据只是假想 seam。本阶段新增第二个 Adapter `compile_director_plan`（`DirectorConfig` + `&[ActorDefinition]` → 计划），两个编译器产出同一种 IR、由同一个执行器游走——seam 被第二个实现证成为真实 seam：任何一侧资产结构变化只需改对应编译器，执行器与另一条流水线不受影响（Locality）。
- **Depth / Leverage 变化**：执行器一处实现同时服务两条流水线（Leverage：扇出、汇聚、熔断、Scratchpad 流转只写一遍）；调用方为导演-演员付出的 Interface 成本与剧本流水线完全相同（一次编译 + 一次执行 + 一个闭包），Depth 提升。删除测试验证：若删掉 `graph_orchestrator`，两条流水线的编排复杂度会同时回潮到各自调用方——该 Module 在挣自己的位置。
- **Interface 即测试面**：新增测试全部经编译器 + 执行器 + 假阶段闭包这条既有 Interface 驱动，不触碰任何内部私有辅助函数。

## FanOut 的 PlanNode 表达与执行机制

- **导演节点**（`kind = DirectorPlan { max_beats}`，`input = UserInput`）：执行器以玩家输入调用阶段闭包，产出经 `parse_director_plan` 解析为分镜集（非法 JSON / 空 beats 在解析层显式报错）；分镜数超过 `max_beats` 显式报错；分镜集序列化写入 Scratchpad `director:beats`。
- **FanOut 节点**（`kind = FanOutActors { actors, max_beats}`，`input = FanOutBeats`）：执行器在运行时按分镜数逐镜串行实例化演员节点——串行是刻意的：与旧实现一致，每位演员的用户提示词包含前序分镜演出，保序且视界递进。每镜构造一个演员阶段资产（`stage = actor:{slot_id}`、`prompt = persona`、`tools` / `tool_permissions` 来自命中的 `ActorDefinition`；未命中资产时 persona 与工具为空，走旧路径视界裁剪），当前镜头上下文（`fanout:current_beat` JSON、`fanout:beat_index`、`fanout:beat_total`）写入 Scratchpad 供阶段调用方做视界裁剪与时间线定位；演员产出写入 `actor:{slot_id}` 并按分镜序收集。
- **汇聚节点**（`kind = Standard`，`input = FanOutAssembly`）：FanOut 汇聚结果（`[{slot_id, text}]`，按分镜序）写入 Scratchpad `fanout:results`；汇聚节点把各槽位产出按分镜序装配为与旧实现逐字一致的装配输入，调用阶段闭包缝合定稿，写入 `final` 后返回。

### 显式化语义（C2）

- **分镜数上限**：`MAX_DIRECTOR_BEATS = 32`（显式命名常量）。来源：`DirectorConfig` 资产没有分镜数上限字段，本常量是执行器熔断值（防导演异常产出无界扇出耗尽 API 余额，对应 spec 用户故事 5 的熔断精神），32 远高于正常分镜规模；导演节点与 FanOut 节点双重校验，超限**显式报错不截断**。
- **导演产出分镜为空**：显式报错（解析层「beats 为空」； FanOut 节点在分镜集为空时报「分镜集为空」，手工构造的无导演供数计划同样锁定此行为），不以空扇出静默续跑到汇聚节点。
- **单个演员失败**：整个计划显式失败，错误带完整定位信息——`FanOut 演员执行失败（分镜 {i}/{total}，slot_id={slot}，character={character}）：{原始错误}`；不静默丢弃、不以空串顶替、不默认成功。失败镜之前的产出保留在 Scratchpad，失败镜及之后无产出、无汇聚结果（测试锁定）。

## 第二编译器 `compile_director_plan`

- 输入：`&DirectorConfig` + `&[ActorDefinition]`（蓝图编排资产）。
- 输出：3 节点 `OrchestrationPlan`——导演节点（`stage = director:plan`，prompt / tools / tool_permissions 来自导演资产）→ FanOut 节点（携带演员资产全集与上限）→ 汇聚节点（`stage = director:assembly`，prompt 为装配指令）。
- 编译期校验：演员 `actor_name` 为空或重复即编译错误（分镜 `character` 引用将歧义，绝不留到运行时才发现）。

## 接线与删除

- `director_actor::run_director_actor_pipeline` 同名入口保留为薄入口：`record_run_start` → 资产装配（编排资产加载、导演缺失显式报错、ToolCall 契约表编译与全局能力池工具注入，与旧实现同序同源）→ `compile_director_plan` → `execute_orchestration_plan`（阶段闭包按 `stage` 身份分发导演 / 演员 / 装配三类真实调用）→ 成功 `record_run_finish(completed)` / 失败统一 `record_run_finish(failed)` 后显式返回错误。
- 阶段闭包分发：导演阶段（全量 system + 导演 prompt、结构化 Schema、工具循环、`director:plan` 草稿记账与时间线）；演员阶段（视界裁剪、工具循环、草稿记账、成功 / 失败时间线，失败先发 Failed 事件再上抛）；装配阶段（经 `stage_call` 以「导演·装配」调用）。工具执行回调抽为 `make_tool_execute` 辅助函数（导演 / 演员共用同一条 `execute_tool_call_with_plan` 链），消除旧实现两处重复装配。
- 删除：旧 `run_director_actor_pipeline` 内的全部命令式编排（导演双路调用分支、逐镜 `for` 循环、装配输入手工拼装与直接 `stage_call`）。
- `AgentPipeline::DirectorActor` 保留说明：该变体是 `resolve_pipeline` 按蓝图 `AgentModeSwitch` 资产解析出的**路由标签**（数据驱动，不含执行逻辑），其原先路由到的硬编码执行已删除、分发臂现只调用图编排薄入口；标签本身保留使 `stream_processor` 的禁词 Nudge 分发（`run_director_nudge_pass`，独立单趟重写、非流水线编排）与运行记录模式字符串（`director_actor` / `director_nudge`）不发生无谓变更。

## 已知限制或后续待办

- FanOut 为串行扇出（保序与前序视界递进所必需），不做并行演员调用；若未来需要并行，须先解决演员间视界语义再立项。

## 审查修正（2026-11-11）

code-review 第二轮（固定点 `703f1979..97c18b31`）Standards 轴复查发现：本阶段在 `graph_orchestrator.rs` 的 FanOut 实例化处留有一处静默降级——分镜 `character` 未命中任何 `ActorDefinition` 时，`actor_def.map(...).unwrap_or_default()` 以空 persona / 空 tools 构造演员阶段，执行器层无日志、无事件；降级可见性仅靠阶段调用方（`director_actor.rs` 的 `run_actor_stage`）以「stage.prompt 是否为空」反推未命中来触发旧路径裁剪与时间线 Info 事件，信号是隐式的（命中但 persona 为空的演员会被误判进旧路径，与旧实现按 def 命中与否分流不符）。据此，上方审计表中 **C2 一行原标 √ 有误，应为 ×**：当时确实存在一处「自动降级」且决定点不发声，违反 C2「严禁静默回退 / 自动降级」。
