## 改动摘要（仅 `src-tauri/src/services/blueprint_codec.rs`）

### 4a · DSL 覆盖扩展

- 新增映射表 `FLOW_NODE_DSL`（29 条）+ 双向查找 `flow_dsl_name` / `flow_node_type`：为除 initial_state_config / tool_definition / branch（既有形式保留）之外的**全部已知节点种类**各设一个 `flow.<种类>` 类型化形式，统一模式 `flow.<名>({ ...config, __nodeId, __position })`，config 对象逐字往返。清单：start、end、prompt、schemaField、mutexGate、groupGate、modeSwitch、roleSwitch、constant、stepBudget、sampling、samplingOpenAi、samplingAnthropic、invokeSchema、calculator、conditionGate、toolReturn、inspector、writer、querier、bannedWords、scriptwriterPipeline、agentModeSwitch、director、actor、uiLayout、macroInstance、macroInputs、macroOutputs。
- **取舍论证（codebase-design 词汇）**：codec 的 Interface 是「图 ⇄ .nv.ts 往返无损」这一条不变量，调用方（MCP 工具、nv-converter、创作者）只需学一个模式。29 种形式共用同一装配/解析实现（config 逐字透传 + 信封保留键），是 Implementation 覆盖扩大而 Interface 不扩张的深化（Depth/Leverage）；若为每种节点另设专属语法与字段重排，Interface 面积与往返风险同步膨胀，且字段重排必然引入新的归一化点，违背无损口径。低频种类（各 1 个）与高频种类同表覆盖，因为边际成本为一行映射，而「典型预设 fragment 只剩异类」的目标要求长尾清零。
- 导出：节点分发新增 typed 分支；config 非对象显式报错（与 flow.branch 同纪律，C2）。导入：`read_top_level_call` 新增通用 arm；start/end 无 config，给其塞 config 字段显式报错；未知 flow 种类显式报错。
- fragment 新口径：仅容纳真正异类——无名/重名 tool_definition（无法以键唯一表达）、第二个及以后的 initial_state_config（state 只能承载一个）；连线与评论仍逐字经 fragment 往返。
- **顺带修复一处真实无损缺陷（本阶段实测发现）**：原图坐标恰为 (0,0) 的节点（如默认预设的 n_core prompt）在类型化后会被旧的「原点即待排版」启发式扫描误移位。改为解析期显式记录排版候选——只有 DSL 节点缺失 `__position`（或状态节点缺失 `__statePosition`）才入选，显式坐标（含 (0,0)）一律逐字保留；删除组装后按坐标值猜测的扫描。`is_default_origin_position` 作为语义命名保留并由其既有回归测试固定，不再驱动排版。

### 4c · parameters_schema 空白归一化——保持现状确认

确认维持现状、不改代码：`parameters_schema` 在代码侧以对象呈现、导入时压回紧凑 JSON 字符串，空白格式不保留、语义等价。理由：该字段的权威形态是 JSON 语义值而非文本排版，空白不承载任何运行时语义；为保留空白需让 DSL 语法引入原始字符串通道，扩大 Interface 且与「声明式字面量子集」冲突。此决定已成文于工单 05 Walkthrough，本阶段复核后维持。
