## 改动动机

计划 §5 要求「模型通过 ToolCall 驱动数据容器，规则与运算由蓝图节点承担，门禁拦截后把 ToolResult
回传模型继续生成」。此前这条回路有 8 处断点（请求不带 tools、`active_tools` 无消费者、
流结束直接 `Err`、回执不进上下文、回注 UPDATE 违反表 CHECK、门禁与蓝图脱钩、推理期无 agent 分支、
OpenAI 侧不解析 `tool_calls`）。本次逐条打通。

## 运作机制（端到端时序）

```
用户发消息 → 编译提示（active_tools → request.tools；ToolDefinition 下游收成 ToolPlan）
  → HTTP/SSE → tool_use / tool_calls 累积（Anthropic 按 index 的 input_json_delta；OpenAI 按 index 分片）
  → stop_reason=tool_use → persist_tool_use_skeletons（批量落 agent_runs/agent_drafts/message_tool_calls）
  → emit tool_use 事件 → 返回 pending_tool_uses
  → dispatch_tool_calls：逐条 execute_tool_call_with_plan（蓝图门禁 → 运算器 → save + broadcast_hud_patch；
     拦截则 Err 原文）→ submit_tool_results（一条 user 消息 + N 个 tool_result part + 递增 part_index，
     aggregate content 携带真实回执）→ 开新轮 → 下一跳 SSE（含 tool_result）→ 正文
```

轮次上限：`count_tool_rounds_since_last_user_input` 以 `agent_runs` 的 distinct round 计数，
超过 5 轮直接报错，避免模型无限调用工具烧 token。
