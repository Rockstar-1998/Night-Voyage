# 20261024-0155-UE5蓝图宏模型与编译期内联展开引擎-新功能增加

## 1. 改动摘要

本工单完成 Ticket 02（UE5 风格蓝图宏 Schema 定义与编译期内联展开引擎），为蓝图系统引入完整的宏数据模型、严格类型化引脚（PinType）与零运行栈开销的静态内联消除算法：

- **宏数据结构与枚举定义 (`src-tauri/src/models/blueprint.rs`)**：
  - 定义 `PinType` 引脚类型枚举（`Exec`, `Number`, `String`, `Boolean`, `Object`），实现 `is_compatible` 类型判定规则：`Exec` 仅能连接 `Exec`；`Object` 兼容任意数据引脚；标量数据引脚（Number/String/Boolean）彼此互斥。
  - 定义 `MacroPinDefinition`（含 `id`, `name`, `pin_type`）与 `BlueprintMacro` 宏资产模型（含输入引脚列表、输出引脚列表、内部子图节点与连线）。
  - 在 `NodeType` 与 `NodeConfig` 中新增宏三位一体变体：`MacroInstance`（外部调用实例）、`MacroInputs`（宏输入代理）、`MacroOutputs`（宏输出代理）。
  - 在顶层 `BlueprintGraph` 引入 `macros: Vec<BlueprintMacro>` 资产库字段，实现向后兼容序列化与反序列化。
- **宏编译期内联展开与引脚校验引擎 (`src-tauri/src/services/blueprint_executor.rs`)**：
  - 实现 `check_macro_cycles`：基于三色 DFS 拓扑排序算法，在编译前检测宏资产的直接或间接递归成环调用（如 $A \to B \to A$），显式拦截并报错 `RecursiveMacroCycle`。
  - 实现 `validate_macro_pins`：在内联前深度审计顶层图与各宏内部全部连线，凡存在 Exec 与数据引脚混连或不兼容数据类型相连（如 Number 连入 String），显式拦截并报错 `IncompatiblePinTypes`。
  - 实现 `inline_single_macro_instance` 与 `expand_macros`：
    1. 为宏内部节点注入隔离命名空间前缀 `m_{instance_id}_`；
    2. 自动匹配宏的输入输出引脚，将外部调用入边精准桥接至内部受体节点，内部终点精准连通至外部受体；
    3. 支持输入输出直通边（Pass-through）；
    4. 消除 `MacroInstance`、`MacroInputs`、`MacroOutputs` 代理节点，实现纯扁平图拓扑输出与零运行时调用栈开销；
    5. 支持多层嵌套宏（Nested Macros）迭代展开。
  - 在 `execute_blueprint` 与 `validate_blueprint_ui_contract` 入口处接入 `expand_macros`，确保蓝图执行器与 UI 契约门禁均无缝支持宏化子图。
- **单元测试验证与回归覆盖 (`src-tauri/src/services/blueprint_executor.rs`)**：
  - 新增 4 个完整单元测试：
    1. `test_macro_inline_expansion_basic`：验证基础计算宏展开后节点 ID 命名空间化与端口重连线；
    2. `test_macro_pin_type_validation`：验证 Number 对 String 互斥及 Exec 连入数据引脚的强报错；
    3. `test_macro_recursive_cycle_rejection`：验证双向引用宏环路检测与报错；
    4. `test_macro_nested_expansion`：验证内外双层嵌套宏的扁平化展开与连续执行。

## 2. 改动动机

在先前的蓝图设计中，多节点复杂逻辑（如数值计算、门禁检查、结果封装）缺乏子图封装机制，导致画板连线繁杂（Spaghetti Graph）；且运行时多智能体或复杂计算若引入动态调用栈会严重增加状态复杂度与内存开销。引入 UE5 风格的编译期宏：
1. 节点可以在视觉上高度折叠为单个宏实例；
2. 静态内联展开算法在编译期将宏展开为标准扁平拓扑，保持零调用栈损耗；
3. 引脚类型系统（PinType）在连线期与编译期实施类型防御，彻底消除非确定性类型错误。
