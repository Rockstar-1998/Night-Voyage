# [修改] 多人房历史消息展示名去规范化（方案 A）

## 1. 改动摘要

针对上一轮「Bug 1 残留在房客离开后历史消息显示『玩家』」的根因，采用用户批准的**方案 A**：在 `messages` 表新增 `display_name` 列，插入用户消息时把发送者真实展示名去规范化写入，使历史渲染不再依赖 `conversation_members` 表的存在性。

改动文件与要点：

- **新增迁移** `src-tauri/migrations/0043_messages_denormalized_display_name.sql`
  - `ALTER TABLE messages ADD COLUMN display_name TEXT;`
  - 回填历史：仅对 `role='user'` 且仍能在 `conversation_members` 中找到对应成员的消息，写入其真实 `display_name`；已删除成员的旧消息保持 `NULL`（新发消息均自包含）。

- **`src-tauri/src/repositories/message_repository.rs`**
  - `InsertMessageRecord` 增加字段 `pub display_name: Option<String>`。
  - `insert_record` 的 `INSERT` 语句加入 `display_name` 列并 `.bind(&record.display_name)`。
  - `list_by_conversation` 与 `find_by_id` 的 SELECT 从 `cm.display_name AS display_name` 改为 `COALESCE(m.display_name, cm.display_name) AS display_name`——优先取消息自带名，缺失时回退到成员表（兼容过渡期）。
  - `row_to_ui_message` 已用 `try_get("display_name")` 读取，兼容新列，无需改。

- **`src-tauri/src/services/chat_service.rs`**
  - `submit_input`（约 L350-388）：在用户可见 user 消息插入前，查询 `conversation_members.display_name WHERE id = member_id`，得到 `sender_display_name`，写入该 `InsertMessageRecord` 的 `display_name` 字段（房主与房客统一走此路径）。
  - 其余 7 处 `InsertMessageRecord`（聚合 user、assistant 消息、工具结果、regenerate 等）全部补 `display_name: None`。

- **`src-tauri/src/commands/conversations.rs`**
  - `conversations_fork` 的 fork 复制消息路径：SELECT 增加 `COALESCE(display_name,'') AS display_name`，INSERT 增加 `display_name` 列与绑定，保留历史署名。
  - 开场 assistant 消息的 `InsertMessageRecord` 补 `display_name: None`。

- **`src/App.tsx`**
  - 回滚上一轮用于定位的 `[toChatMessage][DIAG-user]` `console.debug` 块。`senderName` 仍优先 `message.displayName`（上一轮已落地，本次保留）。

## 2. 改动动机

用户确认：房主永久保留房客记录与发言。房客断线时其 `conversation_members` 记录被删除（`network/mod.rs`），此后重开房间但房客未加入时，房客的历史 user 消息仍会渲染，但 JOIN 源 `cm.display_name` 已为 `NULL`，渲染层降级为「玩家」。

去规范化把发送者名固化进 `messages.display_name`，历史消息自包含，彻底消除对成员表存在性的依赖，符合 C2（零静默回退）与 AGENTS.md「永不假死、零静默回退」硬目标。
