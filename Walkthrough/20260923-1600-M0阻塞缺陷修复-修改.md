# 20260923-1600 - M0 阻塞缺陷修复 - 修改

本次修复是「Agent 与游戏机制系统」补齐工程（`plans/agent-system-architecture-plan.md`）的前置阻塞解。
M0 不做新功能，只把 M1–M5 会踩到的八处既有缺陷（含 3 处违反 C2 的静默回退）修掉。

## 改动摘要

| # | 文件 | 改动 |
|---|---|---|
| M0-1 | `src-tauri/migrations/0047_message_tool_calls_status.sql`（新增） | 按 0027 的既有做法重建 `message_tool_calls`，`status` CHECK 由 `('pending','completed','failed','ignored')` 扩为并含 `'result_available'`，数据 `INSERT…SELECT` 搬移、索引重建 |

## 改动动机

- **M0-1**：`repositories/message_repository.rs::update_tool_call_status` 会写 `status='result_available'`，而 0018 的 CHECK 不允许该值 → UPDATE 必然失败，ToolResult 无法落盘。这是 Agent ToolCall 回路的硬断点，不修则 M2 全线不通。
- **M0-2/M0-3/M0-4/M0-8**：四处都是「失败被静默吞掉/放行」的直接 C2 违规。其中 M0-2 最危险——未知门禁类型默认放行会使门禁形同虚设，本该被拦截的 ToolCall 会真实改写数据容器。
- **M0-5/M0-6/M0-7**：三处前后端数据契约不一致，会导致布局/InvokeSchema 节点「存进去读不出」，UI 设计器（M3）与 Schema 激活（M1）无法工作。
