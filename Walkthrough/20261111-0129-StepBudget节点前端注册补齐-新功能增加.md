## 业务摘要

StepBudget 节点（后端 `step_budget` / `StepBudgetConfig { max_steps, short_circuit_on_tools, is_locked }`，工单 01 已落地）此前在前端完全不可见：类型表无此类型、画布无端口/配色、选择器不可新建、配置面板无表单。本次按既有节点（以 branch / condition_gate 为参照）的全部注册点逐一补齐，PC 与移动端双端覆盖：

- **PC 端（`src/`）**：
  - `lib/blueprint/types.ts`：`NODE_TYPES` 新增 `step_budget`、`StepBudgetConfig` 接口、判别联合新增成员；
  - `components/blueprint/nodeLayout.ts`：主题色（#f43f5e）、出/入端口（单 exec in/out，与 Rust 引脚规格一致）、锁定位、标题（`Step Budget: N 步`）与副标题（单步直出 / N 步预算）；
  - `components/blueprint/NodeSelector.tsx`：标签与说明各一条（自动进入可新建列表）；
  - `components/blueprint/BlueprintEditor.tsx`：新建默认配置工厂（max_steps=1、short_circuit_on_tools=true、is_locked=false，与 Rust 默认值一致）；
  - `components/blueprint/NodeConfigPanel.tsx`：面板标题标签、`updateStepBudget`、Match 分发，及新增表单组件 `nodes/StepBudgetNode.tsx`（max_steps 数字输入（≥1 钳制）+ 首步短路开关 + 语义说明卡）；
  - `lib/icons.ts`：新增 `Gauge` 图标再导出（lucide 标准图标，与既有再导出同模式）。
- **移动端（`src-mobile/`）**（C5 独立实现、同一注册面）：`lib/blueprint/types.ts` 同步三项；`mobileNodeLayout.ts` 同步配色/端口/锁定/标题/副标题与新建工厂；`MobileNodeConfigForms.tsx` 新增 `StepBudgetForm`（NumberInput + Toggle，移动端原生控件）+ Match + 面板工厂；`MobileNodeConfigPanel.tsx` 类型显示名；`BlueprintEditor.tsx` 可添加节点列表新增一项。

## 验证

- 以最小依赖集（typescript + solid-js + lucide-solid + tauri api）在临时目录对 `tsconfig.json` 与 `tsconfig.mobile.json` 跑 `tsc --noEmit`：与 step_budget 相关的类型错误为零——过程中逮到并修复一处遗漏（NodeConfigPanel 的 `NODE_TYPE_LABELS` 穷尽 Record）。剩余报错均为既存类别（最小安装缺 `motion` 包、lucide 子路径解析差异、既存未用变量等），与本次改动无关。
- 顺带发现一处既存问题（非本次引入，未在本单修复）：移动端 `MobileNodeConfigPanel.tsx` 的 `nodeTypeLabel` switch 缺 `initial_state_config` 与三个 macro 类型的 case 且无默认返回，tsc 报 TS2366；建议后续单独立项。
- 本机无完整 node_modules，未跑 vite 构建；图标 `gauge` 为 lucide 标准图标且与既有 60+ 再导出同模式，风险可控，已如实记录。
