# 20260714-1430 蓝图编辑器预设管理（新建/删除/复制/重命名）

## 1. 改动摘要

为蓝图编辑器添加预设管理功能（新建、删除、复制、重命名），PC 端与移动端同步覆盖。

### 后端 command 签名

```rust
#[tauri::command]
pub async fn presets_rename(
    state: tauri::State<'_, AppState>,
    id: i64,
    new_name: String,
) -> Result<PresetDetail, String>

#[tauri::command]
pub async fn presets_duplicate(
    state: tauri::State<'_, AppState>,
    id: i64,
    new_name: String,
) -> Result<PresetDetail, String>
```

### 前端封装签名

```typescript
export async function presetsRename(id: number, newName: string): Promise<PresetDetail>
export async function presetsDuplicate(id: number, newName: string): Promise<PresetDetail>
```

### UI 实现方式

- **新建预设**：标题栏右侧按钮（PC）/ 主体顶部卡片按钮（移动端），调用 `presetsCreate({ name: '新预设 ${timestamp}' })` 后刷新列表。
- **复制**：每张卡片上的复制图标按钮，调用 `presetsDuplicate(id, '${name} 副本')` 后刷新列表。
- **重命名**：inline 编辑。点击重命名图标 → 卡片标题变为 `<input>`，Enter 提交 / Esc 取消 / blur 提交，调用 `presetsRename(id, newName)` 后刷新列表。空名时 `showToast('预设名称不能为空', 'warning')`。
- **删除**：删除图标按钮 → `showConfirm` 非阻塞确认对话框 → 确认后调用 `presetsDelete(id)` → 刷新列表。
- **PC 卡片**：从 `<button>` 改为 `<div role="button" tabIndex={0}>` + onClick + onKeyDown(Enter/Space)，操作按钮组 hover 显示（`opacity-0 group-hover:opacity-100`）。
- **移动端卡片**：从 `<button>` 改为 `<div>` + onClick，操作按钮组常驻显示（触控无 hover）。
- **busy 遮罩**：操作进行中卡片上覆盖半透明遮罩 + "处理中…"，防止重复点击。
- **错误处理**：所有失败用 `showToast('xxx 失败：' + message, 'error')` 显式报错，不静默回退。

## 2. 改动动机

蓝图编辑器原本只能点击进入编辑，缺少预设的生命周期管理（新建/删除/复制/重命名）。用户要求"复制与重命名按钮放在每个预设框上"，因此每张卡片都需要常驻/hover 显示的操作按钮。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 新建/复制/重命名/删除全部通过 Tauri command 调用后端 service/repository 完成；前端只负责事件转发、loading 状态与错误展示。 |
| C2 Zero-Fallback Errors | √ | 所有异步操作 try/catch，失败用 showToast 显式报错；重命名空名用 showToast('warning') 阻止提交；后端 rename 返回 `Result<bool, String>` 在 service 层检查 rows_affected，未找到预设返回 `"指定预设不存在"`；后端 map_err 把反斜杠替换为正斜杠，避免 IPC JSON 解析问题。 |
| C3 Responsiveness | √ | 所有异步操作不阻塞 UI 线程（async/await + SolidJS 信号驱动渲染）；busy 期间禁用按钮 + 遮罩，防止重复点击与 UI 假死。 |
| C4 AI UI Isolation | √ | 不涉及 AI 动态 UI 层。 |
| C5 Mobile Frontend Independence | √ | PC 端代码在 `src/App.tsx`，移动端代码在 `src-mobile/components/blueprint/MobilePresetBlueprintEntry.tsx`，两端 UI 完全独立实现，零 UI 代码耦合；移动端按既有模式从 `../../../src/lib/backend` 导入后端封装（共享 Rust 后端的 TS glue，非 UI 代码）。 |
| C6 Project Cache Location | √ | 不涉及缓存写入。 |
| C7 PC/Android Coverage | √ | PC 端与移动端同步实现，共用同一套 Rust 后端 command（`presets_rename` / `presets_duplicate`），不为某端单开后门。 |

## 5. 已知限制或后续待办

- **重命名不检查名称冲突**：与现有 `update` 行为一致，允许重名。如需唯一性约束，需在 repository 层加 `name_exists` 检查（与 `import` 一致）。
- **新建预设命名**：使用 `新预设 ${Date.now()}` 时间戳命名，用户需后续手动重命名。未做"新建后立即进入重命名"的交互优化。
- **复制后的名称**：固定为 `${原名} 副本`，未做"副本 2/3"递增。如原名为"测试 副本"，复制后为"测试 副本 副本"。
- **PC 端 inline 重命名 blur 提交**：blur 时自动提交（与 Enter 一致）。如用户点击其他操作按钮，blur 会先触发提交。当前通过 `stopPropagation` 阻止了 input click 冒泡，但 blur 提交是预期行为。
- **移动端 inline 重命名**：同样 blur 提交。移动端虚拟键盘可能遮挡输入框，未做 scrollIntoView 优化。
