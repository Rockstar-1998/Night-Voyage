# SCHEMA 顺序调查与 BlueprintEdge 类型补丁

## 改动摘要

- `src/lib/blueprint/types.ts`
  - `BlueprintEdge` 新增可选字段 `order?: number`：同一源节点 + 同一出口端口连出多条边时的分支/合并遍历顺序。缺省视为 0，与 Rust `#[serde(default)]` 语义一致，向后兼容旧版蓝图。

## 改动动机

- 工作区既有未提交改动（后端 `order_schema_properties`、PC 编辑器 `order: 0`、预设文件 `order` 字段）已使用 `order`，但共享 TS 类型 `BlueprintEdge` 未声明该字段，PC 编辑器构造带 `order` 的边会触发 TS 多余属性检查错误。本补丁补齐类型缺口。
- 本次不新增任何功能逻辑，仅恢复类型与数据/后端的契约一致。

## 调查结论（供后续参考）

蓝图编译 prompt 与 schema 顺序的流水线：

1. **prompt blocks**：DFS 从 Start 遍历到 End，顺序由「出口端口优先级（gate options 顺序）→ 边 `order` → target id」决定；blocks 保持遍历顺序，不再重排。
2. **schema 字段**：三步流水线
   - DFS 遍历中 `apply_schema_field` 逐个 `props.insert`（serde_json Map 保留首次插入顺序）；
   - `inject_core_schema_baseline`：缺 `thinking`/`text` 时追加到末尾（text 因此总是排最后）；
   - `order_schema_properties`（工作区未提交）：按固定语义优先级重排 thinking(0) → text(1) → 其余按字母序，`required` 同步。
3. 用户上报的旧顺序 `thinking, status_bar, todo_list, options, text` 正是「DFS 插入 + text 基线追加」的产物，即修复前的行为；修复后应为 `thinking, text, options, status_bar, todo_list`。
