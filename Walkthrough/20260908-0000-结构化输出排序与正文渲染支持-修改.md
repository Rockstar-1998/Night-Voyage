# 结构化输出排序与正文渲染支持 - 修改

## 1. 改动摘要

本次改动针对蓝图与结构化输出在 PC 端与移动端的渲染排序错误（如数字最大却排在最前）、`hide_label` 无效、以及缺少将特定字段作为正文渲染（`body` 属性）的问题进行了端到端（后端存储、编译器、PC端与移动端蓝图及渲染器）的全面支持。

### 修改文件及模块：
1. **`src-tauri/src/models/blueprint.rs`**:
   - 在 `BlueprintGraph` 中增加 `derive_display_config()` 方法，自动根据拓扑遍历图中的 `SchemaField` 节点及其 `order`、`body`、`hide_label`、`color` 等属性提取标准化 `HashMap<String, FieldDisplayConfig>`。
2. **`src-tauri/src/services/preset_service.rs`**:
   - 在 `create_preset` 与 `update_preset` 时，若未直接传递或需兜底，自动从 `blueprint_graph` 中提取最新的 `structured_output_display` 进行持久化存储。
3. **`src-tauri/src/repositories/preset_repository.rs`**:
   - 在 `row_to_preset_summary` 中，对数据库中 `structured_output_display` 为空的记录增加从 `blueprint_graph` 提取 display config 的动态派生回退，确保旧预设在新界面中能立即感知拓扑顺序。
4. **`src-tauri/src/services/prompt_compiler.rs`**:
   - `build_field_display_map` 补充将节点的 `order` 字段写入到导出的 display map 中。
5. **`src/lib/blueprint/types.ts`**:
   - 在 `FieldDisplayConfig` 中补充 `body` 与 `order` 属性。
   - 增加 `deriveStructuredOutputDisplayFromGraphJson` 和 `deriveStructuredOutputDisplay` 辅助函数。
6. **`src/components/blueprint/BlueprintEditor.tsx`**:
   - 在保存预设时，自动调用 `deriveStructuredOutputDisplay` 将最新的 display config 包含在 save payload 中。
7. **`src/components/blueprint/nodes/SchemaFieldNode.tsx`**:
   - 补充 `body` 复选框控制，允许用户指定将某个字段直接作为正文气泡内容渲染。
8. **`src/lib/messageFormatter.ts` & `src/components/MessageItem.tsx`**:
   - 更新类型定义与解析器，支持 `order` 与 `body` 字段透传。
9. **`src/components/MessageFormatRenderer.tsx`**:
   - 统一字段遍历与排序逻辑（`sortedFieldEntries`），依照 `order` 升序稳定排序。
   - 实现 `body` 字段渲染：将标记为 `body` 的字段以自然正文方式排版并支持折叠/隐藏标签控制。
10. **`src/App.tsx`**:
    - 在 PC 桌面端顶层计算 `effectiveStructuredOutputDisplay`，当预设缺少显式 `structuredOutputDisplay` 时自动从 `blueprintGraph` 中动态派生并透传至 `ChatArea`。
11. **`src-mobile/lib/structured.ts`**:
    - 移动端补充 `body` 与 `order` 字段定义以及图数据派生函数。
12. **`src-mobile/components/blueprint/MobilePresetBlueprintEntry.tsx`**:
    - 移动端蓝图保存流程集成 display config 自动派生。
13. **`src-mobile/components/blueprint/MobileNodeConfigForms.tsx`**:
    - 移动端节点编辑表单增加 `body` 开关。
14. **`src-mobile/App.tsx`**:
    - 向 `MobileChatView` 传递 `presetId`。
15. **`src-mobile/components/MobileChatView.tsx`**:
    - 根据当前 `presetId` 从预设列表中解析出上下文关联的 `structuredOutputDisplay`（若为空则从 `blueprintGraph` 派生）并透传至移动端消息气泡。
16. **`src-mobile/components/MobileStructuredRenderer.tsx`**:
    - 统一排序与渲染逻辑，依照 `order` 升序排列，并对 `body` 字段进行正文渲染支持。

## 2. 改动动机

1. **排序倒置与错乱**：此前字段排序未将蓝图节点中的 `order` / `priority` 纳入消息渲染器的权重计算，导致用户设定最高序号（如 7）的字段被错误放置在最前方展示。
2. **标签隐藏失效**：`hide_label` 在部分渲染逻辑中被忽略，普通 TEXT 字段依然无条件渲染标签文字。
3. **缺乏正文嵌入能力**：用户希望模型生成的特定结构化字段（如主要叙述正文）能直接作为消息正文呈现，而非全被包裹在键值对属性卡片中。
4. **移动端与 PC 端双端一致性**：移动端此前未接入预设级 `structuredOutputDisplay` 配置，导致移动端消息气泡无法应用蓝图配置中的视觉排版规则。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 业务计算、图拓扑分析与持久化派生统一在后端与服务层处理，前端仅负责渲染与信号绑定 |
| C2 Zero-Fallback Errors | √ | 无静默吞错，反序列化与派生均通过显式错误处理与严谨类型系统 |
| C3 Responsiveness | √ | 使用细粒度响应式 memo，排序逻辑仅在消息或配置变动时单次执行，无主线程阻塞 |
| C4 AI UI Isolation | √ | 未引入不安全沙箱污染，结构化渲染依旧运行在受控渲染器组件中 |
| C5 Mobile Frontend Independence | √ | `src/` 与 `src-mobile/` 零 UI 代码耦合，双端分别独立实现渲染组件与类型派生 |
| C6 Project Cache Location | √ | 运行时缓存与构建临时文件遵循既定规范，不向系统盘乱写 |
| C7 PC/Android Coverage | √ | 功能完整覆盖 PC 端与移动端（包括蓝图节点表单、预设派生、消息渲染器） |
