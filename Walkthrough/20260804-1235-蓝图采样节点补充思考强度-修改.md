# 蓝图 Sampling Params 节点补充思考强度（thinking）

修改类型：修改
时间：2026-08-04 12:35

## 1. 改动摘要

问题：蓝图编辑器里的「Sampling Params」节点没有「思考强度」字段，用户在该节点配置的
`thinking_enabled` / `thinking_budget_tokens` 在图执行与 prompt 编译阶段被静默丢弃
（违反 C2 零回退）。预设级路径（`BlueprintEditor` 已捕获 `thinkingEnabled`/`thinkingBudgetTokens`）
是通的，缺口只在蓝图节点链路。

改动文件与函数：

- `src-tauri/src/models/blueprint.rs`
  - `SamplingParamsConfig`：新增 `thinking_enabled: Option<bool>`、`thinking_budget_tokens: Option<i64>`。
  - `CompiledSamplingParams`：新增同样两个字段，并加 `#[derive(Default)]` 以便默认构造。
- `src-tauri/src/services/blueprint_executor.rs`
  - `merge_sampling_params`：新增把节点 `thinking_enabled` / `thinking_budget_tokens` 透传到编译结果。
  - 默认 `CompiledSamplingParams { ..Default::default() }` 补齐新字段。
  - 测试构造点（`sampling` helper）与单元测试 `test_sampling_params_carries_thinking` 补齐新字段。
  - 移除诊断阶段临时加的 `use crate::dbg_eprintln;`（已无引用）。
- `src-tauri/src/services/prompt_compiler.rs`
  - `apply_blueprint_sampling_params`：把蓝图 `CompiledSamplingParams` 的 `thinking_enabled` /
    `thinking_budget_tokens` 合并进最终 `CompiledSamplingParams`（override 预设/provider override）。
- `src-tauri/src/services/preset_service.rs`
  - 内建蓝图样例的 `SamplingParamsConfig` 构造补齐两个新字段（`None`）。
- `src/lib/blueprint/types.ts`
  - `SamplingParamsConfig` 接口新增 `thinking_enabled: boolean | null`、`thinking_budget_tokens: number | null`。
- `src/components/blueprint/nodes/SamplingParamsNode.tsx`
  - 在 `presence_penalty` 之后新增「思考强度」区段：一个 `thinking_enabled` 复选框（勾选=true，
    取消=null）与一个 `thinking_budget_tokens` 数字输入（min=128，留空=null，未开启时禁用）。
- `src/components/blueprint/BlueprintEditor.tsx`
  - 新建 `sampling_params` 节点的默认 config 补齐 `thinking_enabled: null`、`thinking_budget_tokens: null`。

## 2. 改动动机

后端 `prompt_compiler` 与 `provider_adapter` 早已支持 `thinking_enabled` / `thinking_budget_tokens`，
但蓝图 `SamplingParamsConfig` 类型自诞生起就未包含这两个字段，导致：
1. 节点编辑器 UI 不渲染「思考强度」；
2. `merge_sampling_params` 与 `apply_blueprint_sampling_params` 不向下传递；
3. 经由此节点配置的思考强度被静默丢弃，与 C2（零回退）冲突。
本次把这两个字段贯通到蓝图节点链路，使「思考强度」在蓝图预设中可用且生效。
