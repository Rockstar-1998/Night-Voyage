# 延迟自动重试至用户触发 — 后端改造

## 1. 改动摘要

本次改动为后端流式重试链路新增 `auto_retry_enabled` 字段，将"首次失败即自动重试"改为"首次失败后停止，等待用户点击自动重试按钮"（仅 `retry_failed_round` 入口携带 `auto_retry_enabled=true`，其余三处入口传 `false`）。

### 改动要点

- `spawn_stream_task` 失败分支（非 abort、非确定性错误、非 `is_round_aborted` 路径）末尾的 loop 控制由原来的"无条件 sleep 1s 后 continue"改为：先判断 `auto_retry_enabled`，若为 `false` 则 `break` 退出循环（首次失败即停止，等待用户点击"自动重试"按钮触发 `retry_failed_round`）；若为 `true` 才 sleep 后 continue。
- abort 路径（`error == STREAM_ABORTED_ERROR`）、确定性错误路径（`mem0 retrieval failed` / `Prompt Compiler`）、`is_round_aborted` 检测路径不受影响，均维持原有 `break` 行为。
- `StreamRetryEvent` / `RoomMessage::StreamRetry` / `RoomStreamRetryPayload` 三处数据结构同步新增 `auto_retry_enabled`，确保前端与联机房间均能感知当前重试是否为自动模式，用于 UI 按钮显隐与状态展示。

## 2. 改动动机

原 `spawn_stream_task` 的自动重试 loop 在任何失败后都会无条件 sleep 1s 后 continue，导致：

- 首次失败时前端无法介入决策，用户失去对重试时机的控制；
- 自动重试与用户主动触发的重试在事件层面无法区分，前端无法据此切换"自动重试按钮"的可见性。

本次改造将首次失败延迟到用户触发：仅 `retry_failed_round`（用户主动点击重试）入口传 `true` 启用自动重试 loop；其余入口（`submit_input` / `dispatch_tool_round` / `regenerate_round`）传 `false`，首次失败即停止 loop 并通过 `llm-stream-retry` 事件通知前端展示重试按钮。事件新增 `auto_retry_enabled` 字段使前端能区分"等待用户触发"与"自动重试中"两种状态。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 改动全部位于 Rust 后端（models/network/services），前端仅通过 Tauri event 被动接收 `auto_retry_enabled` 状态用于渲染，无业务逻辑前移 |
| C2 Zero-Fallback Errors | √ | 失败仍显式 emit `llm-stream-retry` 并广播 `StreamRetry`；`break` 后 loop 退出，错误状态可见，无吞异常/静默回退/默认成功 |
| C3 Responsiveness | √ | `break` 提前退出减少无谓重试开销；sleep 仅在 `auto_retry_enabled=true` 分支保留，与原行为一致 |
| C4 AI UI Isolation | N/A | 本改动不涉及 AI 动态 UI 沙箱层 |
| C5 Mobile Frontend Independence | N/A | 本改动不涉及前端代码，PC 与移动端通过同一 Rust 后端事件接口获取 `auto_retry_enabled` |
| C6 Project Cache Location | √ | 无缓存写入 |
| C7 PC/Android Coverage | √ | 后端命令/事件对两端共享，`auto_retry_enabled` 通过统一的 `llm-stream-retry` event 与 `StreamRetry` 房间消息下发，未为某端单开后门 |

- `submit_input` / `dispatch_tool_round` / `regenerate_round` 三入口在流式失败后不再自动重试，loop 立即 break，前端收到 `llm-stream-retry`（`autoRetryEnabled=false`）后展示"自动重试"按钮。

## 5. 已知限制或后续待办

- 本次仅完成后端字段与 loop 控制改造；前端（PC `src/` 与移动端 `src-mobile/`）对 `autoRetryEnabled` 事件字段的消费、"自动重试"按钮的显隐与点击调用 `retry_failed_round` 的逻辑属后续前端任务，不在本次 spec 范围内。
- `RoomMessage::StreamRetry { .. }` 在 `event_name()` 中使用 `..` 通配（预先存在代码），新增字段不破坏其匹配，但该写法与 guardrails "禁 `..` 跳过字段"风格存在历史偏差，本次未在 spec 范围内修正。
- `auto_retry_enabled: bool` 作为函数参数在失败分支驱动 `break`/`continue` 行为分支，属于运行期 bool 标志位；当前为用户明确指定的 spec 设计，作为"用户触发重试"与"自动重试"两种模式的区分信号同时通过事件下发前端。若后续需进一步类型化（如拆分 `ManualRetryMode` / `AutoRetryMode` 类型），可在前端任务落地后统一评估。
