## 2. 改动动机

在针对本分支（`feat/blueprint-macro-ui-contract`）进行的二轴代码复审中，发掘并定位了以下需彻底治理的潜在缺陷与规范偏离：
1. **Standards 规范轴**：
   - `blueprint_executor.rs` 的 `get_port_pin_type(node, port, is_output: bool)` 使用了布尔标志位分流输入/输出，违反了 Rust 官方 API 设计准则与项目的“类型驱动、最小分支”硬规范。
   - `orchestrator.rs` 在写回 `rejection_loop_state` 时使用了 `.unwrap_or_default()`，静默忽略了潜在的 JSON 序列化失败，违反 C2 零回退原则。
2. **Spec 规格轴**：
   - 审阅打回机制中，当审阅者输出打回评语并触发最大重试上限熔断后，下游的终审/润色阶段接收到了审阅者的 `[REJECT]` 评语而非前序流水线生成的正文草稿，导致故事正文被评语覆盖。
   - Spec Line 26 要求静态校验工具节点对数据契约与初始状态的合规性，原实现缺少针对 `Calculator` 节点修改属性是否在初始状态存在的校验。
   - 智能体声明的全局能力（MCP/ActionBridge 工具）未能在流水线启动前注册至运行时能力字典。
