# 蓝图编辑器前端 JSON 格式与迁移逻辑修复 — serde unit variant 不匹配 + 新建空白预设误触发迁移

**修改类型**：debug

**日期**：2026-07-14
**作者**：assistant

## 1. 改动摘要

用户实测发现蓝图编辑器基础功能完全不可用：新建空白预设即触发"旧预设迁移"流程，保存时报 `blueprint_graph JSON 无效: invalid type: map, expected unit variant NodeConfig::Start`，NodeSelector 下拉菜单也只显示 Start 一个选项。

本次修复三个根因，全部在前端 `BlueprintEditor.tsx` 中完成，后端无需改动。

### 改动文件

| 文件 | 改动 |
|------|------|
| `src/components/blueprint/BlueprintEditor.tsx` | 1. `serializeBlueprintGraph` 序列化时剥除 Start/End 节点的 `config: {}` 字段，匹配后端 serde unit variant 格式；2. 新增 `normalizeLoadedNodes` 在 load 路径对 Start/End 补回 `config: {}` 占位；3. `onMount` 迁移分支前检查 `hasLegacyContent`，新建空白预设不触发迁移 |

## 2. 改动动机

### 根因 1：serde unit variant JSON 格式不匹配（问题 2 — 保存报错）

**后端 Rust** `NodeConfig` 使用 `#[serde(tag = "type", content = "config", rename_all = "snake_case")]`：
- unit variant `Start`/`End` 序列化为 `{"type":"start"}`（**不带** `config` 字段）
- 反序列化时期望 `{"type":"start"}`，收到 `{"type":"start","config":{}}` 会报 `invalid type: map, expected unit variant NodeConfig::Start`

**前端 TypeScript** `NodeConfig` union 定义为 `{ type: 'start'; config: StartConfig }`，其中 `StartConfig = {}`。`createEmptyGraph()` 和 `defaultConfigForType('start')` 都产生 `config: {}`，`JSON.stringify` 序列化为 `"config":{}`，后端反序列化失败。

**修复**：`serializeBlueprintGraph` 中对 Start/End 节点剥除 `config` 字段，只输出 `{ type, id, position }`。新增 `normalizeLoadedNodes` 在 load 路径对 Start/End 补回 `config: {}`（因为从 DB 读回的 JSON 中 Start/End 不带 config，但前端类型系统需要它存在以支持 discriminated union narrowing）。

### 根因 2：新建空白预设误触发迁移（问题 1 — 逻辑错误）

`onMount` 中，当 `blueprintGraph` 为空/null 时**无条件**进入"Legacy preset — migrate"分支。但新建的空白预设 `blueprintGraph` 也是 null，导致：
1. 错误触发 `migrateToBlueprint` 迁移流程
2. 迁移生成的图保存时因根因 1 的 JSON 格式问题失败
3. 用户看到"旧预设已自动迁移为蓝图，正在保存..."和"迁移结果保存失败"的矛盾提示

**修复**：在迁移分支前检查 `hasLegacyContent`（blocks/semanticGroups/structuredOutputSchema 是否有内容）。新建空白预设无 legacy 内容，直接使用 `createEmptyGraph()` 的 Start→End 初始图，不触发迁移。

### 根因 3：NodeSelector 只显示 Start（问题 3 — 副作用）

`NodeSelector.tsx` 代码本身正确：`NODE_TYPES` 有 8 个元素，`<For each={NODE_TYPES}>` 应渲染全部 8 个 `<li>`。运行时 `NODE_TYPES` 未被修改。

确认是根因 1+2 的副作用：迁移失败抛出 JS 异常（`presetsUpdate` reject），影响了 SolidJS 的渲染周期，导致 `<For>` 只渲染了第一个元素。修复根因 1+2 后，迁移不再失败，NodeSelector 应恢复正常。

### 4.2 验收方法与预期效果

1. **新建空白预设**：打开蓝图编辑器后不再显示"旧预设已自动迁移为蓝图"，直接显示 Start→End 初始图，`isDirty` 为 false
2. **保存空白预设**：手动点击保存按钮，`serializeBlueprintGraph` 剥除 Start/End 的 config，后端 serde 正确反序列化，保存成功
3. **加载已有图**：从 DB 读回的 JSON 中 Start/End 不带 config，`normalizeLoadedNodes` 补回 `config: {}`，前端 discriminated union narrowing 正常工作
4. **NodeSelector**：修复根因 1+2 后，迁移不再抛异常，`<For each={NODE_TYPES}>` 正常渲染全部 8 个节点选项
5. **添加节点**：用户点击"添加节点"→选择类型→`defaultConfigForType` 产生带 `config` 的节点→保存时 `serializeBlueprintGraph` 对 Start/End 剥除 config，其他节点原样输出
