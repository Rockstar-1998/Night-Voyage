# 分支节点匹配规则输入框逐字失焦 — debug

## 1. 改动摘要

| 文件 | 位置 | 改动 |
|------|------|------|
| `src/components/blueprint/nodes/BranchNode.tsx` | `BranchNode` 组件 cases 列表 | `<For>` → `<Index>`；`caseItem.match_value`/`caseItem.port` → `caseItem().match_value`/`caseItem().port`；`index()` → `index`；import 增加 `Index`、移除 `For` |
| `src-mobile/components/blueprint/MobileNodeConfigForms.tsx` | `BranchForm` 组件 cases 列表 | 同上（保留 `For`，因 `Select` 与 GateForm options 仍在用） |

两处均补充了一段注释说明为何必须用 `<Index>`。

## 2. 改动动机

用户反馈：Branch 节点配置面板中，匹配规则的「匹配值」「出口端口名」输入框，无论是输入一个汉字还是一个英文字母，都会立刻失焦，必须重新点击才能再输入一个字符。

根因：

- 每次 `onInput` 都走不可变更新 —— `cases.map((c, i) => i === index ? { ...c, ...updates } : c)`，生成**全新的 case 对象**。
- Solid 的 `<For>` 通过**引用相等**做 reconciliation。新对象 ≠ 旧对象，被判定为"该项被替换"，于是销毁整行 DOM 并重建，**正在输入的 `<input>` 元素被销毁**，焦点随之丢失。
- 与节点类型分发无关：PC 的 `NodeConfigPanel` 与移动端的 `MobileNodeConfigForm` 均已使用 `<Switch>/<Match>`，非 keyed `<Show>` 保证了表单组件本身不会随配置变更重建（这也是为什么 `label` / `default_port` 输入框不失焦，只有 cases 行失焦）。

修复方式：改用 `<Index>`。`<Index>` 按**数组下标**做 reconciliation，长度不变时不重建 DOM，只把行内 signal 更新为新值（item 变成 `Accessor<T>`），输入框于是保持焦点与光标位置。

## 5. 已知限制与后续待办

- **同类问题仍在别处**：`MutexGate` / `GroupGate` 的 options 列表在 PC（`MutexGateNode.tsx` / `GroupGateNode.tsx`）与移动端（`MobileNodeConfigForms.tsx` 的 `GateForm`）同样使用 `<For>` + 不可变更新，存在完全相同的逐字失焦问题。本次按用户指示**只修 Branch**，未改动。
- **未处理的独立缺陷（用户明确指示本次不修）**：前端节点类型字面量为 `sampling_params_openai`，而 Rust `NodeConfig` 枚举 `#[serde(rename_all = "snake_case")]` 将其序列化为 `sampling_params_open_ai`。蓝图中一旦存在该类型节点，保存时后端解析必然失败并报 `unknown variant 'sampling_params_openai'`。修复方向二选一：给 `blueprint.rs` 的 `SamplingParamsOpenAi` / `NodeType::SamplingParamsOpenAi` 加 `#[serde(rename = "sampling_params_openai")]`，或统一前端字面量为 `sampling_params_open_ai`（需数据迁移）。
