## 2. 改动动机

针对 `/code-review` 代码审阅在 Standards（规范标准）和 Spec（规格说明）两大维度提出的问题进行系统性修复：
1. **彻底解决 C5 移动端独立性违规**：移动端此前从 PC 宿主 `src/lib/backend` 导入契约验证函数，违反了双端零 UI 代码耦合硬约束。通过建立 `src-mobile/lib/backend/blueprint.ts` 实现双端完全独立。
2. **彻底解决 C11 硬编码数据违规**：前端工具权限模态框此前硬编码了 `cast_spell`、`buy_item` 等虚构奇幻 RPG 能力池。改由外部注入的 `availableTools`、蓝图声明的 `customTools` 以及既有配置动态合并生成。
3. **彻底解决 C2 零回退违规**：
   - 命令层 `blueprint_validate_ui_contract` 不再通过 `.ok()` 吞掉布局配置加载错误；
   - 编排器打回目标 `reject_target` 若配置了不存在的阶段，不再静默路由至第 0 阶段，而是显式报错。
4. **消除代码异味与原生类型偏执**：
   - 提取共享三色 DFS 环检测函数 `find_directed_graph_cycle`，消除重复实现；
   - 引入 `ReviewVerdict` 领域枚举消除 `is_verdict_reject` 闭包与裸字符串判定；
   - 消除 `_ =>` 宽泛通配符，实现类型驱动的穷尽分支匹配。
5. **对齐 Spec 宏多出口与循环状态设计**：
   - 支持宏内联展开多 `Outputs` 出口分支；
   - 运行时实例化并持久化 `RejectionLoopState` 至 ephemeral scratchpad，发射中间打回时序事件。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 前端仅负责展示与交互，所有宏展开、拓扑环检测、契约校验、流水线调度与打回熔断均在 Rust 后端执行 |
| C2 Zero-Fallback Errors | √ | 消除所有 `.ok()` 降级、默认目标兜底及宏错误静默处理；找不到 `reject_target` 显式抛错 |
| C3 Responsiveness | √ | 后端执行采用异步非阻塞与纯内存 Scratchpad 方案，前端渲染细粒度响应，零主线程卡顿 |
| C4 AI UI Isolation | √ | 不涉及 AI 渲染宿主样式污染 |
| C5 Mobile Frontend Independence | √ | `src-mobile` 拥有独立的 `lib/backend/blueprint.ts`，零跨端引用，双端独立编译通过 |
| C6 Project Cache Location | √ | 工具链构建与测试均指向 `D:\software_cache` 与 `D:\data\Night Voyage\.cache` |
| C7 PC/Android Coverage | √ | 工具权限管理、契约校验与编排调度在 PC 端与移动端均具有对称实现并独立构建通过 |
| C8 MCP-Only Acceptance | √ | 验收与测试均通过规范 MCP / Tauri 命令驱动的真实后端系统验证 |
| C9 MCP Rolling Development | √ | MCP 验收工具保持敏捷按需接入与真实链路挂载 |
| C10 MCP Demo Front-Mount | √ | 蓝图校验与能力权限编辑在 PC 与移动端均有前端实体面板交互承载 |
| C11 No Hardcoded Data | √ | 彻底清理 `DEFAULT_CAPABILITY_POOL` 与 `MOBILE_DEFAULT_CAPABILITY_POOL`，所有能力来源于真实图契约与后端声明 |
