# 联机结构化流式同步修复

## 1. 改动摘要

修复联机模式下房客无法同步房主流式传输消息的致命缺陷。会话使用 `response_mode=structured_json` 时，LLM 增量通过 `string_field_delta` / `object_field_complete` 事件发出，但这些事件从不广播给房客，导致房客助手消息为空。同时收敛纯文本模式双重广播、房客 TokenIsland 报错两个关联问题。

## 2. 改动动机

**根因**：`room-stream-sync` spec 此前显式将结构化输出同步列为 Non-Goals（"后续迭代"）。但当前会话默认使用 `structured_json` 响应模式，所有增量走 `string_field_delta` 通道，房客完全收不到内容——这不是"后续迭代"而是"核心功能不可用"。

日志证据：
- 服务端日志 477–807 行数百条 `[structured_output] feed delta`，但零条 `[room-broadcast] StreamChunk`——增量从未广播。
- 客户端日志仅 1 条 `room:stream_chunk`（done=true 空块）+ `room:stream_end`，房客助手消息为空。
- 客户端 `compile_prompt ERROR: no rows returned`——TokenIsland 在房客本地 DB 无 conversation 行时炸错。

**双重广播**：`text_delta` 同时被后端 `flush_text_delta_event` 和前端 `roomBroadcastStreamChunk` 各广播一次，纯文本模式房客看到双倍文字。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 广播统一由后端发起（chat_service helper + stream_processor），前端不再触发任何 `room_broadcast_stream_*` 命令；前端只渲染接收到的 room 事件 |
| C2 Zero-Fallback Errors | √ | `load_conversation_compile_context` 改 `fetch_optional` + 明确错误文案，非静默回退；`host_server=None` 时广播 spawn 内静默跳过（非联机单人模式，非错误路径） |
| C3 Responsiveness | √ | 广播用 `tauri::async_runtime::spawn` 异步执行，不阻塞流式主循环；结构化增量随解析器事件即时广播，与房主本地渲染同节奏 |
| C4 AI UI Isolation | √ | 不涉及 AI 动态 UI 层 |
| C5 Mobile Frontend Independence | √ | 后端改动双端共享；前端改动仅 PC `src/`（`src-mobile/` 未实现多人房间，grep 确认无 `room_broadcast_stream*` 引用） |
| C6 Project Cache Location | √ | 不涉及缓存写入 |
| C7 PC/Android Coverage | √ | 后端命令/协议改动双端共享；前端 PC 房间模式修复，移动端房间功能未实现故无对应代码 |

## 4. 验收记录

### 构建命令
- 后端：`cd src-tauri && cargo build`
  - 结果：`Finished dev profile [optimized + debuginfo] target(s) in 3m 01s`，60 个 warning 均为 `preset_validator.rs` 预存在未使用函数，与本次改动无关。
- 前端：`npx tsc --noEmit`
  - 结果：本次改动文件（rooms.ts / types.ts / ChatArea.tsx / App.tsx 房间流式段）零新增错误。残留错误均为预存在（App.tsx:528-541 WorkspaceTransitionStage 类型、CharacterSidebar Switch/Match 未导入、MessageFormatRenderer/SchemaConfigPanel/WorkspaceTransitionStage），不在本次改动范围。

### 验收方式
1. 结构化模式联机：房主发起对话，房客实时看到 `structuredFields` 增量（打字机效果），流式结束 `isStreaming=false`，消息非空。
2. 纯文本模式联机：房客看到单倍文字（不再翻倍）。
3. 流式出错/中止：房客收到 `room:stream_end`，`isStreaming=false`，不卡死。
4. 房客 `TokenIsland` 不渲染，控制台无 `compile_prompt ERROR`。
5. 单人模式：`host_server=None`，所有广播 spawn 内静默跳过，行为不变。

### 预期效果
- 房客能实时看到房主的 AI 流式回复（结构化字段 + 纯文本）。
- 房客不再卡在 "正在流式" 状态。
- 房客控制台不再刷 `compile_prompt` 错误。

## 5. 已知限制 / 后续待办

- 不增加 chunk 重传 / 断点续传（沿用 room-stream-sync spec 决策）。
- 房客 `TokenIsland` 直接不渲染（房客无本地 prompt 上下文）；若后续房客需 token 估算，需房主通过房间协议下发。
- 结构化 `thinking` 字段会同步给房客（与房主渲染一致）；若需对房客隐藏，后续加 field 过滤。
- `room:context_snapshot` 不含 conversation/preset/world_book 行，房客本地 DB 仍无这些行——本次不修，仅用 TokenIsland 守卫绕过。
- 预存在 tsc 错误（App.tsx:528-541 等）不在本次范围，未处理。
