# 新功能增加：蓝图执行顺序标签（PC + Mobile 双端）

- 修改类型：新功能增加
- 时间：2026-08-26 11:15

## 1. 改动摘要

| 文件 | 改动 |
|------|------|
| `src/components/blueprint/nodeLayout.ts` | 新增 `computeExecutionOrder(graph)`：从 `start` 节点（或所有源节点）开始 BFS，沿 output→input 边为每个可达节点分配 1-based 执行顺序号。 |
| `src/components/blueprint/BlueprintCanvas.tsx` | ① 导入 `computeExecutionOrder` 并创建 memo；② 在节点头部左上角渲染圆形顺序徽章，存在徽章时标题右移避免重叠。 |
| `src-mobile/components/blueprint/mobileNodeLayout.ts` | 同步新增 `computeExecutionOrder(graph)`，与 PC 端算法一致。 |
| `src-mobile/components/blueprint/MobileBlueprintCanvas.tsx` | 同步导入、创建 memo、渲染顺序徽章并右移标题。 |

## 2. 改动动机

用户反馈蓝图画布仍显示旧布局且无执行顺序标签。检查发现：
- 竖向布局（端口在节点上下边缘）已在 `nodeLayout.ts` / `mobileNodeLayout.ts` 中实现，但运行中的应用未重建，因此仍显示旧水平布局。
- 执行顺序标签（Spec Checklist 8.2 / 13.2）尚未实现。

本次补全执行顺序标签的双端实现，使用户能在节点头部直接看到执行流序号。

## 4. 验收记录

- 构建命令：
  - `npx tsc --noEmit -p tsconfig.json` → exitCode 0，stdout 空。
  - `npx tsc --noEmit -p tsconfig.mobile.json` → exitCode 0，stdout 空。
- 验收方式：
  1. 类型检查零错误。
  2. 启动应用后，蓝图节点头部左侧应出现圆形数字徽章（从 start 节点开始编号）。
  3. 竖向布局效果：需重新构建/刷新 Tauri 应用后才能生效（源码已支持，运行二进制仍是旧构建）。
- 实际结果：两端 tsc 均通过。

## 5. 已知限制 / 后续待办

- 当前执行顺序是前端基于图拓扑的渲染用序号，仅供用户定向；真正的运行时执行顺序由后端 `blueprint_executor.rs` 决定。
- 若图中存在多个并行的源节点（无 start 节点时），它们会按节点数组顺序依次编号，可能不完全符合运行时语义。
- 竖向布局已在源码中实现，但用户截图仍显示旧水平布局，说明运行中的应用未重新构建。需要用户执行 `npm run tauri dev` / `npm run tauri build` 或重启已构建应用以加载最新前端 bundle。
