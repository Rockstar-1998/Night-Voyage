# 预设详情视图与 Gate 选择 UI（里程碑 C）

## 改动摘要

实现 spec `blueprint-runtime-selection-and-role-axis` 里程碑 C：在预设工作区
加入"台前"预设详情视图，用户在此选择 Gate 选项（互斥组单选 chip / 普通组多选
checkbox），蓝图编辑器退为"幕后"入口。

### 改动文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/lib/backend/types.ts` | 修改 | 新增 `PresetGateSelection` / `BlueprintGateOption` / `BlueprintGate` 三个接口 |
| `src/lib/backend/gates.ts` | 新建 | 4 个 Tauri command 包装：`updatePresetGateSelection` / `loadPresetGateSelections` / `clearPresetGateSelection` / `loadBlueprintGates` |
| `src/lib/backend/index.ts` | 修改 | 加入 `export * from './gates';` |
| `src/lib/backend.ts` | 修改 | **关键修复**：加入 `export * from './backend/gates';`——此文件遮蔽了 `backend/index.ts`，不加这行则 `'../lib/backend'` 导入路径解析到 `backend.ts` 而非 `backend/index.ts`，导致 gates 函数不可见 |
| `src/components/PresetDetailView.tsx` | 新建 | PC 预设详情视图：Gate 选择 UI（互斥 chip / 多选 checkbox）+ 乐观更新 + 错误回滚 + "编辑蓝图"入口 |
| `src/App.tsx` | 修改 | 导航从 2 层（卡片→编辑器）重构为 3 层（卡片→PresetDetailView→BlueprintEditor）；`editingPresetId` 拆为 `presetDetailId` + `editingBlueprintId` |
| `src-mobile/components/blueprint/MobilePresetDetailView.tsx` | 新建 | 移动端独立预设详情视图（C5 零代码耦合）：触控友好 chip/checkbox + safe-area 适配 + 移动端 header |
| `src-mobile/components/blueprint/MobilePresetBlueprintEntry.tsx` | 修改 | 导航从 2 层重构为 3 层；`handleOpenPreset` 改为进入详情视图；新增 `handleEditBlueprint` 从详情视图加载图并进入编辑器 |

### 函数/模块级改动

- **`src/lib/backend/gates.ts`**（新模块）：4 个 async 函数，封装 `invokeCommand`
  调用，与后端 `src-tauri/src/commands/blueprint.rs` 的 4 个命令一一对应。
- **`PresetDetailView`（PC）**：`onMount` 并行加载 gates + selections；`GateSelector`
  子组件按 kind 渲染 chip 或 checkbox；`handleToggle` 乐观更新 + IPC 失败回滚。
- **`MobilePresetDetailView`**：独立实现，不导入 PC 组件；交互模式适配触控
  （`active:scale-95` 反馈、更大触控目标、safe-area-top）。
- **`MobilePresetBlueprintEntry`**：`handleOpenPreset` 从"加载图→进编辑器"简化
  为"setViewingPreset(preset)"；原加载逻辑移至 `handleEditBlueprint`，由详情
  视图"编辑蓝图"按钮触发。

## 改动动机

spec §3.3 明确：Gate 选择 UI 应在预设工作区（"台前"），而非对话界面。蓝图
编辑器作为"幕后"配置工具。原导航直接从预设卡片进入蓝图编辑器，缺少让用户
选择 Gate 选项的中间层。本次改动补全该中间层。

**关键发现**：`src/lib/backend.ts`（向后兼容文件）在 TypeScript 模块解析中
优先于 `src/lib/backend/index.ts`（目录 + index）。此前里程碑 B 未在 `backend.ts`
中补 gates 的 re-export，导致 PC `PresetDetailView` 导入 `'../lib/backend'`
时解析到 `backend.ts`，4 个 gates 函数不可见，tsc 报 "no exported member"。
本次在 `backend.ts` 加入 `export * from './backend/gates';` 修复。

## 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 前端仅渲染 + IPC 调用，Gate 选择持久化由后端命令处理 |
| C2 Zero-Fallback Errors | √ | 加载/更新失败显式 toast，不静默跳过；乐观更新失败时回滚到前值 |
| C3 Responsiveness | √ | 选项点击只触发单条 IPC + 本地信号 patch；每个 Gate 独立小组件，选择变更只更新该 Gate 信号 |
| C4 AI UI Isolation | √ | 本改动不涉及 AI 动态 UI 层 |
| C5 Mobile Frontend Independence | √ | `MobilePresetDetailView` 完全独立实现，不导入 PC `PresetDetailView`；移动端交互模式（触控 chip/checkbox、safe-area）独立设计 |
| C6 Project Cache Location | √ | 本改动不涉及缓存写入 |
| C7 PC/Android Coverage | √ | PC（`src/`）与移动端（`src-mobile/`）均实现 PresetDetailView + 3 层导航；共享 `src/lib/backend/gates.ts` IPC 封装 |

npx tsc --noEmit -p tsconfig.json

### 验收方式

1. **tsc 双端通过**：PC 与移动端 `tsc --noEmit` 均退出码 0。
2. **backend.ts 遮蔽修复**：`src/lib/backend.ts` 加入 `export * from './backend/gates';`
   后，PC `PresetDetailView` 的 4 个 gates 函数导入可正确解析。
3. **导航 3 层结构**：PC `App.tsx` 与移动端 `MobilePresetBlueprintEntry.tsx`
   均从"卡片→编辑器"重构为"卡片→PresetDetailView→BlueprintEditor"。

### 预期效果

- 点击预设卡片 → 进入 PresetDetailView（台前），而非直接进蓝图编辑器
- PresetDetailView 展示该预设蓝图中所有 MutexGate / GroupGate 节点的选项
- 互斥组选项渲染为单选 chip（点击已选项清空选择）
- 普通组选项渲染为多选 checkbox
- 每个选项展示 label + description（description 为 null 时不渲染）
- 选择变更即时持久化到 `preset_gate_selections` 表（乐观更新 + 失败回滚）
- PresetDetailView 右上角"编辑蓝图"按钮进入 BlueprintEditor（幕后）

### 实际结果

- tsc 双端通过（退出码 0）
- 导航 3 层结构代码已就位（待运行时人工验收确认 UI 交互）

## 已知限制或后续待办

1. **运行时人工验收未做**：tsc 通过仅保证类型正确，实际 UI 交互（chip 点击、
   checkbox 切换、乐观更新回滚、IPC 失败 toast）需启动应用后人工确认。
2. **`openingPreset` 指示器在详情视图中不可见**：`handleEditBlueprint` 设置
   `openingPreset` 信号，但该信号仅在列表视图卡片上渲染"加载中…"。从详情
   视图触发编辑时，加载指示器不可见。图加载通常很快，暂不额外处理。
3. **`backend.ts` 与 `backend/index.ts` 双重 re-export**：这是历史遗留的向后
   兼容设计。两个文件都需要手动维护 re-export 列表，容易遗漏（本次即因此
   踩坑）。后续可考虑统一到单一入口，但不在本里程碑范围内。
