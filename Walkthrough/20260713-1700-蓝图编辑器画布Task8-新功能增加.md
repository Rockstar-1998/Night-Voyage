## 改动动机

蓝图编辑器需要一个可视化画布让用户以节点图方式编辑 preset。Task 7 已完成类型定义（`src/lib/blueprint/types.ts`）和迁移转换器（`migration.ts`），Task 8 在此基础上实现画布交互层。画布是纯渲染层（C1）：只渲染 + 转发用户操作事件，所有业务状态（graph / viewTransform / hiddenNodeIds）由父组件 BlueprintEditor（Task 10）持有。

## 关键设计决策

### 决策 1：Props 接口扩展（相对任务描述）

任务描述给出的 `BlueprintCanvasProps` 列出了 8 个字段，但 SubTask 8.6（眼睛图标切换显隐）需要一个回调，且任务描述的 "State" 章节明确说 `viewTransform` 通过 props 接收。因此最终 Props 在任务描述基础上**新增 2 个字段**：

```typescript
export interface BlueprintCanvasProps {
  graph: BlueprintGraph;
  viewTransform: ViewTransform;             // 新增：父组件持有，画布读取
  selectedNodeId: string | null;
  hiddenNodeIds: Set<string>;
  onNodeSelect: (nodeId: string | null) => void;
  onNodeMove: (nodeId: string, position: Position) => void;
  onEdgeCreate: (source: string, sourcePort: string, target: string, targetPort: string) => void;
  onEdgeDelete: (edgeId: string) => void;
  onGraphPan: (offset: Position) => void;
  onGraphZoom: (zoom: number) => void;
  onToggleNodeHidden: (nodeId: string) => void;  // 新增：SubTask 8.6
}
```

任务描述 "State" 章节提到 `draggingNodeId` 和 `connectingFrom` 也由父组件管理，但这两个是**瞬时交互状态**（无业务语义），放在父组件会导致 Props 接口膨胀且增加父子同步开销。本实现将其作为画布内部 `createSignal` 状态，符合"画布只渲染 + 转发意图"的 C1 边界。

### 决策 2：视图变换用嵌套 `<g transform>` 而非每节点全量变换

任务描述建议 `transform: translate(x*zoom+offsetX, y*zoom+offsetY) scale(zoom)`（每节点全量变换）。本实现采用嵌套方案：

```tsx
<svg>
  <g transform={`translate(${offsetX}, ${offsetY}) scale(${zoom})`}>
    <For each={nodes}>
      {(node) => <g transform={`translate(${node.position.x}, ${node.position.y})`}>...</g>}
    </For>
  </g>
</svg>
```

**优势**：
- 视图变换（pan/zoom）只更新外层 `<g>` 的 transform（1 处响应式写入）
- 节点移动只更新该节点的 `<g transform>`（SolidJS `<For>` 按引用追踪，只 patch 该节点）
- 两种变换正交解耦，SolidJS 细粒度响应式自然保证"节点位置变化只更新该节点的 transform"

### 决策 3：连线汇聚规则遵循 spec（input 端口可接多条边）

任务描述 SubTask 8.3 提到"input 端口已有连线 → 拒绝"，但 spec 明确说"汇聚（集线器）：一个 input 可接多条线（Gate/ModeSwitch 子链表末尾汇聚）"。两者冲突时以 spec（真相源）为准：

- `validateConnection` 不检查 input 端口已有连线
- 只拒绝**完全重复**的边（相同 source/source_port/target/target_port）
- 其他拒绝规则：自连、反向、环路、锁定端点

### 决策 4：环路检测用迭代 DFS（非递归）

`hasPath(edges, from, to)` 用显式栈迭代实现，避免深图递归栈溢出。`wouldCreateCycle(edges, source, target)` 在添加 source→target 之前检查是否已存在 target→source 的路径。

### 决策 5：Pointer Capture 统一三种手势

`InteractionState` 是判别联合（pan / node-drag / connect），同一时刻只有一个手势活跃。手势开始时 `setPointerCapture(pointerId)` 在 SVG 根上，确保手指/鼠标移出 SVG 边界仍能收到 move/up 事件。手势结束 `releasePointerCapture`。

### 决策 6：连线终点检测用 `document.elementFromPoint` + `data-*` 属性

由于 Pointer Capture 后 `pointerup` 的 `e.target` 是 SVG 根（不是实际命中的端口圆点），用 `document.elementFromPoint(clientX, clientY)` 找到实际元素，再 `closest('[data-port-kind="input"]')` 向上查找 input 端口。端口圆点带 `data-node-id` / `data-port` / `data-port-kind` 三个 data 属性。

### 决策 7：滚轮缩放用非被动监听器

SolidJS 的 `onWheel` 用事件委托，可能是 passive 的，无法 `preventDefault`。本实现用 `onMount` + `addEventListener('wheel', handler, { passive: false })` + `onCleanup` 移除，确保能阻止页面滚动。缩放保持鼠标位置在图坐标中不变（zoom-to-cursor）。

### 决策 8：节点内联渲染（不拆 8 种节点组件）

任务明确要求"本任务画布内联渲染节点（简单矩形+标题+端口）"，不实现 8 种节点组件（Task 9）。所有节点共用一套渲染逻辑，仅通过 `computeNodeLayout(node)` 返回的 `accentColor` / `title` / `subtitle` / `ports` 区分外观。

### 决策 9：眼睛/锁图标用纯 SVG 形状（非 lucide 组件）

lucide-solid 图标是 `<svg>` 组件，嵌套在 SVG 内需要 `foreignObject`，引入 HTML-in-SVG 复杂性。本实现用基本 SVG 形状（ellipse + circle 画眼睛，rect + path 画锁）直接绘制，事件处理在 `<g>` 上更可靠。隐藏状态用红色斜线覆盖眼睛图标。

### 决策 10：边删除用 onPointerDown（非 onClick）

边点击热区是 14px 宽的透明 stroke。用 `onPointerDown` + `stopPropagation` 立即删除，避免 pan 误触发。锁定节点的边拒绝删除并 toast 提示。

## 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 画布只渲染 + 转发用户意图（onNodeMove / onEdgeCreate / onEdgeDelete / onGraphPan / onGraphZoom / onToggleNodeHidden），无业务计算、无持久化、无后端调用。环路检测和连线校验是**输入校验**（拒绝无效用户操作），不是业务逻辑 |
| C2 Zero-Fallback Errors | √ | 所有无效操作（自连/反向/环路/重复/锁定端点）显式 toast 报错，不静默吞掉；连线终点未命中 input 端口时静默取消（这是正常的用户取消手势，不是错误） |
| C3 Responsiveness | √ | 节点位置用 SVG `transform` 属性（合成友好，不触发 layout）；SolidJS `<For>` 按引用追踪节点，单节点移动只 patch 该节点 transform；pan/zoom 只更新外层 `<g>` transform；缩放钳制在 [0.2, 3.0] 防止极端值 |
| C4 AI UI Isolation | √ | 不涉及 AI 渲染层 |
| C5 Mobile Frontend Independence | √ | 画布组件在 `src/components/blueprint/`（PC 专属）；`nodeLayout.ts` 是纯函数无 SolidJS 依赖，移动端（Task 13）可通过相对路径 `../../src/components/blueprint/nodeLayout` 引用——这是 spec 明确允许的共享层（类型 + 纯逻辑），不是 UI 代码耦合 |
| C6 Project Cache Location | √ | 不涉及缓存写入 |
| C7 PC/Android Coverage | √ | 本任务是 PC 端（Task 8）；移动端画布在 Task 13 独立实现。`nodeLayout.ts` 设计为双端可复用 |

### 验收方式

1. **类型检查**：`npx tsc --noEmit` 退出码 0（真实输出见上）
2. **Props 接口**：导出 `BlueprintCanvasProps`，含 10 个字段（任务描述的 8 个 + `viewTransform` + `onToggleNodeHidden`）
3. **视图变换**：父组件通过 `viewTransform` prop 传入 { offsetX, offsetY, zoom }；画布渲染外层 `<g transform="translate(offsetX, offsetY) scale(zoom)">`；滚轮缩放保持鼠标位置不变（zoom-to-cursor）；缩放钳制 [0.2, 3.0]
4. **节点拖拽**：`handleNodePointerDown` 记录起始屏幕坐标 + 起始节点位置；`handlePointerMove` 用 `(deltaScreen / zoom)` 转换为图坐标增量，调用 `onNodeMove`；锁定节点不可拖拽
5. **连线交互**：output 端口 `onPointerDown` 启动手势（`stopPropagation` 防止节点拖拽）；move 更新临时贝塞尔线；up 时 `document.elementFromPoint` + `closest('[data-port-kind="input"]')` 找终点；`validateConnection` 校验后调 `onEdgeCreate` 或 toast 报错
6. **环路检测**：`wouldCreateCycle(edges, source, target)` 用迭代 DFS 检查添加 source→target 后是否成环（即是否已存在 target→source 路径）
7. **锁定节点**：`isNodeLocked` 只对 Prompt / SchemaField / SamplingParams 返回 `is_locked` 字段；拖拽、连线起点、连线终点、边删除四处均检查锁定状态
8. **显隐切换**：每个节点右上角眼睛图标，`onPointerDown` stopPropagation + `onClick` 调 `onToggleNodeHidden`；`visibleNodes` memo 过滤 `hiddenNodeIds`；隐藏节点的边也隐藏（`isEdgeHidden` 检查两端是否在 hiddenNodeIds 中）
