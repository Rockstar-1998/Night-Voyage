# Walkthrough: 结构化输出数组字段流式渲染修复

- 修改类型: 修改
- 日期: 2026-08-22
- 主题: 流式结构化输出时 `todo_list` / `options` 等数组字段不进入 UI

## 1. 改动摘要

**问题**：PC 端流式结构化输出时，只有 `thinking`（string）和 `status_bar`（object）实时渲染，
数组字段（`todo_list`、`options`）在流式过程中完全不出现，流结束后若前端仍走 `structuredFields`
（非空则优先于完整 `content`）也会永久缺失，用户滚动到底也看不到这些字段。

**根因**：`structured_output_parser.rs` 的 `complete_container_value` 只对 `Value::Object`
发 `ObjectFieldComplete` 事件；遇到 `Value::Array` 仅做内部 `fields.insert`，**不发任何事件**，
导致该字段在流式链路中没有出口。

**改动文件与函数**：

- `src-tauri/src/services/structured_output_parser.rs`
  - `StructuredOutputEvent` 枚举新增变体 `ArrayFieldComplete { key: String, value: Value }`。
  - `complete_container_value`：对 `Value::Array` 额外 push `ArrayFieldComplete` 事件
    （对象分支保持 `ObjectFieldComplete` 不变，隔离性最好，不动既有测试与联机广播）。

- `src-tauri/src/services/stream_processor.rs`
  - 三处 `ObjectFieldComplete` 消费点（openai_compatible 1 处、anthropic 2 处）各补一个
    `ArrayFieldComplete` 分支：序列化 `value.to_string()`（数组 JSON 字符串），走与对象相同的
    `emit_object_field_complete_event`，把数组写进对应 `content_part.json_value` 并广播
    `object_field_complete` 事件。
  - 对象分支保持 `Value::Object(value).to_string()` 不变（其 `value` 为 `Map`，需包成 `Value::Object`）。

**前端零改动**：宿主 PC 前端 `MessageItem.tsx:86` 已支持 `[` 前缀数组 JSON（kind='array'），
`App.tsx` 的 `object_field_complete` 处理器把 JSON 字符串推进 `structuredFields`；联机客户端
走 `RoomMessage::StreamObjectFieldComplete`（JSON 字符串，不分类型）。数组复用同一通道即可渲染。

## 2. 改动动机

用户实测：round 113 的 NVIDIA 回复含 `thinking` / `status_bar` / `todo_list` / `options` 四字段，
UI 只显示了 `thinking` 与部分 `todo_list` 内容，`status_bar` 卡片与 `options` 选项始终缺失。
确认滚动到底仍缺失，判定为确定性渲染 bug，非截图截断。修复后数组字段将与对象字段一样实时出现。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 后端负责解析与事件下发，前端只渲染 |
| C2 Zero-Fallback Errors | √ | 解析失败走既有 `ParseError` 事件，无静默回退 |
| C3 Responsiveness | √ | 事件驱动增量渲染，无阻塞 |
| C4 AI UI Isolation | √ | 不涉及 AI 生成 UI 沙箱 |
| C5 Mobile Frontend Independence | √ | 后端改动，未跨端互引 |
| C6 Project Cache Location | √ | 无缓存写入 |
| C7 PC/Android Coverage | √* | 本条改动覆盖 PC 宿主 + 联机广播两通道；**移动端独立前端从未实现结构化输出渲染**（pre-existing 缺口，非本次引入），见「已知限制」 |

> *C7 说明：本次修复本身是后端事件层，PC 宿主与联机房间客户端均通过同一 `object_field_complete`
> 通道获得数组字段。移动端（`src-mobile/`）目前完全无 `structuredFields` / `object_field_complete`
> 渲染代码——这是结构化输出功能在移动端的既有缺失，本次未扩大也未修复，列为后续独立任务。

## 5. 已知限制或后续待办

- **移动端结构化输出渲染缺失（C7 既有缺口）**：`src-mobile/` 完全没有 `structuredFields` /
  `object_field_complete` / `parseStructuredResponse` 相关代码，移动端不渲染任何结构化字段。
  需另立任务实现移动端结构化渲染（对象键值卡 + 数组可点击选项），才能满足 C7 双端覆盖。
- 本次未做前端改动，依赖既有数组解析路径；若后续预设 schema 出现嵌套数组/对象混合结构，
  需回归 `MessageItem.tsx` 的 `StructuredField` 类型支持。
