## 业务摘要

为每轮 Agent 执行建立事务级状态基线，使 Regenerate / Delete / Rewind 的状态回滚从「无保障」变为「原子还原」：

- **迁移 `0051_round_snapshots.sql`**：新表 `round_snapshots(conversation_id, round_id, round_index, state_json, captured_at)`，主键 `(conversation_id, round_id)`。
- **新增 `src-tauri/src/repositories/round_snapshot_repository.rs`**（`RoundSnapshotRepository`）：`capture_baseline`（直读 DB 持久化状态、首次捕获为准 `INSERT OR IGNORE`——同轮自动重试/失败重试再次进入执行入口不得污染基线）、`load`、`restore`（经 `save_session_state` 原子写回；无基线返回 `false` 不报错，兼容历史轮次）、`delete_for_round`、`delete_after_round_index`（级联清理）。
- **捕获接线**：`stream_processor::spawn_stream_task` 在任务启动、任何生成开始前捕获基线；捕获失败按 C2 走既有失败收尾路径（mark_failed + `llm-stream-error`），绝不无保障裸奔。
- **Regenerate 原子回滚**：`ChatService::regenerate_round` 在建新 swipe 之前先 `restore` 该轮基线并丢弃残留暂存缓存——扣过款的轮次重新生成不再重复扣款。
- **Rewind 级联恢复**：`rewind_to_round` 删除后续轮次后，还原目标轮基线、丢弃暂存缓存、级联删除后续轮次的快照（目标轮基线保留，供其重新执行时继续充当回滚基线）。
- **Delete 级联恢复**：`delete_message` 在删除前预取轮次序号与「是否为最后一轮」；轮次被彻底删除时——最后一轮 → 还原其基线并丢弃暂存；中间轮 → 仅删除其快照记录（语义边界见下）。
- **SubmitAbort 补齐**：既有链已实现「轮次状态轮询中止 → 流任务停止消费、局部的流式工具累积器随任务析构」；本单补上缺失环节——`agent_runtime::discard_session_state_cache`，中止分支物理丢弃回合内未提交的暂存状态（此前该缓存会残留并被下一回合优先读到，是脏数据通道）。
- **能力矩阵适配**：`MODE_CAPABILITIES` 九模式保持纯数据查表、单元格未动；新增纯推导谓词 `ModeCapabilities::requires_snapshot_rollback(op)`——被放行（Allow / SnapshotLimited）的 Regenerate/Delete/Rewind 必须联动快照回滚，被 Block 的操作不执行故不回滚，其余操作恒假。全 9 模式 × 7 操作矩阵测试锁定。

## 语义边界（明确记录）

- **Delete 中间轮不回滚状态**：后续轮次仍然存在，其快照基线建立在包含被删轮突变的现状态之上；强行回退到被删轮基线会让后续轮次的状态前提失效。此时仅清理被删轮的快照记录，状态突变保留（与本功能上线前行为一致，不产生新的不一致）。
- **历史轮次无基线**：本功能上线前产生的轮次没有快照，restore 返回 false 并按现状继续——这是数据不存在的客观事实，不是静默回退；新轮次自捕获接线起强制有基线。
