# [修改] 蓝图编辑器：PROMPT 输出顺序 + schema 生效到回复体

## 1. 改动摘要

### `src-tauri/src/services/prompt_compiler.rs`
- **Bug 1（PROMPT 顺序反转）**：蓝图系统块排序由原升序改为分段排序。
  - `PresetRule` 块（`kind == PromptBlockKind::PresetRule`，即蓝图 PROMPT 节点，priority 10..=100）按 `priority` **降序**排列——`core_identity`(100) 在前，`mem_stateless`(40) 在后。
  - 其余元块（kind 层 priority ≥150：MultiplayerProtocol=150、CharacterBase=200、PlayerBase=250、WorldBookMatch=300 …）保持**升序**并排在全部 PresetRule 之后。
  - 两组数值无重叠（preset 10..=100 < meta 150+），因此该改法只反转 preset 规则内部顺序，同时保留既有的「preset 规则在前、元块在后」边界。
  - 修正了蓝图路径把 `system_blocks.sort_by_key(|b| b.priority)`（升序）导致的回归：原把 `core_identity` 推到最后、`mem_stateless` 顶到最前。
- **Bug 2（schema 对回复无效）**：在蓝图合并段（原 line ~661 之后）新增逻辑——当蓝图 `structured_output_schema` 的 `properties` 非空（即蓝图定义了至少一个 schema 字段）时，强制将 `preset_compiler_data.params.response_mode` 设为 `"structured_json"`；空 schema（`properties: {}`）不切，避免把无 schema 节点的纯蓝图对话也变成结构化输出。

### `src-tauri/src/llm/mod.rs`
- `build_openai_structured_json_response_format`：OpenAI `response_format` 的 `strict` 由 `true` 改为 `false`。
  - 原因：蓝图 `SchemaField` 支持 `required: false` 的可选字段（不在 schema 的 `required` 数组里），OpenAI 严格模式要求「所有属性要么在 required、要么类型含 null」，否则请求被拒。非严格模式仍按 JSON Schema 约束输出形状。
  - 与既有单测 `openai_structured_json_request_sets_json_schema_format`（断言 `strict == false`）对齐——原代码 `true` 与该单测预期不符，属潜在回归。

## 2. 改动动机
- **Bug 1 现象**：默认预设「Night Voyage 默认预设.nvpreset.json」第一个 PROMPT 节点是 `core_identity`（priority 100），但实际输出系统块第一块却是 `【记忆模式：无状态感知】`（`mem_stateless`，priority 40），顺序被反转。
- **Bug 2 现象**：蓝图产出 `structured_output_schema` 后，请求体里没有任何结构化约束，模型按 PROMPT 节点写散文；schema 对回复完全无效。根因：`provider_adapter` 仅在 `response_mode == "structured_json"` 时注入 `response_format`(OpenAI)/`output_config`(Anthropic)，而蓝图路径只塞了 schema、从未切 `response_mode`。
