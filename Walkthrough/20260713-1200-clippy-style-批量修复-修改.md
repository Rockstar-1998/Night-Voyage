### 1.2 R1 手动修复 — `RoomMessage` large_enum_variant

**问题**：`src-tauri/src/network/mod.rs:38` 的 `RoomMessage` 枚举最大变体 `JoinSuccess`（792 bytes）与第二变体 `ContextSnapshot`（512 bytes）差异过大，clippy 建议用 `Box` 缩减枚举大小。

**修复策略**：将 `JoinSuccess.conversation: ConversationListItem`（约 272 bytes 的 struct）改为 `Box<ConversationListItem>`，以缩小最大变体。

**改动文件与位置**：

| 文件 | 行号 | 改动 |
|------|------|------|
| `src-tauri/src/network/mod.rs` | 47 | `conversation: ConversationListItem` → `conversation: Box<ConversationListItem>` |
| `src-tauri/src/network/mod.rs` | 794 | `RoomJoinSession.conversation: ConversationListItem` → `Box<ConversationListItem>`（保持类型一致，match 解构时直接 move，零拷贝） |
| `src-tauri/src/network/mod.rs` | 1337 | 构造 `RoomMessage::JoinSuccess { conversation, ... }` → `conversation: Box::new(conversation)` |
| `src-tauri/src/commands/rooms.rs` | 245 | `conversation: Some(session.conversation)` → `conversation: Some(*session.conversation)`（解 Box 给 `RoomJoinResult.conversation: Option<ConversationListItem>`） |

**未改动位置**：
- `network/mod.rs:1651` 的 match 解构 `RoomMessage::JoinSuccess { conversation, ... }`：因为 `conversation` 字段类型变了，但解构后 `conversation` 变量自动是 `Box<ConversationListItem>`，move 到 `RoomJoinSession.conversation`（同类型）无需调整。

**影响评估**：`Box<T>` 在 serde 中是透明的，序列化结果一致；`Box` 解引用会自动 deref，访问字段无需修改；`rooms.rs:245` 处需要显式 `*session.conversation` 解 Box 以赋值给非 Box 类型的 `RoomJoinResult.conversation`（前端通过 serde 读取该字段，类型不变）。

### 1.3 R2 手动修复 — `conversations.rs` type_complexity

**问题**：`src-tauri/src/commands/conversations.rs:1069` 出现 9 元组 `(Option<String>, Option<i64>, Option<i64>, Option<i64>, Option<i64>, String, String, Option<String>, String)` 用于 `sqlx::query_as` 返回类型，触发 `type_complexity`。

**修复**：在 `conversations.rs` 顶部（第 13 行后）抽 `type` alias：

```rust
type ConversationForkOriginal = (
    Option<String>,
    Option<i64>,
    Option<i64>,
    Option<i64>,
    Option<i64>,
    String,
    String,
    Option<String>,
    String,
);
```

并将 `conversations_fork` 函数内：
```rust
let original: (Option<String>, Option<i64>, Option<i64>, Option<i64>, Option<i64>, String, String, Option<String>, String) = sqlx::query_as(...)
```
替换为：
```rust
let original: ConversationForkOriginal = sqlx::query_as(...)
```

**影响评估**：仅类型别名，零运行时影响；该 9 元组只在 `conversations_fork` 中使用一次，未跨函数复用。

### 1.4 R5 手动修复 — `mem0_snapshot.rs` unnecessary_sort_by（降序变体）

**问题**：`src-tauri/src/services/mem0_snapshot.rs:171` 的 `snapshots.sort_by(|a, b| b.round_index.cmp(&a.round_index))` 是降序排序，`--fix` 未自动应用（需要 `std::cmp::Reverse` 导入）。

**修复**：
```rust
// 修改前
snapshots.sort_by(|a, b| b.round_index.cmp(&a.round_index));
// 修改后
snapshots.sort_by_key(|s| std::cmp::Reverse(s.round_index));
```

用全路径 `std::cmp::Reverse` 避免修改 use 区。

## 2. 改动动机

P4 阶段批量消除 clippy style 警告，让代码风格更贴近 Rust 官方推荐。本阶段所有修复均为机械重构，不改变运行时行为：
- 类型别名 + Box 包装 + sort_by_key 替换 + 嵌套 if 合并 + 单 arm match 改 if。
- 严格遵守"组合优于继承、类型驱动、最小分支"的项目 Rust 风格准则。
- 不触碰 D4-D9/D11 死代码删除决策（这些由主 agent 单独处理）。

## 5. 已知限制或后续待办

1. **`too_many_arguments`（21 处）**：本阶段未处理。这些函数（如 `preset_repository::create`/`update`、`chat_service::emit_llm_stream_event`、`stream_processor::spawn_stream_task` 等）参数数量超标，但重构为 builder 模式或参数对象会改变公共 API，超出 P4 "机械修复" 范围。已批准为后续重构候选。
2. **D4-D9/D11 dead code（9 处）**：保留不动，由主 agent 单独处理。涉及 `prompt_compiler.rs`、`provider_adapter.rs`、`chat_service.rs` 中未使用的函数/字段/变体。
3. **R5 全路径 `std::cmp::Reverse`**：使用全路径避免修改 use 区，如果文件后续需要更多 Reverse 用法，可考虑提取 `use std::cmp::Reverse;`。
4. **R1 仅 Box 一个字段**：当前只把 `JoinSuccess.conversation` Box 化以消除 large_enum_variant 警告。如果未来 `JoinSuccess` 或 `ContextSnapshot` 新增大字段导致警告复现，需进一步 Box 或抽取 inner struct。当前 clippy 已无 large_enum_variant 警告。
5. **`ConversationForkOriginal` type alias 单次使用**：当前仅在 `conversations_fork` 中使用一次。若未来该 9 元组在其他函数复用，alias 已就绪。
