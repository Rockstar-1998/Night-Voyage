# 20260915-0115-三态记忆对齐与蓝图RPG背包运算门禁规范重构-修改

## 1. 改动摘要

- **受影响文件**：[`plans/agent-system-architecture-plan.md`](file:///d:/data/Night%20Voyage/plans/agent-system-architecture-plan.md)
- **改动内容**：
  1. **修正三态会话记忆基石表述**：
     - 正确梳理系统现存的三大记忆模式：`STATELESS`（无状态感知）、`LEGACY`（经典滑动窗口）、`MEM0`（向量与实体记忆），明确其由原生蓝图 `ModeSwitch` 节点分流作为底层基础设施；
     - 会话推进层明确划分为 **Standard 标准推进**（0 额外状态机开销直通现有管线）与 **Agent 跑团游戏机制引擎**（在三态记忆之上激活自定义 ToolCall、背包状态机与多智能体）；
  2. **全面增补跑团 RPG 高级机制与蓝图能力**：
     - **结构化游戏状态机（`GameState` / `InventoryItem`）**：支持数值属性（HP/Gold/Weight）与背包物品管理，纯内存计算 + 回合定稿单次持久化；
     - **`ToolDefinition` 节点**：创作者在蓝图上可视化声明自定义 ToolCall 契约（JSON Schema 参数与描述），编译期自动注册给大模型；
     - **`Calculator` 运算器节点**：确定性数学运算（加减乘除/Clamp）与背包增删扣减（`add_item` / `remove_item` / `recompute_weight`），杜绝大模型随意凭空造物或算错金币；
     - **`ConditionGate` 判定门禁节点**：超重判定、金币充足判定、背包满位拦截、道具数量校验；双出口 `pass` / `blocked`，未通过时阻断修改并生成结构化错误提示；
     - **`ToolReturn` 节点**：将成功结果或阻断错误打包为 ToolResult 回传大模型，强迫大模型按客观规则与数值结果推进剧情；
     - 提供完整的“商店购买铁剑 -> 金币校验 -> 超重校验 -> 扣款入包”全流程 ASCII 蓝图拓扑图；
  3. **前台操作与调试对齐**：在调试抽屉中增补游戏状态查看器（GameState Viewer），支持实时观测与单步调试金币、负重进度条与背包物品清单。

## 2. 改动动机

响应用户两点核心纠偏：
1. 架构总览图表述混淆，忽视了项目既有的三模式（`STATELESS` / `LEGACY` / `MEM0`）；
2. 原方案缺少核心跑团与 RPG 功能，只能生硬定义 Agent，无法支持背包系统、数值增减、超重判定、金币扣除、背包满位拦截，以及无法自定义 ToolCall。
通过本次重构，将 Agent 蓝图从单薄的“提示词组装流水线”真正升级为具备确定性规则与数值计算能力的“跑团与游戏逻辑图”。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 背包运算、数值增减、门禁阻断与 ToolCall 调度完全在 Rust 后端执行，前端仅负责状态渲染展示 |
| C2 Zero-Fallback Errors | √ | 规则门禁未通过时显式抛出具体拦截原因（如金币差额、超重公斤数），严禁静默放行或自动降级 |
| C3 Responsiveness | √ | `GameState` 在内存中纳秒级运算，仅在回合结束单次写入 SQLite，UI 线程永不阻塞 |
| C4 AI UI Isolation | √ | 不触碰 AI 沙箱隔离层 |
| C5 Mobile Frontend Independence | √ | 规范普适约束双端，PC 抽屉与移动端面板独立渲染 |
| C6 Project Cache Location | √ | 零磁盘临时文件，纯内存变量流转，符合 C6 规范 |
| C7 PC/Android Coverage | √ | 蓝图节点与背包状态引擎同时无缝覆盖 PC 与 Android 双端 |
