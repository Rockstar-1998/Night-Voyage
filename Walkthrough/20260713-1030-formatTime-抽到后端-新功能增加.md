# formatTime 抽到 Rust 后端 — 新功能增加

## 1. 改动摘要

将 PC `src/components/SessionSidebar.tsx` 与移动端 `src-mobile/components/SessionList.tsx` 中逐字重复的 `formatTime` 本地工具函数迁移到 Rust 后端 Tauri 命令，两端通过 Tauri IPC 调用同一份后端实现。

### 原 formatTime 实现（两端完全相同）

```ts
const formatTime = (timestamp: number) =>
  new Date(timestamp * 1000).toLocaleString('zh-CN', {
    month: '2-digit',
    day: '2-digit',
    hour: '2-digit',
    minute: '2-digit',
  });
```

### 新命令签名

```rust
#[tauri::command]
pub fn format_timestamp(timestamp: i64) -> Result<String, String>
```
- 输入：Unix 秒级时间戳
- 输出：`MM/DD HH:mm`（本地时区，与 `Date.toLocaleString('zh-CN', …)` 输出形状一致）
- 错误：无效时间戳返回 `Err(String)`，遵循 C2

```rust
#[tauri::command]
pub fn format_timestamps(timestamps: Vec<i64>) -> Result<Vec<String>, String>
```
- 批量版本，索引一一对应，避免 N 条会话触发 N 次 IPC

### 前端调用模式（两端一致）

```ts
const [formattedTimes] = createResource(
  () => props.sessions,
  async (sessions) => {
    if (sessions.length === 0) return new Map<number, string>();
    const timestamps = sessions.map((s) => s.updatedAt);
    const formatted = await formatTimestamps(timestamps);
    const lookup = new Map<number, string>();
    timestamps.forEach((ts, idx) => lookup.set(ts, formatted[idx]));
    return lookup;
  },
);
// 渲染热路径：formattedTimes()?.get(session.updatedAt) ?? ''
```

## 2. 改动动机

- **消除跨前端重复**：两端 `formatTime` 函数体完全相同，存在维护漂移风险。
- **遵循 C1 前端只渲染**：时间格式化属于"非渲染逻辑"，按 guardrails 应放后端。
- **遵循 C5 移动端独立**：新增 `src-mobile/lib/backend/` 目录，移动端拥有自己的 IPC 封装，不通过 import PC 端代码复用 `formatTimestamp`。
- **遵循 C7 双端覆盖**：同一后端命令同时服务 PC 与 Android。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 时间格式化逻辑全部在 Rust 后端 `commands::utils`；前端只做 IPC 调用与渲染 |
| C2 Zero-Fallback Errors | √ | Rust 命令返回 `Result<String, String>`；无效时间戳以 `Err` 显式抛出，无 `unwrap()` / `expect()` / `ok()` 吞错；前端 `createResource` 错误会经 SolidJS Resource 状态暴露给 UI（resource.error 可读），无静默回退；`formattedTimes()?.get(...) ?? ''` 的 `''` 仅是资源加载完成前的占位渲染（loading state），并非错误吞掉 |
| C3 Responsiveness | √ | 渲染热路径只做同步 `Map.get` 查表；批量 IPC 仅在 `props.sessions` 引用变化（父级 reload）时触发，搜索过滤不触发重取；本地时区格式化在后端为纯 CPU 计算，无 IO |
| C4 AI UI Isolation | √ | 本次改动与 AI 动态 UI 层无关 |
| C5 Mobile Frontend Independence | √ | 移动端 `formatTimestamp` 封装在独立 `src-mobile/lib/backend/utils.ts`，未通过 `'../../src/lib/backend'` 复用 PC 代码；两端只共享同一份 Rust 命令 |
| C6 Project Cache Location | √ | 新建 `D:\software_cache\tsconfig.mobile.scan.json` 落在统一缓存目录，未写入系统盘 |
| C7 PC/Android Coverage | √ | 同一 Rust 命令同时注册到 `invoke_handler`，PC 与移动端均可调用；两端调用模式一致 |

### 上报：发现已有 C5 违例（不在本任务范围）

- **风险点**：`src-mobile/App.tsx:24` 与 `src-mobile/components/SessionList.tsx:3` 现存 `import { … } from '../../src/lib/backend'`（直接复用 PC 端 `src/lib/backend`），违反复 C5 "禁止移动端代码 import PC 端的工具函数"
- **影响范围**：移动端 `CharacterCard`、`ConversationListItem`、`resolveImageSrc`、`conversationsList` 等共享导入当前均走 PC 端代码
- **建议的修正方向**：在 `src-mobile/lib/backend/` 下建立独立的 types/conversations/characters/assets 等模块副本（或抽公共类型包），由移动端独立维护；本次任务不扩展此违例，新增的 `formatTimestamp` 已正确隔离

## 5. 已知限制或后续待办

### 5.1 已知限制

1. **`src/lib/backend.ts` shim 文件遮蔽 `backend/index.ts`**：TypeScript 模块解析中，`'../lib/backend'` 命中 `src/lib/backend.ts`（文件）而非 `src/lib/backend/index.ts`（目录索引）。本次任务为兼容 shim 追加了 `export * from './backend/utils';`。后续若清理 shim，需同步移除该行。
2. **异步化对热路径的潜在影响**：原 `formatTime` 同步返回字符串；改为 `createResource` 后，首次渲染时 `formattedTimes()` 为 `undefined`，渲染为空字符串。该空白持续时间极短（一次 IPC 往返 + 后端纯 CPU 计算），且只在 `props.sessions` 引用变化时触发一次（搜索过滤不触发）。若实测发现肉眼可见闪烁，可考虑在 `App.tsx` 加载 sessions 时同步预格式化并塞入 store。
3. **`toLocaleString('zh-CN', …)` 的 ICU 输出形状未在 Rust 完整复刻**：JS `toLocaleString` 输出依赖宿主 ICU 数据，可能因 WebView 版本产生细微差异（分隔符、字段顺序）。Rust 实现固定输出 `MM/DD HH:mm`。若实际 WebView 显示与此前不一致，需要调整 Rust 端 `format!` 模板。
4. **`D:\software_cache\tsconfig.mobile.scan.json` 不是仓库文件**：仅用于本地 tsc 扫描，不应提交到 git。
5. **现有 C5 违例未修复**：移动端从 PC `src/lib/backend` 导入 types/IPC 封装的问题未在本任务中处理（超出范围）。
