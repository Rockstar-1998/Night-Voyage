## 1. 改动摘要

- **移动端前端独立性与契约（`src-mobile/lib/backend/`）**：
  - 新建 `types.ts`、`ui_layout.ts`、`schema.ts`、`game_state.ts`、`actionBridge.ts`，独立封装移动端所需的 UI 布局、Schema 与会话状态 Tauri commands 与类型契约，彻底解开对 PC 端 `src/lib/backend/` 的跨端相对引用，严格遵守 **C5 移动端独立性**。
- **移动端 UI 设计器能力对齐（`src-mobile/components/preset/MobileUiDesignerModal.tsx`）**：
  - **嵌套控件完整配置**：补全嵌套 Widget 的控件类型切换（`widgetType`）、自由坐标与自适应宽高（`x`, `y`, `width`, `height`）、StatBar 专属配置（条色 `bar_color`、条厚 `bar_thickness`、方向 `vertical`、上限绑定 `max_stat`）、Badge 专属配置（`badge_background`、`badge_color`）、ActionButton 专属配置（白名单命令 `command`、结果卡 `result_schema_id`）；
  - **嵌套容器完整配置**：补全嵌套 Container 的容器类型切换（`kind: panel/tabs/grid`）、排版模式（`layoutMode: flex/absolute/grid`）与尺寸输入（`width`, `height`, `x`, `y`）；
  - **根容器子项配置对齐**：同样为顶层 Widget 补充控件类型切换、坐标尺寸及各类专属配置卡片；
  - **根除硬编码预览数据（C11）**：移除 `PREVIEW_SNAPSHOT` 硬编码假数据，通过 `sessionGameStateGet` 动态获取当前真实会话状态，无会话时采用 `EMPTY_SNAPSHOT` + 青色设计态占位徽标呈现，实现双端预览行为完全一致。
- **C2 零静默回退加固**：
  - **PC 端 `LayoutTreeNode.tsx`**：当 StatBar 的 `max_stat` 属性指定了绑定路径但在快照中无法解析为有效正数且处于非设计预览态时，显式标记并渲染报警红字 `上限错误: {max_stat}`，杜绝静默进度归零；
  - **移动端 `MobileLayoutTree.tsx`**：移除 `max_stat` 缺失时静默降级为定值 `100` 的兜底代码，当 `max_stat` 无效且非设计态时显式报警 `上限错误: {max_stat}`，保持双端零静默回退一致性；
  - **PC 端 `UiDesignerModal.tsx`**：修复会话状态加载时 `.catch(() => {})` 吞异常的隐患，将其通过 `report(..., true)` 显式上报为警告。
- **后端宏持久化与归一化单元测试覆盖**：
  - `src-tauri/src/commands/blueprint.rs`：新增 `test_normalize_blueprint_graph_preserves_macros` 单元测试，验证经 `normalize_blueprint_graph` 归一化后的图 JSON 完整保留宏定义及其子图拓扑；
  - `src-tauri/src/services/preset_service.rs`：新增 `test_preset_export_import_preserves_macros` 单元测试，验证预设导出与导入往返闭环后，`macros` 宏资产完整无损保真。

## 2. 改动动机

- 依据双审查员（Standards Reviewer 与 Spec Reviewer）的审查反馈：
  1. 移动端 UI 设计器在此前的提交中，嵌套控件与容器缺少控件类型切换与专属配置卡片，违反了 C7 双端覆盖原则；
  2. 移动端 UI 设计器仍残留硬编码的示例物品假数据，违反 C11 No Hardcoded Data 原则；
  3. StatBar 进度条在 `max_stat` 数据源缺失时，移动端静默回退为 100，PC 端静默归零不报错，违反 C2 零静默回退原则；
  4. 缺少专门针对宏在 `normalize_blueprint_graph` 及预设导入导出中的保真单元测试。
- 本次改动针对上述 4 项问题实施系统性闭环修复与全量测试验证。

| C1 Frontend Render-Only | √ | 前端只负责布局树状态维护与渲染，布局保存与契约校验全量由 Rust 后端处理 |
