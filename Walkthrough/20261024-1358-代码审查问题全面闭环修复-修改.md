# 代码审查问题全面闭环修复留痕记录

## 1. 改动摘要

针对最新一次双轴代码审查（Standards 轴与 Spec 轴）提出的所有遗留问题进行了深度工程修复与闭环对齐：

1. **`src-tauri/src/models/blueprint.rs`**：
   - 将 `is_tool_allowed` 与 `resolve_tools` 提取至结构体 `AgentToolPermissions`，消除结构体间的代码重复与特性依恋（Feature Envy）；
   - `ScriptwriterStage`、`DirectorConfig` 与 `ActorDefinition` 的对应方法统一委托给 `AgentToolPermissions` 执行。

2. **`src-tauri/src/services/preset_service.rs`**：
   - 提取公共异步校验辅助函数 `validate_ui_contract_for_graph`，消除了 `create` 与 `update` 中重复的 UI 数据契约提取与静态比对逻辑；
   - 消除 `.ok().flatten()` 隐式吞异常行为，将 SQLite 查询错误通过 `.map_err(...)?` 显式向上抛出，严格遵循 C2 零回退原则。

3. **`src-tauri/src/services/blueprint_executor.rs`**：
   - 在 `BlueprintError` 中新增结构化变体 `MacroDefinitionInvalid { macro_id: String, reason: String }`；
   - 重构 DFS 环路检测，以强类型枚举 `enum DfsColor { White, Gray, Black }` 代替数字魔数（`0, 1, 2`），并穷尽匹配所有分支，禁除 `_ => {}` 通配符；
   - 在 `inline_single_macro_instance` 中，若外部引脚接入宏实例但宏内部缺少对应 `MacroInputs` 或 `MacroOutputs` 代理节点，显式抛出 `MacroDefinitionInvalid` 错误，严禁静默丢弃连线；
   - 在 `validate_blueprint_ui_contract` 中，当 `required_inventory` 为 true 且 `cfg.inventory.is_empty()` 时，显式置 `missing_inventory = true` 并输出错误描述；
   - 补充多项针对性单元测试（空背包违约、宏代理节点缺失阻断、引脚类型校验等）。

4. **`src-tauri/src/services/agent/orchestrator.rs`**：
   - 重构 `ReviewVerdict::parse`，禁除模糊启发式中文文本匹配，仅匹配结构化判定 Token（`[REJECT]`, `[REJECTED]`, `[VERDICT: REJECT]`, `[VERDICT:REJECT]`）；
   - 在 `execute_dynamic_scriptwriter_pipeline_with_hook` 中，当阶段判定为打回但未配置 `reject_target` 时，立即报错阻断并提示 `C2 严禁隐式回退`，彻底禁除此前隐式回退至 `&stages[0]` 的容缺降级路径；
   - 新增 `test_rejection_pipeline_missing_reject_target_fails` 单元测试。

5. **`src-tauri/src/services/prompt_compiler.rs`**：
   - 在 `compile_prompt` 中引入 `PresetService::validate_ui_contract_for_graph` 门禁，当蓝图或预设绑定了 UI 布局且契约违约时，物理阻断提示词编译与会话启动。

6. **`src/components/blueprint/BlueprintEditor.tsx` & `nodeLayout.ts`**：
   - 在 `BlueprintEditor.tsx` 中，当 `contractValidation` 违约时，物理禁用工具栏上的“编译预览”按钮并呈现提示 tooltip；
   - 在 `nodeLayout.ts` 中，为包含打回目标（`reject_target`）的 `scriptwriter_pipeline` 节点暴露 `out` (完成) 与 `reject` (打回) 两个执行流出口，并在 `validateConnection` 中放行 `reject` 反向连线的拓扑环路校验；
   - 为 `agent_mode_switch` 节点补齐 `out_single`、`out_director_actor` 与 `out_scriptwriter` 独立执行流引脚。

7. **`src-mobile/components/blueprint/mobileNodeLayout.ts`**：
   - 保持移动端前端完全独立隔离（C5），同步补齐 `scriptwriter_pipeline` 的 `out` / `reject` 双引脚及 `agent_mode_switch` 三向分支引脚，同步放行 `reject` 打回反向边。

## 2. 改动动机

- 满足规格说明（Spec）核心要求：
  - UI-First 数据契约必须在保存、编译预览和会话启动阶段实现全链路物理阻断；
  - 剧本流水线的审阅打回回路必须具备可视化的 `out` / `reject` 双引脚，支持向生成阶段绘制反向打回边；
  - 宏展开必须严密保证数据流与执行流完整性，缺失代理节点必须 fail-fast。
- 满足编码标准（Standards）核心要求：
  - 杜绝 Feature Envy、消除多处重复代码；
  - 消除状态机魔数，改用 Exhaustive Enum Match；
  - 杜绝任意级别的静默降级与隐式回退（C2 零回退原则）。
