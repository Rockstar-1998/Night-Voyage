## 1. 改动摘要

- **PC 蓝图编辑器 (`src/components/blueprint/BlueprintEditor.tsx`)**：
  - `createEmptyGraph()`：为空白蓝图初始化 `macros: []` 字段，确保数据模型结构完整；
  - `loadPresetDetail()` 反序列化：在加载预设 `blueprint_graph` 解析出 `parsed` 后，补全调用 `setGraph('macros', parsed.macros ?? [])`，根除加载时 `macros` 字段被遗漏遗弃的问题；
  - 空白蓝图回退：在无图重置为 `empty` 时补全 `setGraph('macros', empty.macros ?? [])`。

- **移动端蓝图入口 (`src-mobile/components/blueprint/MobilePresetBlueprintEntry.tsx`)**：
  - `createEmptyGraph()`：补充初始化 `comments: [], macros: []`；
  - `serializeBlueprintGraph()`：序列化时输出 `macros: graph.macros ?? []`，确保移动端图保存时完整持久化宏资产库；
  - `parseGraph()`：反序列化时将 `macros: parsed.macros ?? []` 注入 `graph`，消除双端行为不对齐。

- **后端自动化测试与契约回归 (`src-tauri/src/services/blueprint_executor.rs`)**：
  - 新增 `test_validate_blueprint_ui_contract_with_macro_instance` 自动化单元测试：
    1. 严密验证当蓝图包含 `MacroInstance` 但 `graph.macros` 缺失定义时，严格触发 `BlueprintMacroNotFound("macro_buy_item_rule")`（C2 零回退）；
    2. 验证当 `graph.macros` 包含宏定义时，宏内联展开正常打通并顺利通过 UI 契约静态校验。

## 2. 改动动机

- 用户在导入含宏定义与宏调用节点（如 `macro_buy_item_rule`）的高级预设（如 V3.0 宏化智能体预设）后，打开蓝图编辑器报错：
  `• 宏内联展开失败（C2 零回退）: BlueprintMacroNotFound("macro_buy_item_rule")`。
- **根本原因排查闭环**：
  在 `BlueprintEditor.tsx` 与 `MobilePresetBlueprintEntry.tsx` 中，尽管后端模型已完整声明并序列化 `macros`，但在前端加载解析 `parsed` 蓝图 JSON 时，状态管理只更新了 `nodes`、`edges`、`comments`，遗漏了 `setGraph('macros', parsed.macros ?? [])`。
  导致：
  1. 前端内存 store 中的 `graph.macros` 为空；
  2. 蓝图编辑器加载后自动触发的 UI 数据契约校验 `runContractValidation` 序列化出的 JSON 中 `macros: []`；
  3. 后端执行 `validate_blueprint_ui_contract` 时遇到 `MacroInstance("macro_buy_item_rule")`，在宏库中查找不到，触发零回退报错；
  4. 用户在编辑器中保存还会导致持久化数据中的宏定义被永久清洗抹除。
- 补全加载与保存双向通路后，彻底消除此截断。
