# 蓝图编辑器全节点类型测试补全 — MutexGate / GroupGate 集成测试

**修改类型**：debug

**日期**：2026-07-14
**作者**：assistant

## 1. 改动摘要

用户追问"所有的可操作蓝图类型你都试了吗？"，审查后发现：8 种 `NodeConfig` 变体中，`MutexGate` 和 `GroupGate` 只在 `blueprint_executor.rs` 内部单元测试中覆盖，未走 `PresetService::create → DB → load → execute` 完整链路。本次补两个集成测试补全覆盖。

### 改动文件

| 文件 | 改动 |
|------|------|
| `src-tauri/src/services/preset_service.rs` | `#[cfg(test)] mod tests` 新增 `mutex_gate_graph_json()` / `group_gate_graph_json()` 构造器 + `test_mutex_gate_full_lifecycle` / `test_group_gate_full_lifecycle` 两个集成测试；import 补 `GateOption` / `GroupGateConfig` / `MutexGateConfig` |

## 2. 改动动机

### 测试覆盖审查

`NodeConfig` 共 8 个变体：`Start` / `End` / `Prompt` / `SchemaField` / `MutexGate` / `GroupGate` / `ModeSwitch` / `SamplingParams`。

审查 `preset_service::tests`（之前的 6 个集成测试）发现：
- `Start` / `End` / `ModeSwitch` — `minimal_graph_json()` 覆盖
- `Prompt` / `SchemaField` / `SamplingParams` — `full_graph_json()` 覆盖
- `MutexGate` — **缺**
- `GroupGate` — **缺**

`blueprint_executor::tests` 内部 10 个单元测试已覆盖全部变体（含 `test_mutex_gate` / `test_group_gate_multi_select`），但那只验证执行器本身，没验证"图 JSON 序列化 → 存 DB → 读回 → 反序列化 → 执行"的完整链路。

### 解法

补两个集成测试，把 MutexGate 和 GroupGate 的图走完整 DB 生命周期：
- `test_mutex_gate_full_lifecycle`：Start → MutexGate(opt_a/opt_b) → PromptA/PromptB → End；选中 opt_a 执行，断言只产出 block_a
- `test_group_gate_full_lifecycle`：Start → GroupGate(a/b) → PromptA/PromptB → End；选中 a+b 执行，断言产出 block_a + block_b（按 options 声明顺序）
