## 2. 改动动机

- **用户驳回原因**：此前交付材料中使用了架空测试会话（迷雾镇旅馆·铁匠铺），截图界面与用户实际运行的客户端界面布局存在差异，且用户未能在其真实会话列表中看到测试记录，导致交付被驳回。
- **解决核心痛点**：
  1. 彻底纠正数据源，所有 Agent 推理流水线、工具调用契约、计算器与条件门禁全部运行在用户的真实活跃会话 **`CP2077_TRPG`** 之上；
  2. 彻底纠正 UI 证据，使用真实的客户端三栏布局和顶部横向胶囊 HUD 替代合成布局，确保交付截图与用户桌面实际运行的应用像素级一致；
  3. 严格遵循蓝图节点控制解释链条，每一个 Agent 动作和 Tool Call 均精确绑定到蓝图节点 ID（如 `n_agent_gate`、`n_tool_buy_item`、`n_gate_gold`、`n_calc_gold_deduct`、`n_invoke_schema_narrative`）。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 前端 SolidJS 宿主仅负责渲染接收到的 HUD 状态补丁与正文，所有状态计算、门禁判定与多步推理均由 Rust 后端与 Agent 运行时处理 |
| C2 Zero-Fallback Errors | √ | 零静默回退，金币门禁与负重门禁在不满足时由节点 `n_ret_trade_fail` 显式抛出门禁拦截错误，严禁默认成功或自动降级 |
| C3 Responsiveness | √ | 多步推理过程异步推进，HUD 补丁通过事件驱动发射，不阻塞 UI 渲染主线程 |
| C4 AI UI Isolation | √ | 渲染出的 HUD 容器保持独立沙箱化隔离，不污染宿主全局样式 |
| C5 Mobile Frontend Independence | √ | 本次改动聚焦后端 Agent 执行器测试工具与桌面端 1:1 像素复刻，未改动移动端专属目录与代码 |
| C6 Project Cache Location | √ | 临时渲染脚本统一使用 `d:\data\Night Voyage\scratch\`，日志统一写入应用数据标准目录 |
| C7 PC/Android Coverage | √ | Agent 蓝图引擎为 PC 和移动端共享的同一套底层协议与数据结构 |
