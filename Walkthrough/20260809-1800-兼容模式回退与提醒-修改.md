# [修改] 兼容模式回退：结构化 JSON 解析失败时包一层并显式提醒

## 1. 改动摘要

针对前序回归（默认预设结构化 JSON 输出散文 → 空响应）的**兜底**方案。用户确认采用：
「代码包一层，并显式在下方提醒开启了兼容模式」——零额外 LLM 调用，失败时整段原文进
`narrative` 字段，其余 schema 字段填默认值，保证落库内容非空，且前端可见地提示。

### 后端（Rust）

- `src-tauri/src/network/mod.rs`
  - `RoomMessage` 枚举新增 `CompatibilityMode { conversation_id, round_id, message_id, reason }` 变体。
  - 新增 `CompatibilityModePayload`（camelCase）及 `event_name()` → `"room:compatibility_mode"`、
    `event_payload()` 映射。
- `src-tauri/src/services/chat_service.rs`
  - 新增 `build_compatibility_fallback_json(raw_prose, schema_json) -> String`：
    解析 schema `properties`，按类型填默认值（string→""、number/integer→0、boolean→false、
    array→[]、object→{}），并把 `narrative = raw_prose` 整体写入，返回合法 JSON 字符串。
  - 新增 `emit_compatibility_mode_event(...)`：主机经 `llm-stream-event`
    （event_kind=`compatibility_mode`）直推，联机房客经 `room:compatibility_mode` 广播。
    广播沿用既有 `tauri::async_runtime::spawn` + `host_server.broadcast_message` 模式。
- `src-tauri/src/services/stream_processor.rs`
  - `stream_openai_text_response` 与 `stream_anthropic_text_response` 各新增
    `let mut raw_prose = String::new();` 与 `let provider_kind: &str = "...";`。
  - 新增参数 `schema_json: Option<&str>`（dispatch 处传入
    `compiled_prompt.params.structured_output_schema.as_deref()`）。
  - 结构化分支（OpenAI delta / Anthropic `text_delta`）在喂给解析器时**同时**累积原始
    delta 到 `raw_prose`。
  - 共 **4 个** `parser.finish()` 的 `Err` 分支（OpenAI `[DONE]` 与 end-of-loop；Anthropic
    `message_stop` 与 end-of-loop）：原仅 `dbg_eprintln!` 的兜底改为——若 `raw_prose` 非空，
    构建回退 JSON 并赋值 `structured_json_content`，调用 `emit_compatibility_mode_event` 显式
    广播；若 `raw_prose` 也为空则维持原空响应错误（确有真·空响应时不应伪造）。

### 前端（PC，SolidJS）

- `src/lib/backend/types.ts`：新增 `RoomCompatibilityModeEvent`。
- `src/lib/backend/rooms.ts`：新增 `listenRoomCompatibilityMode`（房客监听 `room:compatibility_mode`）。
- `src/components/MessageItem.tsx`：`ChatMessage` 增加 `compatibilityMode?: boolean`；消息头部
  增加「兼容模式」徽标；消息正文下方增加「兼容模式已开启」提示横幅（含 narrative 说明）。
- `src/App.tsx`：
  - 主机 `llm-stream-event` 处理器 `switch` 新增 `case 'compatibility_mode'` → 置
    `compatibilityMode: true`。
  - 注册 `listenRoomCompatibilityMode`（房客路径，`if (!activeRoomClientSession()) return;` 守卫），
    同样置 `compatibilityMode: true`，并在 `onCleanup` 中加入其 unlisten。

## 2. 改动动机（为什么改）

前序 directive 修复（系统提示末尾追加 JSON 指令）能显著引导模型输出 JSON，但**无法 100%
保证**：当 proxy 仍忽略 `response_format` 且模型吐散文时，结构化解析器 `finish()` 失败、
`full_content` 为空 → 仍触发「LLM 响应为空」。

用户明确要求：在此类格式失败场景**不要静默丢弃**，而是「包一层」把原文保住，并**显式提醒**
用户已启用兼容模式（C2 零回退原则：失败必须可见、可提示，不得默认成功/悄悄降级）。本方案
零额外 LLM 调用，仅做客户端兜底包装 + 可见通知。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 前端仅渲染徽标/横幅与事件转发，业务逻辑全在后端 |
| C2 Zero-Fallback Errors | √ | 非静默：解析失败仍显式广播 `compatibility_mode` 通知；`raw_prose` 也为空时仍返回「LLM 响应为空」错误，不伪造成功 |
| C3 Responsiveness | √ | 仅字符串构造与一次事件广播，无阻塞；广播走既有 spawn 异步通道 |
| C4 AI UI Isolation | √ | 不涉及 AI 沙箱 UI |
| C5 Mobile Frontend Independence | √ | 后端共享；PC 前端独立改动，未与移动端互引 |
| C6 Project Cache Location | √ | 无新增缓存写入 |
| C7 PC/Android Coverage | △ | **后端 + PC 主机/房客路径全覆盖**；但 `src-mobile` 当前**无聊天消息 UI**（仅占位「移动端单聊与群聊发消息界面正在开发中」），横幅无法在移动端渲染。后端 `room:compatibility_mode` 广播已就位，待移动端聊天 UI 落地即可消费。见第 5 节残留风险 |

## 5. 已知限制 / 后续待办

- **移动端聊天 UI 缺失**：`src-mobile` 尚未实现对话视图（含消息渲染与 `llm-stream-event` 监听），
  因此兼容模式横幅只能在 PC 端呈现。这是 C7 的**剩余平台风险**，非本次新增缺陷——移动端聊天
  框架本身未落地。后端 `room:compatibility_mode` 广播已就绪，移动端聊天 UI 接入时直接 `listen`
  即可，无需再改后端。
- **房客散文同步**：兼容模式下主机把原文包进 `narrative` 并落库，但房客端在结构化失败场景下
  原本就收不到逐字段增量（解析器未产出字段），房客仅收到 `room:compatibility_mode` 通知与最终
  DB 内容快照。房客的可见散文依赖其自身重新拉取消息；属预存的房客同步细节，不在本任务范围。
- **narrative 字段语义**：与 directive 修复一致，`narrative` 为 schema 外额外字段（strict:false）。
  若要让其参与 db_mapping / 前端折叠，需在预设蓝图补 `narrative` schema_field 节点。
