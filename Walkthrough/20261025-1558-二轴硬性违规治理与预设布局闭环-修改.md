# 20261025-1558-二轴硬性违规治理与预设布局闭环-修改

## 1. 改动摘要

针对两轴审查（Standards Reviewer 与 Spec Reviewer）汇报的三项硬性违规与两项规格/设计异味，以及预设导入导出与 UI 布局契约闭环进行了彻底治理与重构：

1. **`src-tauri/src/services/preset_service.rs`**：
   - **C2 零静默回退治理**：在 `resolve_layout_data_interface_for_graph` 中彻底移除 `if preset_id.is_some()` 遗漏判定；当蓝图图节点明确引用了 `layout_id` 但数据库与暂存定义中均不存在时，无条件返回显式错误 `Err("引用了不存在或加载失败的 UI 布局 `{layout_id}`")`。
   - **预设布局资产闭环**：定义 `PortablePresetLayout` 结构体，并将 `layouts: Vec<PortablePresetLayout>` 加入 `PortablePresetFile`。在 `export` 中导出预设关联的 UI 布局，在 `import` 中通过新引入的 `create_with_layouts` 在同一 ACID 事务内持久化关联布局，并提前基于暂存布局校验 UI 数据契约。
2. **`src-tauri/src/services/agent/orchestrator.rs`**：
   - **C2 零静默回退治理**：重构 `ReviewVerdict::parse`，返回 `Result<ReviewVerdict, String>`，彻底消除将未识别/空白输出默认静默回退为 `Approved` 的漏洞；明确要求输出包含有效的判定标记（`[APPROVE]` / `[PASS]` 或 `[REJECT]` / `[打回]`）。
   - **未配置目标拦截**：若非审阅阶段（`reject_target.is_none()`）输出了打回标记，立刻硬错阻断（C2 严禁隐式回退），禁止静默吞没。
   - **数据泥团治理**：将审阅打回钩子签名从散落基本类型 `FnMut(&str, u32, u32, &str)` 重构为结构化参数 `FnMut(&RejectionLoopState)`。
   - **工具定义完整性**：接入 `resolve_known_capability_tool_definition` 并由 `ToolAccessPolicy` 调度。
3. **`src-tauri/src/models/blueprint.rs`**：
   - **类型驱动设计**：定义 `pub enum ToolAccessPolicy { All, Whitelist(Vec<String>) }`，重构 `AgentToolPermissions`，消除布尔分支驱动的 `allow_all: bool`，由类型状态机决定工具权限过滤。
4. **`src-tauri/src/services/action_bridge.rs`**：
   - **契约真实性注入**：实现 `resolve_action_bridge_tool_definition` 与 `resolve_known_capability_tool_definition`，为 ActionBridge 命令（如 `query_session_state`、`get_conversation_detail`）和 MCP 工具注入真实参数 JSON Schema 与描述，杜绝 `{}` 空参数占位破坏模型调用契约。
5. **`src-tauri/src/services/agent/director_actor.rs`**：
   - 在分镜导演工具解析中接入 `resolve_known_capability_tool_definition` 与 `perms.filter_tool_definitions`，保证多智能体角色工具集具备真实 Schema。
6. **`src-tauri/src/commands/schema.rs` 与 `src-tauri/src/commands/blueprint.rs`**：
   - 在 `commands/schema.rs` 提炼可复用查询函数 `query_preset_schemas`，消除了 `preview_blueprint_with_session` 中直接书写 raw SQL 查询预设 Schema 的重复逻辑。
7. **`测试预设/Night Voyage 全能核心预设 V3.0 (宏化智能体与契约驱动版).nvpreset.json`**：
   - 增加规范的 `"layouts"` 数组，包含 `rpg_hud_v3` 官方 HUD 布局定义，控件精准绑定 `stats.credits` (min 0)、`stats.sanity` (min 0, max 100)、`stats.hp` (min 0, max 100)、`stats.mp` (min 0, max 50)、`flags.location`、`flags.weather` 及 `inventory`，与蓝图初始状态完全对齐。

## 2. 改动动机

- 消除审查指出的 Standards 维度硬性违规：
  - `ReviewVerdict::parse` 原先默认 `Approved`，当模型输出格式不符或崩溃时造成假通过；
  - `resolve_layout_data_interface_for_graph` 在 `preset_id` 为 None 时对不存在的 `layout_id` 吞异常返回 `Ok(None)`；
  - `AgentToolPermissions` 存在布尔标志位与列表共存的设计缺陷。
- 补齐官方 V3.0 预设在全新环境导入时的 UI 布局闭环，防止外部环境导入后因数据库缺少对应 HUD 布局而报错或跳过校验。
- 消除空 JSON Schema (`{}`) 工具注入导致的智能体参数校验失效问题。
