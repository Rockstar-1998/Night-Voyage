## 2. 改动动机

在分支代码复审中，两个维度审查发现了如下不符或架构隐患：
1. **C3 响应性隐患**：移动端宏删除对话框调用了浏览器同步阻塞的 `window.confirm()`，违反 UI 线程永不假死原则；
2. **C5 移动端独立性隐患**：移动端 8 个蓝图组件直接跨目录引用 `src/lib/blueprint/types`，违反双端零代码耦合硬约束；
3. **Spec 契约误判**：蓝图执行器的 UI 契约校验在 `required_inventory = true` 时硬性要求 `!cfg.inventory.is_empty()`，导致正常空背包初始状态被判定为契约失败；
4. **C11 硬编码隐患**：双端编辑器内置了固定 4 项 ActionBridge 原语列表，未走后端真实数据库设置白名单接口；
5. **架构分层清晰度**：`blueprint.rs` 命令处理器直接调用同级 `commands::ui_layout` 和 `commands::schema` 并克隆 `state`，存在 Feature Envy 与不必要开销。
