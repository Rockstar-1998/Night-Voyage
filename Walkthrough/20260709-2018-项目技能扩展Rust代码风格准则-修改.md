## 改动摘要

### 新增章节结构

#### 1. Composition Over Inheritance（组合优于继承）
- 复用用结构体组合（newtype / 字段嵌入 / 方法委托），禁 `trait Sub: Super` 继承链与运行时 downcast 模拟 OO 继承。
- trait 保持小而独立可自由组合；变体行为用独立类型 + 公共 trait，不写 `enum Kind + match + flag: bool`。
- 公共扩展点用 `trait` + 泛型 `where T: Trait` 约束。

#### 2. Type-Driven Design（类型驱动、最小分支判断）
- 无效状态不可表达；`if let Some(x) = y { x.foo() } else { alt.foo() }` 改 trait 调度。
- 禁 `enabled: bool` / `is_admin: bool` / `force: bool` / `skip_*` / `.silent` / `.dry_run` 这类把类型决策推迟到运行期的标志位。
- 用 `unwrap_or` / `and_then` / `map` / `filter_map` 组合子替代命令式 if-let 链。
- 错误处理用 `?` + `thiserror` + `From`，禁层层 `match err` 改写错误。
- 保留必要的穷尽 `match`，禁 `_ =>` 吞未知变体、禁 `..` 跳过字段。

#### 3. Idiomatic Rust Conventions（官方风格细节）
- 公共 API 遵循 Rust API Guidelines、命名遵循 RFC 430。
- 参数优先 `&str` / `&[T]` / `Cow<'_, T>`，复杂构造用 builder 模式，转换用 `From` / `TryFrom`。
- 迭代器链与闭包优先于显式 `for`；`unsafe` / `transmute` / 裸指针 / 非数值 `as` 必须给理由。
- 公开导出项必须有 `#[doc]`；Cargo 依赖优先 workspace 共享版本。

#### 4. Self-Check Before Submission（提交前自查）
- 关键词扫描：`if let`、多 arm `match`、`.is_some` / `.is_none` / `.is_`、`.enabled` / `.disabled` / `.force` / `.skip_` / `.silent` / `.dry_run`、非数值 `as `。每条命中必须能回答"为什么这里必须用分支"。
- 反模式扫描：禁 `match` 内 `_ =>` 吞错、禁 `trait Sub: Super`、禁 `disabled: bool` 配 `state: enum`、禁 `.ok()` 吞错（与 C2 交叉）、禁 `Arc<Mutex<GlobalRegistry>>` 当多态分发器。

## 改动动机

用户要求「以后代码都使用组合而非继承，尽量减少分支判断，最大程度符合 Rust 官方推荐编程风格」。现有 night-voyage-guardrails 技能只有 C1–C7 七条约束（C1 前端只渲染、C2 零回退、C3 响应性、C4 AI UI 隔离、C5 移动端独立、C6 缓存路径、C7 双端覆盖），没有专门的 Rust 代码风格章节，AGENTS.md 的 Code Style 段也只列了 4 条散点。本次新增章节把这三条原则以可执行、可审计的方式落到所有未来 Rust 任务上，避免每次评审时再口头重申。

1. **既有代码可能违反新规则**：本次只立规则，不强制重写存量 Rust 代码。后续如做大规模 Rust 重构，应按新规则逐文件过审；如发现存量严重违反（如核心流程里有 `disabled: bool` + `state: enum` 反模式），需要时走 spec 流程单独处理。
