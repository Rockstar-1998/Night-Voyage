## 改动动机

spec 第五阶段要求移动端独立实现蓝图编辑器（C5），让用户在移动端也能以节点图方式编辑 preset。Task 7（类型 + 迁移）已完成共享层，Task 8（PC 画布）已完成参考实现。本任务在此基础上为移动端独立实现画布交互、配置面板、集成入口，针对触摸交互做专门优化（长按防误触、双指捏合、底部抽屉）。

## 关键设计决策

### 决策 1：独立实现 `mobileNodeLayout.ts`（不 import PC `nodeLayout`）

任务描述 SubTask 13.1 明确要求"不 import PC 端的 BlueprintCanvas / nodeLayout / 节点组件"。因此移动端在 `src-mobile/components/blueprint/mobileNodeLayout.ts` 独立实现布局/校验纯函数。函数签名与 PC 端对齐（spec 共享层），但实现完全独立——这是 C5 双端独立的硬约束，避免移动端被 PC 端的后续重构牵连。

### 决策 2：仅复用 spec 共享层（types.ts + migration.ts）

SubTask 13.2 允许通过相对路径复用 `src/lib/blueprint/types.ts` 和 `migration.ts`。这两个文件是 spec 定义的共享层（类型定义 + 纯迁移逻辑，无 SolidJS 依赖），移动端从 `src-mobile/components/blueprint/` 用三级相对路径 `../../../src/lib/blueprint/types` 引用。

### 决策 3：触摸交互状态机（idle / pending_node / pending_port / pan / node_drag / connect / pinch）

移动端不能用 PC 端的"mousedown 即开始拖拽"模型（会误触）。本实现用判别联合 `InteractionState`：
- **idle** → 指针落下根据命中目标进入 pending_* 或 pan
- **pending_node / pending_port** → 启动 500ms 长按计时器；位移超 `LONG_PRESS_MOVE_TOLERANCE`（10px）取消长按转为 pan；长按触发进入 node_drag / connect；松手未触发长按视为点击（选中节点）
- **pan / node_drag / connect** → 单指活跃交互；第二指出现由全局捕获处理器进入 pinch
- **pinch** → 双指活跃；一指松开转为单指 pan

### 决策 4：长按 500ms 进入拖拽/连线模式（防误触）

PC 端 mousedown 立即开始拖拽，移动端这样做会导致滚屏时误拖节点。本实现要求长按 500ms 才进入 node_drag / connect 模式，期间位移超 10px 取消长按（转为平移）。长按触发时 `navigator.vibrate(15)` 触感反馈。

### 决策 5：双指捏合缩放（pointerCache + 中点锚点）

移动端无滚轮，缩放用双指捏合。实现要点：
- `pointerCache: Map<number, Position>` 在捕获阶段 `pointermove` 持续更新每指位置
- 第二指落下时（`pointerCache.size === 2`）进入 pinch 状态，记录起始距离 / 中点 / zoom / offset
- pinch move 时用 `pointerCache` 拿两指最新位置算新距离和中点
- 缩放保持双指中点在屏幕上的位置不变（zoom-to-midpoint）：起始中点对应的图坐标在新 zoom 下仍投影到当前中点屏幕位置

### 决策 6：捕获阶段事件监听（onMount + addEventListener）

SolidJS 的 SVG 类型不支持 `onPointerDownCapture` 等 capture-phase JSX props。本实现用 `onMount` + `svgEl.addEventListener('pointerdown', handler, { capture: true })` + `onCleanup` 移除，确保节点/端口上的 `stopPropagation` 不影响 `pointerCache` 更新和捏合检测。

### 决策 7：底部抽屉配置面板（拖动调高度 + 档位吸附）

移动端屏幕窄，配置面板用底部抽屉（非 PC 端侧栏）。抽屉头部可上下拖动调整高度，松手吸附到最近档位（40% / 65% / 90% vh）。档位快捷按钮直接跳档。抽屉用 `transform: translateY()` 平移（合成器友好，C3），表单区原生 `overflow-y-auto` 滚动。

### 决策 8：草稿/提交模型（draftConfig vs graph）

配置面板实时编辑 `draftConfig`（每次按键回调父级），Save 时提交到 `graph`，Cancel 时丢弃草稿。这让"取消"能真正回滚未保存的编辑，避免误改直接污染 graph。

### 决策 9：后端持久化诚实提示（C2 零回退）

当前 `PresetSummary` / `CreatePresetPayload` 尚未含 `blueprintGraph` 字段（待 Task 12 后端重构）。保存回调先以 toast 形式展示生成的蓝图已保存到内存，并诚实提示"后端 blueprint_graph 持久化待 Task 12 接入"——不静默回退、不假装持久化成功。

### 决策 10：独立 `tsconfig.mobile.json`

原 `tsconfig.json` 只 `include: ["src"]`，不含 `src-mobile`。新建 `tsconfig.mobile.json`，compilerOptions mirror PC 配置（strict / noUnusedLocals / noUnusedParameters / noFallthroughCasesInSwitch），`include` 改为 `["src-mobile"]`。运行 `npx tsc --noEmit -p tsconfig.mobile.json` 验证移动端类型安全。

| 约束 | 合规 | 说明 |
|------|------|------|

| C6 Project Cache Location | √ | 不涉及缓存写入 |
| C7 PC/Android Coverage | √ | 本任务是移动端（Task 13）；PC 端画布在 Task 8 已完成。双端独立实现，共享 spec 类型层 |
