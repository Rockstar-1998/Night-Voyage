## 改动动机

当前 preset 系统的三个结构性问题：
1. **编辑分散**：blocks 表单、schema 编辑器、semanticGroups 配置、采样参数面板各自独立
2. **后端硬编码模式分支**：compile_prompt 里三模式分支是硬编码 if/else
3. **运行时不可控**：后端不按 semanticGroups 裁剪 schema，PlotSummary/世界变量持久化分散

蓝图编辑器作为 preset 的唯一编辑入口，从 Start 开始连线，用节点图表达完整的 prompt 编译流程。后端运行时执行蓝图，产出 compile_prompt 所需的全部数据。

## 关键设计决策

1. **NodeConfig 内部标签 enum**：`#[serde(tag="type", content="config")]` 让单枚举同时承载类型判别 + 配置，从结构上消除"NodeType 与 NodeConfig 变体错配"的无效状态
2. **字段命名 snake_case**：图存储类型与 spec JSON 完全一致，避免转换层
3. **运行时图执行器**：后端 DFS 遍历节点图，支持 ModeSwitch 三模式分支 + Gate 单选/多选
4. **db_mapping 机制**：SchemaField 节点的 db_mapping 字段将 AI 输出的 schema 字段映射到 message_rounds 的 db 列，解决 3 处 TODO
5. **双前端独立**：PC 端 `src/components/blueprint/` + 移动端 `src-mobile/components/blueprint/` 零 UI 代码耦合，共享 `src/lib/blueprint/types.ts` + `migration.ts`
6. **旧 preset 自动迁移**：前端加载时检测无 blueprint_graph 的旧 preset，调用 migrateToBlueprint 自动迁移并持久化

## 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 图执行器在后端，前端只编辑+提交图 |
| C2 Zero-Fallback Errors | √ | 图执行失败显式报错；blueprint_graph 缺失显式报错（不 fallback）；sub_schema 解析失败显式报错 |
| C3 Responsiveness | √ | 图执行器异步执行；前端细粒度响应式；触摸交互优化 |
| C4 AI UI Isolation | √ | 蓝图是宿主 UI，不涉及 AI 动态 UI 层 |
| C5 Mobile Frontend Independence | √ | PC/移动端独立实现，仅共享 types.ts/migration.ts（spec 允许的共享层） |
| C6 Project Cache Location | √ | 无缓存写入 |
| C7 PC/Android Coverage | √ | 双端支持，后端共享 |
