# 延迟自动重试至用户触发 - 前端改造

## 改动摘要

### 涉及文件

1. `src/lib/backend/types.ts`
2. `src/App.tsx`

### 改动详情

#### Task 4: 前端类型定义扩展

- **SubTask 4.1**：`StreamRetryEvent` 接口（约行 601-608）新增字段 `autoRetryEnabled: boolean`。
- **SubTask 4.2**：`RoomStreamRetryEvent` 接口（约行 927-934）新增字段 `autoRetryEnabled: boolean`。

#### Task 5: retryNotice 信号扩展 + 事件处理分流 + UI 改造

- **SubTask 5.1**：`retryNotice` 信号类型从 `{ error: string; attemptCount: number }` 扩展为 `{ error: string; attemptCount: number; autoRetryEnabled: boolean; roundId: number }`，保留 `retryNoticeTimer` 变量不变。
- **SubTask 5.2**：`listenStreamRetry` 回调改为根据 `payload.autoRetryEnabled` 分流：
  - `autoRetryEnabled === true`：保持流式状态（`isStreaming: true`），设置 `replyStatus('connecting')` 和 `abortingRoundId`。
  - `autoRetryEnabled === false`：停止流式状态（`isStreaming: false`，写入 `error`），设置 `replyStatus('idle')`，清除 `abortingRoundId`。
  - 移除原来的 4 秒自动消失定时器逻辑。
- **SubTask 5.3**：`listenRoomStreamRetry` 回调同样按 `autoRetryEnabled` 分流，逻辑与 5.2 一致。
- **SubTask 5.4**：`retryNotice` UI 改造：
  - 标题根据 `autoRetryEnabled` 显示"自动重试中"或"发送失败"。
  - `autoRetryEnabled === false` 时显示"自动重试"按钮，点击调用 `handleRetryFailed('', notice().roundId)`。
  - `autoRetryEnabled === true` 时显示"停止"按钮，点击调用 `handleAbortReply()`。
  - 移除原来的 `pointer-events: 'none'`，使按钮可点击。
- **SubTask 5.5**：在流式结束/错误回调中添加 `setRetryNotice(null)`：
  - `message_stop` case（`llm-stream-event` 的流式结束分支）
  - `listenStreamError` 回调（`llm-stream-error`）
  - `listenRoomStreamEnd` 回调（`room-stream_end`）
- **SubTask 5.6**：`handleSend` 函数开头添加 `setRetryNotice(null)`。
- **SubTask 5.7**：切换会话的 `createEffect`（依赖 `selectedConversationId()`）开头添加 `setRetryNotice(null)`。

## 改动动机

原先前端在收到 `llm-stream-retry` 事件后无条件保持流式状态并自动重试，仅弹窗 4 秒后自动消失。改造后：

- 首次失败（`autoRetryEnabled === false`）时停止流式状态，向用户展示失败原因，等待用户点击"自动重试"按钮才触发重试，将重试决策权交还用户。
- 后端判定可自动重试（`autoRetryEnabled === true`）时保持原有自动重试行为，并提供"停止"按钮让用户可中断。
- 在流式结束、流式错误、发送新消息、切换会话等场景主动清除 `retryNotice`，避免残留通知误导用户。
