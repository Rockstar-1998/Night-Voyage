# 幽灵房间修复与端口冲突检测

## 1. 改动摘要

| 文件 | 模块/函数 | 改动内容 |
|------|-----------|----------|
| `src-tauri/src/utils/port.rs` | 新增 `get_port_occupant` / `query_port_occupant_windows` | 端口占用进程名查询工具，通过 `netstat -ano` + `tasklist` 获取占用端口的进程名 |
| `src-tauri/src/utils.rs` | 模块声明 | 新增 `pub mod port;` 声明子模块 |
| `src-tauri/src/network/mod.rs` | `RoomServer::start` | 端口 `TcpListener::bind` 失败时，调用 `get_port_occupant` 查询占用程序名，返回包含占用程序名的错误信息 |
| `src-tauri/src/commands/rooms.rs` | `room_create` | INSERT rooms 记录前先关闭可能仍在运行的旧 server（`host_server.take()` + `shutdown()`），避免端口被旧实例占用 |
| `src-tauri/src/commands/rooms.rs` | `room_open` | 移除"已有房间在运行，请先关闭"的硬阻塞检查，改为先关闭旧 server 再继续，消除幽灵房间导致的死锁 |
| `src-tauri/src/commands/conversations.rs` | `conversations_delete` | 删除 rooms 记录前，检查运行中的 host_server 是否属于该 conversation，若是则先 `shutdown()`，防止删除后端口仍被占用 |

## 2. 改动动机

用户在删除联机房间后创建新联机房间时遇到"已有房间在运行，请先关闭"错误。

根因：`conversations_delete` 删除了 rooms 表记录但未关闭关联的 RoomServer（`host_server` 未清理），旧 server 仍占用端口。当用户尝试创建/打开新房间时，`room_open` 检查到 `host_server.is_some()` 即报错阻塞，形成幽灵房间死锁。

本次修复从三个入口消除幽灵房间：
1. `room_create` / `room_open` 创建新房间前主动关闭旧 server（不再硬阻塞报错）。
2. `conversations_delete` 删除会话时同步关闭关联的 host_server。
3. `RoomServer::start` 端口绑定失败时查询并告知用户占用程序名，便于排查。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 本次改动全部在后端 Rust 代码，前端无变更 |
| C2 Zero-Fallback Errors | √ | 端口绑定失败仍返回 `Err`，不静默回退；shutdown 失败由现有 shutdown 实现内部处理（发送 channel 信号），不吞异常 |
| C3 Responsiveness | √ | `get_port_occupant` 使用 `tokio::task::spawn_blocking` 包裹阻塞式 `netstat`/`tasklist` 进程调用，避免卡住异步运行时；`conversations_delete` 中先释放 `host_server` 锁再执行 DB 查询，避免持锁阻塞 |
| C4 AI UI Isolation | √ | 不涉及 AI 动态 UI |
| C5 Mobile Frontend Independence | √ | 不涉及前端代码 |
| C6 Project Cache Location | √ | 不涉及缓存写入 |
| C7 PC/Android Coverage | √ | 后端改动对 PC/Android 双端共享同一 Rust 核心，`netstat`/`tasklist` 路径用 `#[cfg(target_os = "windows")]` 隔离，非 Windows 平台返回 `None`（当前仅 Windows 桌面构建） |

### 验收方式

- 编译通过：`cargo build` exit code 0。
- 修复后 `conversations_delete` 删除带房间的会话时，关联的 RoomServer 会被 `shutdown()`，端口释放。
- 修复后 `room_open` 不再因 `host_server.is_some()` 硬阻塞，改为自动关闭旧 server 后继续。
- 修复后 `room_create` 创建新房间前主动关闭旧 server。
- 端口绑定失败时错误信息包含占用程序名（Windows 平台）。

### 预期效果

- 删除联机房间会话后再创建/打开新联机房间不再报"已有房间在运行"。
- 端口被占用时错误信息提示具体占用程序名。

## 5. 已知限制或后续待办

- `get_port_occupant` 仅实现 Windows 平台（`netstat`/`tasklist`），非 Windows 平台返回 `None`，错误信息退化为"端口已被占用，请更换端口"。若后续需要 Linux/macOS 支持，可补充 `lsof`/`ss` 查询实现。
- `conversations_delete` 中 host_server 检查与 shutdown 之间存在理论 TOCTOU 窗口（释放锁后重新获取），但 `take()` 返回 `None` 时安全跳过，不会重复 shutdown。
- 未修改前端调用逻辑，前端 `room_open` 失败重试行为不变。
