# Walkthrough: 蓝图预设强制注入「叙事正文」基线（修改）

## 改动摘要
- **src-tauri/src/models/blueprint.rs**：`FieldDisplayConfig` 新增 `body: bool`（默认 false），用于标记「叙事正文（消息主体）」字段。
- **src-tauri/src/services/blueprint_executor.rs**：新增 `inject_core_schema_baseline`，在 `execute_blueprint` 遍历结束后，若蓝图未显式定义 `thinking` / `text` 字段则以「组合」方式注入（`text` 同时写入 `display_config.body=true` 并加入 `required`）。仅字段缺失时插入，不覆盖作者显式定义。
- **src-tauri/src/services/prompt_compiler.rs**：`display_config` 序列化为 `structured_output_display` 时新增 `body` 字段，确保标记下发到前端。
- **src/lib/messageFormatter.ts**：`StructuredResponseNode.displayConfig` 类型增加 `body?: boolean`。
- **src/components/MessageFormatRenderer.tsx**：`StructuredResponseRenderer` 对 `body` 字段渲染为带强调边线的「消息主体」块，与 `thinking` 折叠区在视觉上明确区分（满足「不同 schema 类型不得共用同一种渲染」）。
- **src-mobile/lib/structured.ts** 与 **src-mobile/components/MobileStructuredRenderer.tsx**：移动端同步支持 `body` 标记与渲染（C7 双端覆盖）。

## 改动动机
用户反馈「预设不可能没有正文」，线索：NVIDIA 预设的实际 Schema 只有 `thinking/status_bar/todo_list/options`，没有正文节点。根因：默认非蓝图 Schema（`provider_adapter.rs`）本就含 `thinking`+`text`；蓝图模式从空 `properties` 起步、只并入可达的 SchemaField 节点，导致蓝图作者必须手动记得加正文，否则模型只能把整段叙事塞进 `thinking`（用户截图所见）。这违反「预设必须有正文」的隐含契约，亦偏离 AGENTS.md「组合优于继承」——公共基线应被注入而非每个节点重复声明。

## 约束合规审计表
| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 仅前端渲染调整，后端只注入元数据 |
| C2 Zero-Fallback Errors | √ | 注入仅当字段缺失，不覆盖已有定义 |
| C3 Stock 约定 | N/A | 非金融工具 |
| C5 移动端独立 | √ | 移动端本地副本 `structured.ts` 独立同步，未复用 PC 组件 |
| C7 双端覆盖 | √ | PC + 移动端均支持 body 渲染 |
| 组合优于继承 | √ | 基线字段以组合方式叠加，未引入 trait/继承；类型驱动的穷尽 `kind` 分支渲染 |
