# 20260915-1902-Schema系统新增常驻会话与保留层数机制-修改

## 1. 改动摘要

- **受影响文件**：[`plans/agent-system-architecture-plan.md`](file:///d:/data/Night%20Voyage/plans/agent-system-architecture-plan.md)
- **改动内容**：
  1. **Schema 系统新增两大全局核心功能控制（第 3 节）**：
     - **功能一：【📌 常驻于会话中】（`persistent_in_session: bool`）**：
       - 未开启：作为传统内联卡片附着在每条消息气泡底部；
       - 开启后：解锁与 UI 模板编辑器的自由排版绑定，允许创作者随意指定呈现位置（PC 端右侧仪表盘 `RightDock`、顶部吸顶栏 `TopSticky`、自由浮动画中画 `FloatingHUD`，或移动端吸顶抽屉 `TopHUD` 等）；`stream_processor` 流式解析 Schema 字段后通过 `session:hud_state_patch` 增量驱动常驻视口原地刷新，始终显示最新数据，彻底消灭历史消息底部的垃圾卡片堆叠；
     - **功能二：【⏳ 限制保留层数】（`retention_depth: Option<u32>`）**：
       - 未开启：全量注入历史 Schema 数据；
       - 开启后：强制要求输入正整数 $N \ge 1$（非法输入即刻阻断），`prompt_compiler.rs` 在装配 Prompt 上下文时执行**倒序滑动裁剪（Reverse Sliding Pruner）**，从最新层倒数仅保留最近 $N$ 层的历史 Schema 状态注入 Prompt，超过 $N$ 层的更早历史数据直接硬丢弃（Hard Pruning），彻底根除传统模式在长对话下历史 Schema 线性膨胀与 Token 耗尽问题；
  2. **数据契约定义固化**：
     - `SchemaDefinition` 增加 `persistent_in_session: bool` 与 `retention_depth: Option<u32>`；
  3. **系统联动与实操指南对齐（第 1.2、4.3、7.2、8.1、9.1、10 节）**：
     - 更新传统模式状态流转表格、常驻 HUD 驱动链路、上下文编译器插槽、创作者预设搭建实操指南以及 Milestone 1 验收标准。

## 2. 改动动机

响应用户指令：“修改文档，现有SCHEMA系统新增两个功能：1.常驻于会话中按钮：启动后就会像我们之前说好的那样，允许UI编辑器随意放置位置，始终显示最新数据。2.保留层数按钮：启动后需要输入正整数，从最新层倒数层级保留在上下文中，过远的直接丢弃。”
使 Schema 体系在兼顾传统单次生成模式的同时，具备强大的常驻表现层自由布局能力，以及对上下文膨胀的确定性硬约束防护能力。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 保留层数倒序裁剪算法与 HUD 补丁广播全在 Rust 后端执行，前端纯渲染 |
| C2 Zero-Fallback Errors | √ | 保留层数严格要求正整数 $N \ge 1$，输入非法数值时实时显式阻断报错，严禁静默 fallback |
| C3 Responsiveness | √ | 保留层数硬丢弃阻断了 Prompt 无效膨胀，大幅降低推理首字延迟与打字机卡顿 |
| C4 AI UI Isolation | √ | 常驻 HUD 容器强制在 Shadow DOM 内部隔离运行，自定义 CSS 绝不污染 SolidJS 宿主 |
| C5 Mobile Frontend Independence | √ | PC 侧边/吸顶与移动端吸顶抽屉保持完全独立实现，零共享 UI 代码 |
| C6 Project Cache Location | √ | Schema 存入 SQLite 数据库表，零零散磁盘碎文件产生 |
| C7 PC/Android Coverage | √ | 两大功能在 PC 与移动端全量覆盖，双端共享相同后端数据契约与接口 |
