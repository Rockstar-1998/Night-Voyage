| `src-tauri/src/lib.rs` | 修改 | `generate_handler!` 宏注册 `room_update_guest_character` |

### 核心改动点

- **RoomMessage 5 个新变体**（`network/mod.rs`）：
  - `MessageEdited { conversation_id, message_id, content }` → event `"room:message_edited"`
  - `MessageDeleted { conversation_id, message_id, round_deleted }` → event `"room:message_deleted"`
  - `RewoundToRound { conversation_id, target_round_id }` → event `"room:rewound_to_round"`
  - `ContextWindowChanged { conversation_id, context_window_size }` → event `"room:context_window_changed"`
  - `GuestCharacterUpdated { conversation_id, member_id, character: GuestCharacterCardPayload }` → event `"room:guest_character_updated"`
- **广播模式统一**：所有新增广播均使用 `tauri::async_runtime::spawn` 异步执行，不阻塞调用方；`host_server` 为 None（单人模式）时静默跳过；广播失败不影响房主操作（best-effort）
- **`broadcast_room_message` 辅助函数**：封装 spawn + lock host_server + broadcast 逻辑，被 `update_message_content` / `delete_message` / `rewind_to_round` 三处复用
- **`delete_message` 的 `round_deleted` 标志**：追踪是否调用了 `delete_round_completely`（3 处调用点均置 true），作为广播 payload 字段告知房客是否整轮删除——此为输出数据而非行为分支标志

## 2. 改动动机

多人模式下房主的 5 项操作（编辑消息、删除消息、回溯到某轮、修改上下文窗口、房客更新人设卡）不同步给房客，导致房客看到的会话状态与房主不一致。本次新增 5 个 `RoomMessage` 变体并在对应后端函数补广播，让房客能实时接收房主操作；同时新增 `room_update_guest_character` 命令让房客运行期更新人设卡并同步给其他房客。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 所有业务逻辑（DB 更新、广播决策）在后端完成，前端仅订阅事件渲染 |
| C2 Zero-Fallback Errors | √ | 广播失败仅 `eprintln` 记录但房主操作正常返回（best-effort 是广播策略，非吞错）；`room_update_guest_character` 校验失败显式返回 Err；无静默回退 |
| C3 Responsiveness | √ | 所有广播使用 `tauri::async_runtime::spawn` 异步执行，不阻塞 UI 线程；`broadcast_message` 内部仅推送 channel buffer，实际 TCP 写由独立 writer task 处理 |
| C4 AI UI Isolation | √ | 不涉及 AI 动态 UI 层 |
| C5 Mobile Frontend Independence | √ | 仅改后端 Rust 代码，不涉及 `src/` 或 `src-mobile/`；两端共用相同后端命令和事件 |
| C6 Project Cache Location | √ | 不涉及缓存写入 |
| C7 PC/Android Coverage | √ | 后端命令两端共用；`room_update_guest_character` 注册在共享的 `generate_handler!` 中，PC 和 Android 均可调用 |

## 5. 已知限制或后续待办

- **房客侧 `room_update_guest_character` 调用路径**：当前命令在 host 机器上执行时完整工作（DB 更新 + 广播）；房客机器上 `host_server` 为 None，DB 更新可执行但广播被跳过。房客→房主的人设卡转发链路（通过 `RoomClient::send_message` 发送 `GuestCharacterUpdated` 给 host，host 在 `RoomServer` read loop 中处理）需后续在前端集成时补全，或由前端直接调用 host 的命令
- **`RoomServer` read loop 未处理 `GuestCharacterUpdated`**：房客通过 TCP 发送的 `GuestCharacterUpdated` 消息在 host 端 read loop 中走 `_ =>` 分支（仅 emit 不处理），后续如需 host 端处理房客转发需补 read loop 分支
- **移动端前端接入**：后端已就绪，`src-mobile/` 需后续对应任务接入相同事件监听
