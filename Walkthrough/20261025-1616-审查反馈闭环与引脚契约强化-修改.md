# 20261025-1616-审查反馈闭环与引脚契约强化-修改

## 1. 改动摘要

针对最新一轮代码审查（Standards Reviewer 与 Spec Reviewer）的反馈进行了深度闭环：

1. **`src-tauri/src/services/action_bridge.rs` & `orchestrator.rs` & `director_actor.rs`**：
   - **C2 零静默回退治理**：在 `action_bridge.rs` 中新增 `resolve_required_capability_tool_definition(tool_name)`，当智能体配置了未在系统任何已知来源（ActionBridge、MCP 工具或原生工作区工具集）中注册的工具能力时，直接返回显式错误 `Err(...)`，彻底杜绝生成 `{}` 空 Schema 占位工具的伪成功行为。
   - **消除代码重复**：将 `orchestrator.rs` 和 `director_actor.rs` 中重复的备用工具查找和 Schema 补全逻辑统一收口至 `action_bridge.rs`。
2. **`src-tauri/src/commands/schema.rs`**：
   - **跨 IPC 路径与错误字符串规范化**：为 `query_preset_schemas` 以及所有 schema 命令的错误信息添加 `.replace('\\', "/")`，杜绝 Windows 路径分隔符引起 IPC JSON 反序列化问题。
3. **`src/components/blueprint/nodeLayout.ts` & `src-mobile/components/blueprint/mobileNodeLayout.ts`**：
   - **类型驱动与引脚兼容性收紧（对齐 Spec Line 59）**：重构 `isPinTypeCompatible(a, b)`。若双方均未标注类型则兼容；一旦任一方显式标注了具体类型（`Number`、`String`、`Boolean` 等），则双方必须均有类型且严格相等（`a === b`），彻底修复未标注引脚单向透传连接有类型宏引脚的安全漏洞。
4. **`src-tauri/src/services/blueprint_executor.rs`**：
   - **静态工具输出契约校验（对齐 Spec Line 26）**：在 `validate_blueprint_ui_contract` 中补全对 `NodeConfig::Writer` 工具输出的静态校验，保证状态写入目标（`stats.*` 与 `flags.*`）均在 `InitialStateConfig` 节点中合法声明。
5. **`src-tauri/src/models/blueprint.rs`**：
   - **类型驱动设计强化**：引入 `CalculatorOp` 领域枚举并为 `CalculatorConfig` 增加 `parsed_op()` 方法，消除了计算器操作符的原始类型偏执（Primitive Obsession）。
