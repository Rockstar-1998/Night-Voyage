# Walkthrough: 执行流水线打回循环与熔断保护机制双端实现 (Ticket 05)

## 改动摘要

1. **后端数据模型扩展 (`src-tauri/src/models/blueprint.rs`, `src/lib/blueprint/types.ts`)**：
   - 为 `ScriptwriterStage` 添加 `reject_target: Option<String>`（打回目标阶段，如 "draft"）与 `max_loop_count: Option<u32>`（最大打回次数，防死循环熔断保护，默认 2 次）。
   - 定义 `RejectionLoopState` 运行时打回上下文状态模型（`loop_id`、`current_iteration`、`max_iterations`、`last_critique`）。
   - 为 `TimelineKind` 扩展 `LoopReject` 枚举变体，用于向前端调试抽屉发射 `agent:timeline_event` 格式的打回与熔断事件。

2. **静态 DAG 拓扑校验特例放行 (`src-tauri/src/services/blueprint_executor.rs`)**：
   - 在图校验器 `validate_graph` 中引入三色 DFS 拓扑校验 `validate_dag_cycles`，对源自 `reject` / `Reject` 引脚的打回反向边进行特例放行，避免误报为非法死循环。
   - 强化 `next_node_id` 对前向放行端口（`approved` / `pass`）的兼容映射。
   - 编写单元测试 `test_dag_cycle_validation_relaxing_reject_pin`：验证 Reject 打回反向边被合法允许，而前向普通出边构成的死循环仍被严密拦截并报 `CycleDetected`。

3. **动态流水线打回调度与熔断保护 (`src-tauri/src/services/agent/orchestrator.rs`)**：
   - 升级 `execute_dynamic_scriptwriter_pipeline`：中间审阅阶段当识别到 `[REJECT]` / `[打回]` / `verdict: reject` 时，触发打回逻辑。
   - 实施反馈注入协议：将审阅批注意见写入纯内存 Scratchpad 工作区的 `{feedback}` 与 `{stage_id.critique}`。
   - 重新驱动目标生成阶段（附带审阅意见与迭代轮次），生成修正稿后再次提交评审。
   - 实现 `max_loop_count` 熔断机制：当打回循环超过上限时，触发熔断保护，标记 `circuit_breaker_tripped`，发射时序阻断事件，安全推进至终稿润色阶段，严防无限死循环或内存挂起。
   - 在 `run_scriptwriter_pipeline` 中接入 `agent:timeline_event` 发射通道。
   - 编写单元测试 `test_rejection_pipeline_and_circuit_breaker` 与 `test_rejection_pipeline_success_after_revision`，全部通过。

4. **双端配置界面同步支持 (`src/components/blueprint/nodes/ScriptwriterPipelineNode.tsx`, `src-mobile/components/blueprint/MobileNodeConfigForms.tsx`)**：
   - PC 端：在阶段配置项中新增“打回目标阶段 (Reject Target)”与“熔断上限 (Max Loops)”数字输入。
   - 移动端：在 `ScriptwriterPipelineForm` 的每个阶段卡片中新增独立的打回目标与熔断轮次输入控件，严守 C5 移动端零代码耦合与 C7 双端对齐。

## 改动动机

满足用户需求（Q3: "实现执行流水线（带打回循环）"）及系统 Spec 规范。打通审阅者（Critic / Reviewer）向初稿者（Drafter）的打回闭环与反馈注入，并以硬性阈值熔断保护机制杜绝死循环，保证会话永不假死（严守 C3）。
