## 改动动机

- **M3**：计划 §4 要求常驻 HUD 由创作者自由排版并跨模式生效。此前布局数据只有后端表与 Rust 类型，
  前端零调用方，会话看到的永远是同一块硬编码面板。本次把「设计 → 存储 → 绑定 → 渲染」这条链打通，
  并把"没配布局"与"配了默认布局"在界面上区分开（后端不返回默认模板）。
- **M4**：计划 §6.3 要求禁词毫秒级扫描、骰点不可篡改、最多重试 2 次并自纠。
  原实现的逐条 `contains` 随词库线性劣化，骰点来自"时间戳异或"可被预测；本次两者都换成真实现。
  另把 Nudge 从"只有工具函数"接到**终稿落库前的真实拦截点**——这才是"提交前阻断"的含义。

## 运作机制

- **布局渲染**：`session_ui_layouts` 决定会话用哪套布局 → `SessionHudMount` 取到 `layoutId`
  → `PersistentHudContainer` 拉布局 → `LayoutTreeNode` 按容器/控件递归渲染，取值走 `resolveDataBinding`。
- **HUD 补丁过滤**：`persistent_hud_keys` = 激活 Schema 中 `DisplayTarget::PersistentHUD` 的字段名集合；
  `InlineMessage` 字段（正文/思维链）只进气泡流。通道 A（DataContainer 的 stats/inventory/flags）不受过滤影响。
- **Nudge**：`spawn_stream_task` 在 `Ok(data)` 分支先校验终稿 → 命中则清 parts + 正文、轮次回 `streaming`、
  `ephemeral_instruction = 纠偏指令`、`continue` 重生成；第 3 次命中直接作废本轮并 `mark_failed`。
- **流水线**：`resolve_pipeline` 决定单模型 / 导演-演员 / 剧本流水线；剧本流水线走
  `assemble_context`（复用 `compile_prompt`）→ draft/critique/refine 三次 `run_subagent` →
  终稿过禁词门禁 → 落盘（正文 + 单个 text part）→ 单段 chunk → 轮后任务。
