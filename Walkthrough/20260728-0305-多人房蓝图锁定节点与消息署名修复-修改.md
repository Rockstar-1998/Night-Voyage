## 1. 改动摘要

### Bug 2：多人房无法请求模型（locked node n_rules is not on main path）
- 文件：[`src-tauri/src/services/blueprint_executor.rs`](src-tauri/src/services/blueprint_executor.rs:446)
- 函数：`validate_graph` 第 9 步校验
- 问题：`validate_graph` 原先要求「所有 `is_locked` 节点必须可从 Start 到达」，否则返回 `BlueprintError::LockedNodeOffMainPath`。预设 14（Night Voyage 默认预设）的蓝图含一个孤立的被锁定节点 `n_rules`（`is_locked=true`，但 `has_incoming_edge=false`），导致整张蓝图校验失败、`execute_blueprint` 返回 Err，进而每轮 `compile_prompt` 抛错、`stream_llm_response` 中断，用户正常发消息后无法请求模型。
- 修复：删除该阻断性校验。`is_locked` 仅表示「核心、用户不可编辑」的意图标记，不代表该节点必须被图执行路径访问；不可达（孤立）锁定节点本就被 `traverse` 跳过，不应阻断整体编译。Start→End 可达性已由第 8 步校验保证。为保留 `reachable_from_start` 变量引用（避免未使用警告），以 `let _ = &reachable_from_start;` 显式消费。

### Bug 1：房客退出重进后名字变为「玩家」，双方各自显示自己的名字
- 文件：[`src/App.tsx`](src/App.tsx:161)（`toChatMessage`）
- 问题：对**所有** `user` 消息统一套用本地 `playerCharacter?.name`，忽略 `message.displayName`（后端按真实成员 `conversation_members.display_name` 存储的发送者名）。多人房下两个客户端都把对方消息渲染成自己的名字；退出重连时本地 `playerCharacter` 上下文丢失 → 回退为「玩家」。
- 修复：`user` 消息的 `senderName` 改为优先使用 `message.displayName`（真实发送者名），本地 `playerCharacter?.name` 仅作自身消息兜底，`displayName` 为空才回退「玩家」。后端 `message_repository.rs` 已通过 `LEFT JOIN conversation_members` 正确携带 `display_name`，字段完整可用，无后端改动。

### 诊断日志（已回滚）
- `blueprint_executor.rs`：临时引入 `dbg_eprintln!` 打印每个节点的 `is_locked / has_incoming_edge / reachable_from_start`，确认 `n_rules` 为孤立锁定节点；修复后已移除导入与打印。
- `App.tsx`：`toChatMessage` 内临时 `console.debug('[toChatMessage][DIAG]', ...)` 打印 `displayName / localPlayerCharName / resolvedSenderName`；修复后已移除。
