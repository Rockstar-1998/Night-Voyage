# [修改] embedding 绑定按 memory_mode 分流校验

## 1. 改动摘要

**动机来源**：用户切换 LLM API 档案（workbuddy→nvidia）时，`conversations_update_bindings` 报
`embedding_provider_id 指向的 API 档案不存在`。根因为：会话 `embedding_provider_id=0`（已删除的 workbuddy 档案）成为悬空引用，
而更新路径无条件校验该字段，导致非 mem0 会话保存时也因 mem0 专属字段而失败。该耦合违反 AGENTS.md 第 116/120/121 行
（低耦合 / 组合优于继承 / 无效状态不可表达）。

**方案**：方案 A —— 后端按会话当前 `memory_mode` 分流 embedding 校验与更新。

**改动文件 / 函数**：
- `src-tauri/src/commands/conversations.rs`
  - `conversations_create`（约 153–164 行）：将 embedding 校验包进 `if memory_mode == "mem0"`。
  - `conversations_update_bindings`（约 351–383、411 行）：
    - 先 `SELECT memory_mode FROM conversations WHERE id = ?` 取当前模式；
    - 仅当 `embedding_update_enabled = (memory_mode == "mem0")` 时校验 `embedding_provider_id`；
    - `embedding_clause` 与绑定均改为 `embedding_update_enabled && embedding_provider_id.is_some()` 才写入，
      确保非 mem0 模式下该字段被完全忽略（不校验、不更新）。

## 2. 改动动机

- 解除阻塞：非 mem0 会话（stateless/legacy）切换 LLM 档案不再被失效的 embedding 引用误伤。
- 消除耦合：embedding 是 mem0 专属关注点，不应泄漏进所有会话的保存路径。
- 对齐规范：满足 AGENTS.md「低耦合」「无效状态不可表达」要求（根因——删 provider 不级联清理引用——属方案 C，本次未做）。
