# 蓝图节点加载丢失修复

## 改动摘要

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/components/blueprint/BlueprintEditor.tsx` | 修改 | **核心修复**：`setGraph(produce(() => { graph.nodes.splice(...) }))` 改为 `setGraph('nodes', newNodes)` 直接路径赋值 |

## 改动动机

### 问题：保存后重新打开节点丢失

前端 debug 日志（通过 invoke 转发到后端 stderr）揭示了根因：

```
[bp-debug] parsed nodes=3 edges=2        ← JSON.parse 成功，3个节点
[bp-debug] graph-store nodes=2           ← setGraph 后 store 里只有2个节点！
[bp-debug] render total=2 visible=2      ← 画布只渲染2个节点
```

数据库读写完全正常（后端日志确认 576 字节保存，576 字节读取），但前端 `setGraph` 后节点丢失。

### 根因：SolidJS store 的 `produce` + `splice` 组合 bug

原代码：
```tsx
setGraph(produce(() => {
  graph.nodes.splice(0, graph.nodes.length, ...normalizedNodes);
  graph.edges.splice(0, graph.edges.length, ...parsed.edges);
  (graph as BlueprintGraph).version = 2;
}));
```

`produce` 包裹的 `splice` 在 SolidJS store 中存在时序问题：
- `graph.nodes.length` 在 `splice` 执行时被读取作为删除计数
- 但 `splice` 同时在修改数组长度
- 这种"先删后插"的操作在 SolidJS store 的细粒度响应式追踪下会产生 race condition
- 结果：最后一个节点（通常是 prompt/schema_field 等业务节点）被丢失

问题是间歇性的——有时 setGraph 成功（render=3），有时失败（render=2），取决于 SolidJS 内部的 batch 执行时机。

### 修复方案

改用 SolidJS store 推荐的直接路径赋值方式：

```tsx
setGraph('nodes', normalizedNodes);
setGraph('edges', parsed.edges);
setGraph('version', 2);
```

这种方式直接替换整个数组，不依赖 splice 的删除+插入语义，没有 race condition。

同时修复了 `handleDeleteNode` 中的 produce 使用，改为直接路径赋值。移除了不再使用的 `produce` import。
