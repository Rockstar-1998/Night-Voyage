# 修改：结构化输出渲染修正（状态面板被误渲染为选项）

## 改动摘要
- `src/components/MessageFormatRenderer.tsx`（`StructuredResponseRenderer`）：原先将所有 `kind === 'object'` 的字段一律渲染为可点击「选项」按钮；改为：
  - **对象字段**（如 `status_bar`）→ 只读键值展示（折叠加灰标签 + 键值行），不可点击。修复「把状态栏条目当成选项」的问题。
  - **新增数组字段**（如 `options`）→ 可点击选项按钮（真实玩家选项），按序号 `1/2/3/4` 标注。
- `src/lib/messageFormatter.ts`：
  - `StructuredField.kind` 增加 `'array'`；
  - `parseStructuredResponse` 增加对数组（字符串元素）的识别，归类为 `kind: 'array'`。
- `src/components/MessageItem.tsx`：内联结构化解析逻辑同步支持以 `[` 开头的数组字段，归类为 `kind: 'array'`（原先数组会被当作普通字符串，或直接落入 `else` 分支）。
- `src-tauri/src/services/stream_processor.rs`（`finish()` 字段遍历）：对 `value.is_array()` 的字段也写入 `json_value`，使数组字段进入 `content_parts`（原先数组被整段丢弃，真实 `options` 从不显示）。

## 改动动机
用户实测：模型返回的结构化 JSON 中，`status_bar`（对象：体力/情绪/理智/社会地位）被错误地渲染成可点击选项（见截图「复杂：尴尬与职业化并存」「无主兽人，援交者」）。同时真正的 `options` 数组因为解析层丢弃数组而从不出图。

根因：前端 `StructuredResponseRenderer` 把「对象字段」与「可点击选项」等价起来，且后端/解析层不处理数组。本次打通整条链路：后端落库数组 → 前端识别数组 → 数组=可点击选项、对象=只读展示。
