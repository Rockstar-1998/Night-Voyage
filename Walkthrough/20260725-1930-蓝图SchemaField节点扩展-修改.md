## 改动摘要

### Rust 后端

| 文件 | 改动 |

| `src-tauri/src/models/blueprint.rs` | `SchemaFieldConfig` 新增 `required: bool`、`context_included: bool`、`display: FieldDisplayConfig` 字段；新增 `FieldDisplayConfig` 结构体（`default_expanded`、`hide_label`）。`BlueprintExecutionResult` 新增 `context_included_keys: HashMap<String, bool>` 与 `display_config: HashMap<String, FieldDisplayConfig>`。`#[serde(default = "default_true")]` 保证旧 JSON 反序列化兼容。 |

### 测试预设

`gen_default_preset.py` 的 `schema_field()` 工厂签名扩展为接受 `required` / `context_included` / `display` 参数（全部可选，默认 `true` / `true` / `default_expanded=true, hide_label=false`）。重新生成的默认预设 31 节点 / 42 边，大小 16970 bytes。

## 改动动机

旧版 `SchemaConfigPanel`（一个 preset 一个面板）在迁移到蓝图架构时被废弃（commit 9338b8e, 2026-07-14），但其核心 UX（多键管理、对象模式切换、子键可视化编辑、contextIncluded / display 偏好）并未在新的「每字段一个节点」方案中复现。本改动把其中：

- **必须的 schema 结构**（`required`、`context_included`、`display`）作为节点配置加回
- **可视化编辑**（对象模式、子键列表、items 类型）封装到 `<SubSchemaEditor>` 复用
- **json 文本框降级**为高级模式

仍然不恢复：多键管理（旧版是 per-preset，新架构天然 per-node，无需 UI 聚合）、语义组联动（被 GroupGate/MutexGate 取代）、`isEnabled` 开关（图拓扑本身是天然的开关）。

## 已知限制

- **SubSchemaEditor 暂未递归**——如果用户选 `object` 模式 + fixed_properties，编辑子键时每个子键还是顶层「type+description」两个字段，没有再展开 sub_schema。简单结构够用，深层嵌套需要后续迭代。
- **context_included 对 db_mapping 字段无意义**已在 UI 中提示，但代码层未禁止（避免硬限制干扰合法用例）。
- **移动端 SchemaFieldForm 仍用 JSON 文本框编辑 sub_schema**——移动端屏幕小、可视化子键编辑体验差；如需一致体验需另写移动端版本 SubSchemaEditor。
- **display_config 与 context_included_keys 在 legacy preset 中已有数据**（来自老 SchemaConfigPanel），新 UI 不会写回这两列（旧 preset 走 DB 直读路径），旧 preset 仍能工作。
