# Walkthrough: 全局能力池与智能体工具权限管控双端实现 (Ticket 04)

## 改动摘要

1. **后端数据模型与接口扩展 (`src-tauri/src/models/blueprint.rs`, `src/lib/blueprint/types.ts`)**：
   - 引入 `AgentToolPermissions`（包含 `allow_all: bool`、`allowed_tools: Vec<String>`、`require_approval: Vec<String>`）。
   - 为 `DirectorConfig`、`ActorDefinition`、`ScriptwriterStage` 添加可选的 `tool_permissions` 字段。
   - 挂载 `effective_tools(&self)` 与 `is_tool_allowed(&self, tool_name: &str)` 方法。

2. **静态校验与执行器门禁 (`src-tauri/src/services/blueprint_executor.rs`, `src-tauri/src/services/agent/director_actor.rs`)**：
   - 在 `extract_orchestration_configs` 中强化静态白名单门禁：当 `allow_all` 为 false 时，校验 `allowed_tools` 是否属于全局注册的有效能力；遇到未声明工具时立即拒绝并抛出结构化错误（严守 C2 零回退）。
   - 在 `director_actor.rs` 派发子智能体时过滤函数调用 Schema，仅下发该智能体白名单内或 `allow_all` 允许的工具，确保未授权工具对 LLM 完全隐蔽不可见。
   - 修复 `src-tauri/src/services/agent/orchestrator.rs` 既有测试用例结构体构造。

3. **PC 端属性卡片与权限编辑弹窗 (`src/components/blueprint/ToolPermissionsModal.tsx`, `ToolPermissionsCard.tsx`, `NodeConfigPanel.tsx`, `ScriptwriterPipelineNode.tsx`)**：
   - 严格参照设计参考图，实现 `ToolPermissionsModal`：包含“全部允许 (Allow All)”开关、允许工具与审批工具标签页切换、多行工具编辑域、常用能力池搜索与“+ 添加”快速交互。
   - 实现 `ToolPermissionsCard` 属性面板概览卡片：展示“全部允许” / “白名单 (N 个允许)”状态微标、已配置权限明细表及“编辑”交互按钮。
   - 在 PC 蓝图配置面板 `NodeConfigPanel`（导演节点 `director_config`、演员节点 `actor_definition`）与剧本流水线节点 `ScriptwriterPipelineNode`（各流水线阶段）全面挂载。

4. **移动端独立触控适配 (`src-mobile/components/blueprint/MobileToolPermissionsModal.tsx`, `MobileNodeConfigForms.tsx`)**：
   - 针对移动端触摸手势设计 `MobileToolPermissionsModal` 与 `MobileToolPermissionsCard`，独立实现（严守 C5 移动端代码零耦合）。
   - 在移动端表单 `DirectorConfigForm`、`ActorDefinitionForm`、`ScriptwriterPipelineForm`（各阶段）深度挂载，实现 PC/Android 双端 100% 对齐（严守 C7）。

---

## 改动动机

解决原 V2.2 蓝图将工具塞入互斥分支 (`MutexGate`) 导致智能体无法共享能力池的架构缺陷（反模式 3），践行“全局定义、按智能体挂载能力白名单”的设计规范（Q4）。实现智能体级别的严格最小权限管控，防止审查/审核子智能体误用或越权执行状态变更与扣费等破坏性动作。

## 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 前端组件仅负责权限表单渲染与回调，所有白名单校验与过滤由 Rust 后端统一执行 |
| C2 Zero-Fallback Errors | √ | 权限非法、未声明工具直接抛出强类型编译错误，绝不静默放行或自动回退 |
| C3 Responsiveness | √ | 搜索与白名单过滤采用纯内存响应式计算，无卡顿无阻塞 |
| C4 AI UI Isolation | √ | 纯蓝图宿主编辑器能力，不影响外部 AI 沙箱 |
| C5 Mobile Frontend Independence | √ | `src-mobile/` 拥有完全独立的 Modal 和 Card 实现，零互引 `src/` 代码 |
| C6 Project Cache Location | √ | Cargo 构建与工具链使用项目目录 `.cache`，无跨盘写系统盘 |
| C7 PC/Android Coverage | √ | PC 与移动端均拥有完整的权限卡片概览与多行/快速添加编辑弹窗 |
| C8 MCP-Only Acceptance | √ | 蓝图后续预设与能力操作均严格采用 MCP 工具路线 |
| C9 MCP Rolling Development | √ | 滚动适配当前阶段所需能力 |
| C10 MCP Demo Front-Mount | √ | 权限卡片与编辑入口均作为真实 UI 按钮挂载在节点配置面板中 |
| C11 No Hardcoded Data | √ | 常用工具参考列表基于系统已注册的 ActionBridge、本地工具及 MCP 契约动态聚合 |
