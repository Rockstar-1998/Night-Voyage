# MCP 端点端到端测试

- 时间：2026-09-22 18:53
- 类型：新功能增加
- 范围：`scripts/mcp_endpoint_e2e.py`（新增）

## 1. 改动摘要

新增 `scripts/mcp_endpoint_e2e.py`：以第三方客户端身份、经 HTTP 直连一个**正在运行**的客户端进程，
对开发期 MCP 端点（`127.0.0.1:55287/mcp`）执行 40 项端到端断言。

| 层 | 覆盖 | 项数 |
|----|------|------|
| A 传输与鉴权 | 缺失令牌 401、错误令牌 401、非 POST 405、错误路径 405 | 4 |
| B JSON-RPC 协议 | initialize、通知 202 空体、ping、未知方法 -32601、非法 JSON -32600 | 5 |
| C 工具清单 | 数量 7、名称集合、inputSchema 齐备 | 3 |
| D 工具语义 | 7 个工具全覆盖 + 状态生命周期 + ToolCall 确定性门禁 + 参数校验 | 26 |
| E 缺陷探针 | X01 `argumentsJson` 静默降级、X02 负零泄漏 | 2 |

关键实现点：

- **令牌与库路径均从真实来源读取**，不硬编码。令牌读 `D:\software_cache\night-voyage-mcp.token`；
  库路径由 `--db` 传入，并在 D01 断言 `nv_db_info` 回报的路径含 `nv-mcp-test`——
  库路径有环境变量 / exe 同目录 / 应用数据目录三种解析来源，不显式断言就可能改错库。
- **强制直连环回地址**。本机环境设有 `HTTP_PROXY` / `HTTPS_PROXY`（均为 `http://127.0.0.1:2788`）
  且无 `NO_PROXY`，`urllib` 默认会读它。若不管，请求会绕经代理再回到环回，
  测试就不再是"客户端 ↔ 端点"的直接一跳。故用 `ProxyHandler({})` 构造 opener，
  并在运行时打印代理环境变量。
- **夹具经 `sqlite3` 直插**：一个 `title='__mcp_e2e__'` 的会话 + 一条消息，先删后插保证幂等。
  `session_states` 的写入**不**由夹具承担，一律经 `nv_session_state_reset`（即真实
  `reset_session_state`）产生，避免手写 JSON 污染 serde 契约。
- **XFAIL 与 FAIL 分离**：既有产品缺陷以 `XFAIL` 登记，与"契约不满足"的 `FAIL` 区分，
  使主套件保持全绿的同时不掩盖缺陷。

## 2. 改动动机

被测端点此前只有"编译成功 + 产物含符号"这一类构建期证据，没有任何运行期证据。
本机进程级写入过滤会让工具链在复用 target 时报错，而 GUI 进程又曾被判定无法跨工具调用存活，
两者叠加导致端点从未被真正调用过一次。

本机实测推翻后一条判断：后台启动的客户端可存活 11 分 33 秒，`[mcp] dev endpoint listening on
http://127.0.0.1:55287/mcp` 正常打印。既然进程可以稳定存活，就必须用真实调用把它测穿。

选择"打真实进程"而非 `cargo test`：每个工具都经 `ToolContext { app: AppHandle, db: SqlitePool }`
落到真实服务层，而 `AppHandle` 只在事件循环跑起来时才存在，单元测试里造不出来。
打真实进程同时也是用户现场演示会走的那条路径。

## 4. 验收记录

- 启动：`NIGHT_VOYAGE_DB_PATH=D:/software_cache/nv-mcp-test/night-voyage.sqlite3 ./night-voyage.exe`
- 执行：`python scripts/mcp_endpoint_e2e.py --db D:/software_cache/nv-mcp-test/night-voyage.sqlite3`
- 结果：`合计 40 项  PASS=38  FAIL=0  XFAIL=2  SKIP=0`，退出码 0
- 隔离性：D01 断言端点回报的库路径含 `nv-mcp-test`，确认真实存档未被触碰
- 收尾：测试实例已终止，`tasklist` 无 `night-voyage.exe` 残留，`55287` 直连返回 `ConnectionRefused`

### 探针登记的两项既有缺陷

| 编号 | 位置 | 现象 | 证据 |

| X01 | `services/agent_runtime.rs:88-89` | `arguments_json` 解析失败被 `.unwrap_or(空对象)` 吞掉，对外报"缺少 item_id 参数"而非"参数不是合法 JSON" | `argumentsJson="这不是合法 JSON"` → `缺少 item_id 参数` |
| X02 | `models/game_state.rs:62-67` | `total_weight()` 对空背包的 `.sum::<f64>()` 返回 `-0.0`（Rust std 的 `Sum for f64` 以 `fold(-0.0, _)` 为初值），`sync_weight()` 将其写入 `stats["weight"]` 并持久化 | 产品自身文本 `当前负重: -0.0kg`；库内 `"weight":-0.0` |

X01、X02 均为改动前既存，本文件不修，等用户决策。

## 5. 已知限制或后续待办

- **HUD 广播不可从进程外观测**。`broadcast_hud_patch` 走 Tauri 进程内事件总线，外部客户端只能
  断言"状态已持久化"（D16/D20），"界面确实刷新"须由现场演示肉眼确认。
- **夹具需手工铺设**。端点无"新建会话"工具，空库无法仅凭 MCP 驱动出完整界面流程；
  演示前需在界面里打开一个会话。
- X01、X02 待用户裁决是否修复。
- `write_text` 观察项（不计入通过率）：该分支只改内存 `state.scratchpad`，既不 `save_session_state`
  也不广播，下一次调用读不到内容，但对外回报"已更新"。
