## 2. 改动动机

在上一轮 `/code-review` 复审中，两个维度发现了深层次的问题：
1. **Standards C2 (Zero-Fallback)**：
   - `services/preset_service.rs` 在 `validate_ui_contract_for_graph` 中对找不到 layout 布局的情况静默返回 `Ok(())`；
   - `commands/blueprint.rs` 在 `preview_blueprint_with_session` 中使用 `if let Ok(...)` 吞掉了 `preset_schemas` 的数据库异常；
   - 双端编辑器在获取能力池与白名单的 catch 块中仅打印 `console.error`，未向用户弹出错误提示。
2. **代码异味治理（Smells）**：
   - **Duplicated Code**：`preset_service.rs` 与 `commands/blueprint.rs` 重复手写了完全相同的 UI 布局读取、反序列化与契约提取逻辑；
   - **Primitive Obsession**：多处散落着 `.toLowerCase() !== 'reject'` 的字面量字符串比较。
3. **Spec 契约完备性**：
   - **Spec Line 40**：明确要求在画布节点（Node）上直接显示错误徽章，原代码仅在顶部有全局横幅；
   - **Spec Line 168**：数据结构中声明的 `require_approval` 高危工具在编排运行时（`orchestrator.rs` 与 `director_actor.rs`）缺少实际的拦截门禁。
