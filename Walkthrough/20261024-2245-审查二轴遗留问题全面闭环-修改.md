## 2. 改动动机

在代码复审（规范标准 Standards 与规格说明 Spec 两个维度）中发现如下问题与坏味道：
1. **Standards C2 (Zero-Fallback)**：双端蓝图编辑器在工具加载与契约校验网络异常时存在空 `.catch(() => {})`，导致校验失败被静默吞掉，进而绕过保存拦截；
2. **Standards C1 (Layer Boundary)**：双端前端在个别调用点绕过 `lib/backend/` 直接裸调用 `@tauri-apps/api/core` 的 `invoke`；
3. **Standards C7 (Dual-Platform)**：PC 端 Agent 调试面板有审阅打回（`loop_reject`）时间线事件展示，而移动端缺少该事件类型与徽章渲染；
4. **Standards IPC Sanitization**：后端命令的错误信息转换未统一对反斜杠做替换规范化；
5. **代码异味**：`director_actor.rs` 工具权限解析逻辑重复拷贝；`types.ts` 重复声明结构体派生函数；Canvas 连接线存在恒真死分支；
6. **Spec 契约落差**：
   - Spec 50/171-173 行明确要求支持 stage 级别工具权限过滤，特别是 critic/reviewer 阶段必须只赋予只读工具（禁止 write）；
   - Spec 102 行要求前端提供可交互的契约 Inspector Drawer 供创作者展开查看契约细节。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|---|---|---|
| C1 Frontend Render-Only | √ | 前端通过 typed backend wrappers 异步请求 Rust 核心，所有业务、校验与过滤逻辑在后端 |
| C2 Zero-Fallback Errors | √ | 修复 catch 静默放行漏洞，契约校验错误或网络异常立即拦截保存并显式反馈；无吞异常 |
| C3 Responsiveness | √ | 所有契约校验与抽屉交互异步细粒度响应，UI 线程永不卡顿假死 |
