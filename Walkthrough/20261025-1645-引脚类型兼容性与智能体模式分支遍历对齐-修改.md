# 20261025-1645-引脚类型兼容性与智能体模式分支遍历对齐-修改

## 1. 改动摘要

- **`src-tauri/src/models/blueprint.rs`**:
  - `PinType::is_compatible`: 增强数据引脚动态兼容性判定，保持 `Exec` 仅与 `Exec` 互通的前提下，允许 `Object`（对应 spec 中的 `Object/Any`）与任意数据引脚（`String` / `Number` / `Boolean`）相互兼容，杜绝伪类型绕过。
- **`src-tauri/src/services/blueprint_executor.rs`**:
  - `get_port_pin_type`:
    - 针对 `NodeConfig::Constant` 节点，将其输出端口 `out` / `value` 严格解析为 `PinType::String`（纯值出口），并明确其无输入端口。
    - 针对 `NodeConfig::Branch` 节点，明确其 `value` 输入端口为 `PinType::String`，`in` 输入端口为 `PinType::Exec`，各 `case` 与 `default_port` 出口为 `PinType::Exec`。
    - 支持 `approved` 与 `reject` 等审阅控制流引脚映射为 `PinType::Exec`。
  - `traverse` 与 `output_port_priority`:
    - 将 `NodeConfig::AgentModeSwitch` 提取为独立的多出口分支节点，依据会话 `gate_selections`（缺省使用 `default_mode`）动态路由至 `out_single` / `out_director_actor` / `out_scriptwriter`。
    - 在 `output_port_priority` 中显式注册 `AgentModeSwitch` 的固定出口优先级（`out_single` > `out_director_actor` > `out_scriptwriter`），确保分支遍历与 `find_merge_node` 汇合点推导确定且一致。
- **`src/components/blueprint/nodeLayout.ts` & `src-mobile/components/blueprint/mobileNodeLayout.ts`**:
  - `isPinTypeCompatible`: 与后端 `PinType::is_compatible` 逻辑完全对齐，允许 `object` 充当 `Any` 与基础数据引脚兼容，同时严格禁止 `exec` 与数据引脚交叉连接。
- **`测试预设/Night Voyage 全能核心预设 V3.0 (宏化智能体与契约驱动版).nvpreset.json`**:
  - 接入正式宏实例 `n_macro_buy_rule` 与 HUD 布局，修正 `n_mode_switch` 多智能体三向分支连线。

## 2. 改动动机

- 此前 `test_mcp_delivery_and_validation_of_canonical_v3_preset` 在执行宏展开与图校验时遭遇两个阻断问题：
  1. `Constant` 节点在端口类型判定中被归入通用兜底分支，误将纯值输出 `out` 解析为 `PinType::Exec`，导致其连向下游 `Branch` 节点的 `value` 输入端口（`PinType::String`）时触发 `IncompatiblePinTypes` 校验失败。
  2. 蓝图遍历执行器 `traverse` 此前将 `AgentModeSwitch` 作为普通线性资产节点处理，试图寻找不存在的 `"out"` 单端口出边，导致多智能体三向分支（`out_single` / `out_director_actor` / `out_scriptwriter`）在运行时抛出 `NoOutgoingEdge { node: "n_mode_switch", port: "out" }`。
