# [修改] 修复 Tailwind 自动内容检测全树扫描导致 vite 构建超时

## 1. 改动摘要

- `src/index.css`：
  - `@import "tailwindcss";` → `@import "tailwindcss" source(none);`
  - 恢复并保留显式内容源：`@source "../src/**/*.{tsx,ts}";` 与新增 `@source "../index.html";`
  - 删除此前误加的 `@config "../tailwind.config.js";`（该路径相对于项目根解析失败，配置从未生效）。
- `src-mobile/index.css`：
  - 同上：`@import "tailwindcss" source(none);`
  - 保留 `@source "../src-mobile/**/*.{tsx,ts}";` 与新增 `@source "../index-mobile.html";`
  - 删除无效的 `@config` 行。
- 删除临时文件：`tailwind.config.js`（无效配置）、若干 `_tw_probe*.mjs` 探针脚本。

## 2. 改动动机

项目根目录混入了多个与前端无关的巨型目录（`src-tauri` 约 65000 文件、`ST2NV-Converter-Web` 约 11000、`sillytavern` 约 1600 等）。

Tailwind CSS v4 默认开启**自动内容检测（automatic content detection）**，会对整个项目根做 `**/*` 递归扫描（仅忽略 `node_modules`/`.git`/`.gitignore` 路径），**与 `@source` 是否追加无关**。vite 插件内部逻辑为：`compiler.root === null` 时扫描 `**/*` 全树；只有 `root === "none"` 才只扫显式 `@source`。

原配置仅靠 `@source "../src/**"` 追加源，但 `root` 仍为 `null`，于是 vite 构建阶段在 Tailwind 扫描整棵 ~9000+ 个模板文件（ts/tsx/js）时卡死，实测 `vite build` 跑满 180s 超时仍不出结果、零产物。

**修复方法（v4 正确语法，经探针在 `@tailwindcss/node` 的 `compile` 上验证 `root === "none"`）：**
在 `@import "tailwindcss"` 语句上追加 `source(none)` 关闭自动检测，再用 `@source` 把内容源**显式限定**到 `src` / `src-mobile` 及两个 html 入口。扫描范围从 ~9000 个无关文件降到约 100 个真实文件。

> 对照实验：临时去掉 `@tailwindcss/vite` 插件后，同一构建 5.96s 完成 → 实锤瓶颈在 Tailwind 扫描，而非前端代码量。

## 4. 验收记录

- 构建命令：
  - 桌面端：`node node_modules/vite/bin/vite.js build`（即 `npm run build`）
  - 移动端：`node node_modules/vite/bin/vite.js build --config vite.config.mobile.ts`
- 验收方式：计时 + 检查产物 CSS 是否含真实工具类。
- 预期效果：构建在数十秒内完成，且生成的 CSS 包含应用实际使用的工具类（证明内容扫描未失效）。
- 实际结果：
  - 桌面端：`✓ built in 5.80s`，`dist/assets/index-*.css` 80.47 kB，含 `.flex`/`.absolute`/`.grid` 等。
  - 移动端：`✓ built in 22.25s`，`dist/assets/index-mobile-*.css` 53.14 kB。
  - 修复前：桌面端 `vite build` 在 `transforming...` 阶段卡满 180s 超时、零产物（无法完成）。

## 5. 已知限制或后续待办

- 移动端构建（22s / 2001 modules）明显慢于桌面端（5.8s / 434 modules），系移动端模块图更大（非 Tailwind 扫描问题）。若需进一步优化可审查 `src-mobile` 依赖图，但已非阻塞项。
- 根因是项目根污染（前端与多个巨型非前端目录同处一根）。本次修复在 Tailwind 层拦截，等价于为前端构建隔离了扫描范围；若日后新增前端目录，需在两份 CSS 的 `@source` 中同步登记，否则新目录的类不会被扫描到。
- 可选增强：把 `ST2NV-Converter-Web` / `sillytavern` / `MEM0` 等无关目录加入 `.gitignore`，可进一步防止其他工具误扫（Tailwind v4 自动检测会尊重 `.gitignore`）。
