# 工单 02：分而治之流式处理器解耦与零延迟旁白保底

## 1. 改动摘要

| 文件 | 改动 |
|------|------|
| `src-tauri/src/services/stream_processor.rs` | 新增 `StreamingToolAccumulator`（双协议流式 ToolCall 静默拼装缓冲：OpenAI `feed_openai_delta` 按 index 拼装、Anthropic `begin_anthropic_tool_use` / `feed_anthropic_json_delta` 按 block 拼装、`finish()` 定稿全量校验）；新增统一工具收尾 `complete_tool_use_turn`（校验 → 骨架落盘 → 逐条 emit → 交编排层），OpenAI `[DONE]` / 流自然结束、Anthropic `stop_reason=tool_use` 三条路径共用；新增 `ToolReceiptSummary`、`synthesize_fallback_narrative`（零延迟旁白纯函数）、`fill_fallback_narrative_if_empty`（旁白回填 SQLite）；新增单元测试 10 个 |
| `src-tauri/src/services/chat_service.rs` | `dispatch_tool_calls` 在执行循环中同步收集回执摘要，工具执行完毕、回注开新轮之前调用 `fill_fallback_narrative_if_empty` 回填旁白 |
| `.scratch/unified-all-agent-architecture/issues/02-*.md` | 6 项 checklist 全部勾选完成 |

关键缺陷修复：OpenAI 兼容流以 `data: [DONE]` 收尾时，旧实现直接按纯文本定稿并把返回值里的 `pending_tool_uses` 置空——已拼装的工具调用会被静默丢弃。本次在 `[DONE]` 分支接入同一条工具收尾，工具只在流终止、校验通过后才进入执行层。

定稿校验语义（原子性闸门）：`finish()` 对整批骨架做全量校验——id/name 缺失、arguments 非合法 JSON 任一命中即整批硬错，编排层不会执行其中任何一条；此前骨架只做 trim 归一，残缺 JSON 会流入执行层逐个失败。

事件契约对齐说明：工单原文写 `game-state:patch`，仓库实际前端契约是 `session:hud_state_patch`（`agent_runtime::broadcast_hud_patch`，工具执行落盘时发射）与 `agent:timeline_event`（`dispatch_tool_calls` 与工具执行链逐条发射）。本次不新造无人监听的事件名，按既有契约对齐，工具原子提交后两类事件均已发射。

## 2. 改动动机

落实《全 Agent 统一执行架构》工单 02：单步充填模式下对白与工具在同一条 SSE 流里混编，必须物理分流——对白 Token 实时进前端打字机通道，工具 Token 只进后端缓冲静默拼装；流终止时一次性校验、落盘、执行。模型只发 ToolCall 不写对白时，依据工具回执在服务端合成极简旁白回填消息正文，杜绝空白气泡，且不发起第二次模型请求。
