## 改动动机

验收演示此前只操作内部数据（MCP 工具改库、广播 HUD），用户在界面上看不到"操作入口"，
只看到结果，判定验收不通过。按 C10，把演示用到的工具能力挂载为前端真实按钮：
用户可在 UI 上亲手触发「重置状态」「执行 ToolCall」等操作，HUD 当场刷新；
MCP 工具与前端按钮从此是同一条路径的两个入口。

## 运作机制

- 面板为自包含组件：自身管理开合/忙碌/输出状态；未选会话时点会话级按钮显式报
  「未选中任何会话」（C2 零静默回退）。
- 全部调用走 `lib/backend` 既有的 `invoke` 封装（异步，C3）；`session_game_state_reset` 与
  `session_tool_call_execute` 由后端广播 `session:hud_state_patch`，上方 PersistentHudContainer
  原地刷新——按钮触发与 MCP 触发的界面效果一致。
- 门禁演示可直接点「门禁探针 金币不足」快捷项：`buy_item` 1000G 会被确定性门禁拦截，
  错误原文红显在输出区，同时 HUD 数值不被污染。

## 约束合规审计

| 约束 | 合规 | 说明 |

## 验收记录

- 构建命令：`scripts\build_dual_release.bat --features=mcp-dev`（沙箱内 node.exe 被安全策略
  黑名单拦截，构建由用户本机执行）。
- 验收方式（C8 + C10）：构建完成后由 MCP `nv_app_restart` 加载新 exe；用户在界面上亲手点
  「MCP 调试台」按钮执行「重置状态 / 门禁探针 / buy_item」，旁观 HUD 当场刷新；
  同时保留 MCP 工具触发的对照演示与 `nv_screenshot` 截图证据。
- 预期效果：按钮触发与 MCP 触发的门禁、持久化、HUD 广播行为完全一致。
