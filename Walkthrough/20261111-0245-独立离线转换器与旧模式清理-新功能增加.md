## 业务摘要

- **新增独立离线工具 `src-tauri/src/bin/nv-converter.rs`**（独立 bin 目标，与主程序生产路径解耦；lib 仅经 `lib.rs` 定向再导出 4 个符号供其使用）：
  - `upgrade_legacy_graph`：旧图 JSON 单向升级——`version` 缺失/1 → 2（现行模型只接受 v2）；旧式 Constant 串 exec 链的拓扑经 `normalize_legacy_value_edges`（与主程序同一条改写规则，单一事实来源）改写为 value 引脚数据流；升级后过现行 `BlueprintGraph` 模型校验，「能在主程序加载」即成功定义；
  - `--to-code` 直接产出 `.nv.ts`（复用工单 05 编解码器）；转换报告逐项打印（升级动作 + legacy sampling_params 等人工关注项），失败退出码 1、绝不静默吞输入；
  - legacy `sampling_params` 节点原样保留并警告：现行模型仍可加载，转换器不猜测目标协议、不做有损改写。
- **生产路径旧模式拦截全量清理**（全量扫描 `src-tauri/src/services/` 确认）：
  - `orchestrator::resolve_pipeline`：删除 `chat_mode != "director_agents"` 早退与 chat_mode 参数——编排架构只由蓝图 `AgentModeSwitch` 资产决定；蓝图缺该节点 = 预设未声明多智能体编排，按单智能体直出（图即权威）；Gate 选项未知仍显式报错；
  - `stream_processor` 流任务：删除随之无用的 chat_mode 加载（原 `unwrap_or_default()` 吞错一并消失）；
  - `stream_processor` 工具分发点：删除「非 agent 模式返回 ToolCall 即报错」拦截——工具可用性由蓝图声明的工具计划决定，未声明工具的预设不会产生 ToolCall；
  - `chat_service::submit_tool_results`：删除「仅 agent 模式可提交回执」拦截，保留工具轮次上限等真实防护。

## 成文说明

- `repositories/round_repository.rs` 的 `chat_mode == "director_agents"` 是写进 `agent_runs.orchestration_mode` 的**来源标签**（运维元数据），不是运行时拦截，予以保留——本单清理目标是「拦截判断」，已全量核查 services/ 下再无同类分支（剩余 chat_mode 引用仅为 action_bridge 的列读写）。
- 旧会话记录：stateless 记忆模式已由历史迁移 0050 在库内收敛；chat_mode 旧会话在新语义下直接按蓝图资产运行，无需离线转换。转换器输入契约是旧预设图 JSON 文件。
