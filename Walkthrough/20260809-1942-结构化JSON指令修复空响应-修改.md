# [修改] 结构化JSON指令修复空响应回归

## 1. 改动摘要

- 文件：`src-tauri/src/services/provider_adapter.rs`
  - `build_llm_chat_request`（约 L152）：当 `response_mode == "structured_json"` 且
    `structured_output_schema` 非空时，向 `system` 末尾追加一条 JSON 输出指令
    （`build_structured_json_directive` 生成），再合并为单条 system message。
  - 新增函数 `build_structured_json_directive(schema_json: &str) -> String`：解析
    JSON Schema 的 `properties`，列出字段名/类型/必填标记/描述，并强制要求：
    1) 仅输出一个 JSON 对象，无散文/Markdown；
    2) 覆盖系统提示中残留的散文格式指令（「电影镜头」「推演路标」等）；
    3) 叙事散文放入额外的 `narrative` 字段（response_format 用 strict:false，允许 schema 外字段）。

## 2. 改动动机（为什么改）

前一次 Bug 2 修复（`prompt_compiler.rs` 强制 `response_mode = "structured_json"`）引入
**回归**：默认预设（`Night Voyage 全能进阶核心预设 V2`，preset_id=22）发起对话后
**响应为空**。

真机日志 + `llm_req_1786275605_..._deepseek-v4-flash.json` 证据链：
- 请求体**已正确携带** `response_format: {type:"json_schema", ...}` 与 schema
  （thinking/status_bar/todo_list/options）——证明强制 structured_json 生效。
- 但模型（经本地 `antigravity-proxy` 127.0.0.1:8002）**返回散文**（delta 全是
  `。\n\n`、`。”\n\n` 这类散文片段），proxy 不强制 json_schema。
- 结构化解析器 `finish error: incomplete JSON: parser stopped at phase BeforeObject`
  → 整个响应被判为「LLM 响应为空」。
- 叠加设计冲突：系统提示里**同时存在**散文指令（电影镜头/推演路标）与 JSON schema
  字段（options/status_bar/todo_list），且 schema **无叙事字段**——纯 JSON 会把
  长篇叙事直接抹掉。

仅靠 `response_format` 无法保证模型输出 JSON（proxy 忽略 + 散文指令对抗）。补一条
位于 system 末尾的权威 JSON 指令，覆盖散文格式要求并把散文重路由到 `narrative`
字段，是客户端唯一可靠的解法。

## 5. 已知限制 / 后续待办

- **模型遵从风险**：若模型仍不遵从 JSON 指令而吐散文，响应仍会判空。届时需要求
  用户确认 proxy 是否转发 `response_format`，或改为 `json_object` + 强指令方案。
- **叙事字段为额外字段**：`narrative` 不在 schema 的 `properties` 内（strict:false
  允许）。若用户希望叙事字段进 schema（参与 db_mapping/前端折叠控制），需在预设的
  蓝图里补一个 `narrative` 类型 schema_field 节点。
- **残留散文指令**：蓝图里 `mod_parallel`/`mod_actions`(推演路标) 等 PROMPT 节点仍
  以散文口吻描述同名字段；指令已要求忽略其格式，但预设作者后续可把这些节点改为
  纯内容定义、由 schema 字段承担结构化输出，避免语义重复。
