# 预设导出显示保存路径 — 修改

## 改动摘要

| 文件 | 改动点 |
|------|--------|
| `src-tauri/src/commands/presets/mod.rs` | 新增 `presets_export_to_file` 命令：由后端生成预设 JSON 后写入用户可见目录，并返回最终保存路径。保留原 `presets_export`（JSON 字符串）供 `presets_duplicate` 等内部流程复用。 |
| `src-tauri/src/lib.rs` | 注册新命令 `presets_export_to_file`。 |
| `src/lib/backend/presets.ts` | 新增 `presetsExportToFile(id, fileName)` 前端封装。 |
| `src/App.tsx` | PC 端「导出预设」改为调用 `presetsExportToFile`；导出成功后通过 `showConfirm` 显示完整路径，并提供「打开文件夹」按钮（`revealItemInDir`）。 |
| `src-mobile/components/blueprint/MobilePresetBlueprintEntry.tsx` | 移动端同步改为调用 `presetsExportToFile`；导出成功后显示路径，并提供「打开文件」按钮（`openPath`）。 |

后端路径策略：
- 桌面端：优先使用系统「下载」目录，子目录 `Night Voyage Exports`；若不可获取则回退到应用数据目录。
- Android：使用应用私有数据目录下的 `exports` 子目录。
- 文件名由前端传入并二次净化，禁止路径分隔符与非法字符；若重名自动追加 `(1)`、`(2)` 等序号。

## 改动动机

用户反馈点击「导出预设」后只收到「已导出预设」提示，但不知道文件实际保存到了哪里。原实现通过 `Blob` + `<a download>` 触发浏览器下载，文件落入浏览器默认下载目录且前端无法获知路径。本次改动改为后端直接写入用户可见目录，并把真实路径返回给前端显示，同时提供一键打开所在文件夹/文件的能力。

## 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 文件 I/O、JSON 序列化、路径计算全部放在后端 Rust 命令中；前端仅负责调用命令、显示结果、打开文件夹。 |
| C2 Zero-Fallback Errors | √ | 后端写入失败、路径解析失败均显式通过 `Result::Err` 返回；前端在 `catch` 中显示错误 Toast。 |
| C3 Responsiveness | √ | 导出命令标记为 `async` Tauri 命令，文件写入在后台线程完成，前端通过 `await` + loading/busy 状态保持响应。 |
| C4 AI UI Isolation | √ | 未涉及 AI 动态 UI。 |
| C5 Mobile Frontend Independence | √ | PC 与移动端导出流程分别位于 `src/App.tsx` 与 `src-mobile/components/blueprint/MobilePresetBlueprintEntry.tsx`，各自使用适合自己平台的 opener API（`revealItemInDir` vs `openPath`），无 UI 代码共享。 |
| C6 Project Cache Location | √/× | 导出文件属于用户主动请求的输出文件而非运行时缓存；桌面端保存在系统「下载」目录便于用户查找。若后续要求所有运行时输出均落盘到 `D:\software_cache`，可改为优先读取环境变量或固定缓存目录。 |
| C7 PC/Android Dual-Platform Coverage | √ | 新命令 `presets_export_to_file` 双端通用；PC 与移动端前端均已切换到新命令并给出路径提示。 |

## 验收记录

构建命令：

```powershell
npx tsc --noEmit -p tsconfig.json
npx tsc --noEmit -p tsconfig.mobile.json
scripts/build_dual_release.bat
npm run build:mobile
```

输出：

- `npx tsc --noEmit -p tsconfig.json`：通过，无错误。
- `npx tsc --noEmit -p tsconfig.mobile.json`：通过，无错误。
- `scripts/build_dual_release.bat`：PC 前端构建成功，Rust release 编译成功（仅既有 dead code 警告），生成实例 A/B。
- `npm run build:mobile`：移动端前端构建成功。

验收方式：

1. 启动应用，进入预设蓝图列表。
2. 点击任意预设卡片的「导出」按钮。
3. 预期效果：弹出确认框，标题为「预设导出成功」，消息中显示完整保存路径（如 `C:/Users/<user>/Downloads/Night Voyage Exports/Night Voyage 全能进阶核心预设 V2.nvpreset.json`）。
4. 点击「打开文件夹」：系统文件资源管理器打开并高亮该文件。
5. 移动端：导出后显示路径；点击「打开文件」调用系统默认程序打开 JSON 文件。

## 已知限制或后续待办

- 当前桌面端使用系统「下载」目录作为默认导出位置，未提供让用户自选保存路径的对话框。如需自定义位置，可后续引入 `tauri-plugin-dialog` 的保存对话框（需评估 Android content URI 写入复杂度）。
- 移动端 `revealItemInDir` 不受支持，因此使用 `openPath` 直接打开文件；部分 Android 系统可能缺少默认 JSON 查看器，效果取决于系统配置。
- 路径跨 IPC 已统一转成正斜杠，PC 端「打开文件夹」调用前未再转回反斜杠；在 Windows 上已验证可正常唤起资源管理器，但在极端环境（含特殊字符路径）可能需要进一步测试。
