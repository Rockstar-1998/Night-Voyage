# 多人房客角色卡转发链路修复

## 改动摘要

### 修改的文件

- `src-tauri/src/network/mod.rs`：
  - `RoomMessage` 枚举新增 `UpdateGuestCharacter { member_id, character }` 变体（房客→房主的上行 TCP 消息，不同于 `GuestCharacterUpdated` 下行广播）
  - RoomServer read loop 的 match 新增 `UpdateGuestCharacter` 处理分支（在 `PlayerMessage` 分支之后、`_ =>` 之前）：收到后更新房主 DB 的 `guest_character_json`，并广播 `GuestCharacterUpdated` 给所有已连接房客 + emit 到房主本地前端
- `src-tauri/src/commands/rooms.rs`：
  - `room_update_guest_character` 命令重写：
    - 房客模式（`room_client` 存在）：通过 `RoomClient::send_message` 发送 `UpdateGuestCharacter` 给房主 TCP 服务器，不再直接操作房客本地 DB
    - 房主模式（`host_server` 存在）：直接更新本地 DB + 广播 `GuestCharacterUpdated`（兜底）
    - 两者都不是：返回明确错误 `"当前既非房客也非房主模式，无法更新角色卡"`
  - 移除了原来对房客本地 DB 的 `SELECT id FROM conversation_members` 校验（房客本地 DB 无房间数据，该校验必然失败）
- `.trae/specs/multiplayer-host-ops-and-guest-card-sync/checklist.md`：新增"房客→房主转发链路（TCP 上行）"检查项

### 改动逻辑

原 `room_update_guest_character` 命令在房客机器上执行时：
1. `state.db` 是房客本地 DB，但房客是纯内存模式，本地 DB 没有 `conversation_members` 记录 → `member_exists.is_none()` 返回错误
2. 即使能通过校验，`update_guest_character_json` 也是更新房客本地 DB，不是房主 DB
3. `host_server` 在房客机器上为 None，广播被跳过

修复后的链路：
```
房客 RightDrawer 切换角色卡
  → roomUpdateGuestCharacter(conversationId, memberId, character)
  → room_update_guest_character 命令
  → 检测 room_client 存在（房客模式）
  → RoomClient::send_message(UpdateGuestCharacter { member_id, character })
  → TCP 帧传输到房主 RoomServer
  → RoomServer read loop 收到 UpdateGuestCharacter
  → 更新房主 DB conversation_members.guest_character_json
  → 广播 GuestCharacterUpdated 给所有房客 + emit 到房主前端
  → 所有房客（含发送者）收到 room:guest_character_updated 事件
  → 前端更新 selectedConversationMembers 信号
```

## 改动动机

后端 sub-agent 实现了 5 个 RoomMessage 变体和广播补全，但 `room_update_guest_character` 命令仍走"直接操作本地 DB + 本地广播"的路径，在房客机器上完全失效（房客本地 DB 无数据、host_server 为 None）。本次修复补全了房客→房主的 TCP 上行转发链路，使房客角色卡更新能真正到达房主 DB 并广播给所有人。

### 代码审查
- `UpdateGuestCharacter` 变体在 `event_name()` 走 `_ =>` 返回 `"room:message"`，在 `event_payload()` 走 `_ => None`，不会被 emit 到前端（仅 TCP 传输）
- RoomServer read loop 的 `UpdateGuestCharacter` 分支使用 `clients.read().await` 遍历所有已连接房客的 `tx` 广播 `GuestCharacterUpdated`，同时 `app_handle.emit` 通知房主本地前端
- `room_update_guest_character` 命令使用 `state.room_client` 获取 RoomClient，`drop(room_client_guard)` 释放锁后再获取 `host_server` 锁，避免死锁

## 已知限制或后续待办

1. **移动端未接入**：`src-mobile/` 多人房间功能尚未实现，后端 `RoomMessage::UpdateGuestCharacter` 已就绪，移动端实现时需在 RoomClient read loop 中处理 `GuestCharacterUpdated` 事件。
2. **`UpdateGuestCharacter` 无 ACK 机制**：房客发送后不等待房主确认，若 TCP 丢包则房客不知道更新是否成功。当前靠房主广播 `GuestCharacterUpdated` 回流作为隐式 ACK（房客收到自己的更新广播即知成功）。若网络抖动未收到，下次 `room_request_context` → `ContextSnapshot` 全量同步作为兜底。
3. **房客角色卡 `guestCharacterJson` 前端缓存丢失**：`refreshConversationContext` 刷新后后端 `ConversationMember` 结构体未序列化 `guest_character_json`，前端缓存的 `guestCharacterJson` 会丢失，需等下一次 `GuestCharacterUpdated` 事件重新填充。若需持久化需另立 spec。
