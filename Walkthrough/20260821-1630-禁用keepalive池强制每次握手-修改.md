# Walkthrough - 20260821-1630 禁用 keep-alive 池、强制每次握手 - 修改

## 1. 改动摘要
- 文件：`src-tauri/src/services/http_client.rs`
- 函数：`shared_permissive_http_client()`
- 改动：在 `Client::builder()` 链中新增 `.pool_max_idle_per_host(0)`，禁用空闲连接池；并加注释说明原因与未来约束。
- 控制流/重试/fallback 均未改动（C2 不触发回退）。

## 2. 改动动机
- 2026-08-21 NVIDIA 自定义 provider（openai_compatible）请求失败，日志（提交 `6355dea` 增强后）显示：
  `cause=client error (SendRequest) <- connection error`，`connect=false timeout=false request=true`。
- 根因为 `shared_permissive_http_client()` 是全局单例 + keep-alive 连接池：Akamai/NVIDIA 边缘对空闲连接超时关掉后，池仍复用该死连接，发请求阶段才暴露 `connection error`；因 `auto_retry disabled` 首败即终止。
- curl 同机同 URL 发 124KB 带鉴权 POST 拿到 401，证明网络/代理无碍，纯应用侧池复用死连接。
- 临时修复（用户决策）：禁用空闲池，强制每次请求新建连接并重新 TLS 握手，根除死连接复用。代价为每次多一次亚秒级握手，对稀疏聊天可接受。
- 注释明确约束：未来 agent 模式（密集串行 LLM 调用）**不得使用此客户端/此线路**，应改为「保留池 + 传输层对 connection error 重试一次」，以免每步累积握手延迟。
