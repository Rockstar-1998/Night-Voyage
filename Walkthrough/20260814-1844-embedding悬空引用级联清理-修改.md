# 20260814-1844-embedding悬空引用级联清理-修改

## 1. 改动摘要

针对"方案 A"暴露出来的**根因**（删除 API 档案后，会话/角色卡仍指向已不存在的 provider id，产生悬空引用 `embedding_provider_id=0`，进而在 `conversations_update_bindings` 触发 `embedding_provider_id 指向的 API 档案不存在`），本次从两处彻底修复：

- **`src-tauri/src/commands/providers.rs`** — `providers_delete` 命令重写：
  - 原实现是裸 `DELETE FROM api_providers WHERE id = ?`，不清理任何引用，留下悬空外键式的指针（违反"无效状态不可表达"）。
  - 新实现把删除与引用清理包进**同一个事务**（`.begin()` → 多条语句 → `tx.commit()`），原子性地：
    1. 删除 `api_providers` 行；
    2. `UPDATE conversations SET provider_id = NULL WHERE provider_id = ?`；
    3. `UPDATE conversations SET embedding_provider_id = NULL WHERE embedding_provider_id = ?`；
    4. `UPDATE character_cards SET default_provider_id = NULL WHERE default_provider_id = ?`；
    5. `DELETE FROM llm_retry_snapshots WHERE provider_id = ?`（`provider_id` 为 NOT NULL，无法置空，删孤儿行）。
  - `api_provider_models` 已通过表级 `ON DELETE CASCADE` 自动处理，此处不复写。
  - 所有错误均 `?` / `map_err(|e| e.to_string())` 显式上抛，**无静默吞异常、无自动降级**（符合 C2）。

- **`src-tauri/migrations/0045_cleanup_dangling_provider_refs.sql`**（新增）—— 一次性修复**存量**悬空引用：
  - `UPDATE conversations SET provider_id = NULL WHERE provider_id IS NOT NULL AND provider_id NOT IN (SELECT id FROM api_providers)`；
  - `UPDATE conversations SET embedding_provider_id = NULL WHERE ...`（仅 MEM0 模式使用，非 mem0 下应为 NULL）；
  - `UPDATE character_cards SET default_provider_id = NULL WHERE ...`；
  - `DELETE FROM llm_retry_snapshots WHERE provider_id NOT IN (SELECT id FROM api_providers)`。
  - 迁移在应用启动时由 `sqlx::migrate!()` 自动执行，与 `_sqlx_migrations` 表校验和机制一致。

## 2. 改动动机

方案 A（按 memory_mode 分流校验）解决了"报错阻断"，但属于**症状缓解**：它让非 mem0 会话跳过 embedding 校验，并未消除数据库里已存在的 `embedding_provider_id=0` 这类悬空引用。只要那条脏数据还在，任何读取/校验路径都可能再次踩雷，且数据本身处于"指向不存在实体"的无效状态。

彻底解法是在**写入侧**保证引用完整性：删除 provider 时已不再被引用的外键必须一并清空。这正好对应项目规范 AGENTS.md 的三条硬性代码风格约束——
- L116 低耦合 / 模块边界清晰；
- L120 组合优于继承（用独立类型 + 公共 trait，而非 bool 开关推迟类型决策）；
- L121 类型驱动、最小分支、"`if let Some(x)=y {...} else {alt.foo()}` 这类把类型决策推迟到运行期的标志位"应改 trait 调度。

悬空引用本质是"运行期仍允许表达无效状态"，与 L121 "无效状态不可表达"直接冲突。本方案在删除命令的事务里强制把引用归零，使无效状态在源头无法成立。
