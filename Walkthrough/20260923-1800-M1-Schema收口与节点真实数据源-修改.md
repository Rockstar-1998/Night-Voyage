## 改动动机

盘点时曾判定「`retention_depth` 未被消费」，实测**早已实现**（`prompt_compiler.rs` 原 950-983 行），
真缺口是两点：① `Some(0)` 被 `if depth >= 1` 静默忽略（违反 C2，非法配置应当报错）；
② 裁剪按「任意 JSON 对象」计数，多 Schema 并用时会把别的 Schema 的历史算进层数导致误裁。
本次把逻辑抽成可测模块并修掉这两点。

节点配置改用真实数据源下拉，是 C11「禁止硬编码数据」的直接落地：
此前 Schema/布局都要手打 ID，既容易打错也无从发现"该预设根本没有这个 Schema"。

## 运作机制

- `dropped_indices(is_assistant[], contents[], schema)`：按 `schema.fields[].name` 做签名识别
  （内容须为 JSON 对象且至少命中一个字段名），从最新往前倒数保留 `retention_depth` 层，
  更早的下标进丢弃集合；`None` 不裁剪、`Some(0)` 返回 `Err`。
- `prompt_compiler` 逐 Schema 调用后按返回下标 `retain`，日志记录丢弃层数。
