# Walkthrough: 移动端聊天 UI 与结构化输出渲染（补齐 C7 缺口）

- 修改类型: 新增
- 日期: 2026-08-22
- 主题: 移动端此前聊天界面为占位符，结构化输出完全不渲染（C7 缺口）；本轮补齐完整聊天 UI + 结构化渲染

## 1. 改动摘要

**背景**：移动端 `src-mobile/App.tsx` 的聊天视图原为占位符（原文"移动端单聊与群聊发消息界面正在开发中"），
消息列表 / 流式接收 / 输入框 / 结构化渲染全部缺失。PC 端此前修复的数组字段渲染（commit cd2e29b）
在移动端同样看不到——因为移动端根本没有渲染层。

**改动文件与职责**：

- `src-mobile/lib/structured.ts`（新增）
  结构化解析纯函数：`parseStructuredResponse`（解析完整 JSON 回复体）、
  `parseStreamingFields`（解析流式过程中 key→JSON 字符串的 `structuredFields`）。
  逻辑对齐 PC 端 `messageFormatter.parseStructuredResponse` 与 `MessageItem` 的
  `streamingStructuredMode` memo，但为**移动端本地副本**（遵守 C5 前端独立，不复用 PC 组件代码）。

- `src-mobile/components/MobileStructuredRenderer.tsx`（新增）
  结构化字段渲染，对齐 PC 端 `MessageFormatRenderer` 的 `StructuredResponseRenderer`：
  - string 字段：可折叠分区（标签=字段名），`hideLabel` 时直接显示正文；
  - object 字段：只读键值卡片；
  - array 字段：编号可点击选项，点击回调 `onChoiceSelect` → 作为新用户消息发送。

- `src-mobile/components/MobileChatView.tsx`（新增）
  移动端聊天视图：
  - 加载历史：`messagesList(conversationId)`（过滤 `user_visible`/`assistant_visible`/`system`）；
  - 流式接收：`listenLlmStreamEvent` 监听 `llm-stream-event`，按 `eventKind` 处理
    `text_delta`（追加 content）/ `string_field_delta`（追加结构化字符串）/ `object_field_complete`
    （写入结构化 JSON）/ `message_stop`（结束）/ `compatibility_mode`（标记）；
    并监听 `listenStreamError` / `listenStreamRetry`；
  - 发送：`sendMessage(conversationId, providerId, content)`，upsert 用户/助手消息为流式；
  - 气泡渲染：用户右对齐、助手左对齐；助手正文优先走 `parseStreamingFields`（流式）或
    `parseStructuredResponse`（历史/流结束后的 content JSON），否则纯文本；
  - 输入栏：textarea + 发送按钮（Enter 发送 / Shift+Enter 换行），回复中禁用。

- `src-mobile/App.tsx`（修改）
  将占位符替换为 `<MobileChatView>`，传入 `conversationId`、`providerId`
  （取自 `sessions.find(...).providerId`）、`onBack`。

## 2. 改动动机

用户确认：上一轮 PC 端数组字段渲染修复后，移动端仍完全不渲染结构化输出。判定为 C7 双端覆盖缺口，
用户选择"完整聊天 UI + 结构化渲染"。由于移动端聊天界面整体是占位符，结构化渲染无法孤立挂载，
故一并实现最小可用聊天视图（列表 + 流式 + 发送 + 结构化渲染），对齐 PC 端渲染逻辑。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 解析与事件下发在后端，移动端只渲染 |
| C2 Zero-Fallback Errors | √ | 流式错误走 `showToast` + `error` 字段展示，无静默回退 |
| C3 Responsiveness | √ | 事件增量更新，自动滚动到底 |
| C4 AI UI Isolation | √ | 不涉及 AI 生成 UI 沙箱 |
| C5 Mobile Frontend Independence | √ | `structured.ts` 为本地解析副本，未 import PC 组件；复用 PC `src/lib/backend` 的 TS glue 是既有模式（App.tsx 已如此），C5 仅要求前端代码独立、共享 Rust 命令 glue 允许 |
| C6 Project Cache Location | √ | 无缓存写入 |
| C7 PC/Android Coverage | √ | 补齐，渲染逻辑与 PC 端对齐 |

## 5. 已知限制或后续待办

- **仅沙箱验证打包**：移动端 app 需在真机/模拟器连接 Rust 后端实测流式接收与发送（沙箱无法跑 Tauri webview）。
- 发送依赖会话 `providerId`（取自 `ConversationListItem.providerId`）；若会话未绑 provider，
  发送按钮在回复空闲态下仍可用但会提示"未绑定供应商"——后续应让会话选择页或设置补全 provider。
- 未实现（后续任务）：abort 中断回复、regenerate、swipe 多版本、联机房间消息收发。
  本轮仅单聊"发送→流式接收→结构化渲染"闭环。
- 纯文本非结构化回复仅做 `whitespace-pre-wrap`，未接入 PC 的伪 XML 富文本格式
  （折叠标签 / 斜体 / 引用等）；如需一致体验后续可补移动端格式解析。
- `dist/` 为构建产物，已被 `.gitignore` 忽略，不纳入提交。
