# 20260915-0149-常驻响应式HUD与UI模板编辑器架构定案-修改

## 1. 改动摘要

- **受影响文件**：[`plans/agent-system-architecture-plan.md`](file:///d:/data/Night%20Voyage/plans/agent-system-architecture-plan.md)
- **改动内容**：
  1. **新增常驻响应式 UI 引擎架构（第 4 节）**：
     - **告别尾随卡片**：彻底摒弃传统“每轮把结构化数据卡片追加在最新消息底部”的过时设计，解决历史消息过期卡片冗余、滚动视线脱靶与大量重复 DOM 渲染开销问题；
     - **常驻锚点（Dock Anchors）**：在会话视口提供固定停靠位：
       - PC 端：右侧常驻仪表盘（`RightDock`）、顶部吸顶横幅（`TopSticky`）、画中画浮窗（`FloatingHUD`）；
       - 移动端（`src-mobile/`）：顶部吸顶精简条（`TopHUD`，点击滑出全屏背包抽屉）与输入框附着条（`BottomSticky`）；
     - **原地响应式补丁（In-Place Reactive Patch）**：基于 SolidJS 细粒度 Signal，由后端 `session:hud_state_patch` 事件驱动特定 DOM 节点毫秒级局部刷新，消息流不追加任何冗余卡片；
  2. **可视化 UI 模板编辑器（UI Template Designer）**：
     - **低代码开箱组件库**：`StatBar`（血条/蓝条/负重渐变条）、`InventoryGrid`（道具槽位/堆叠/气泡）、`AttributeList`（四维属性与金币）、`QuestTracker`（任务目标看板）、`SceneBanner`（场景天气与地点）；
     - **自由代码模式（C4 沙箱隔离）**：支持自定义 HTML + Tailwind 模板，强制置入 `iframe` / `Shadow DOM` 隔离运行，仅通过只读通信桥同步 `GameState`，绝不污染 SolidJS 宿主；
  3. **ToolCall 数据双向修改链路**：
     - 蓝图新增 `UILayoutConfig` 节点，将 ToolCall、运算器（`Calculator`）与 `GameState` 状态变更无缝映射并同步到常驻 UI 插槽中；
  4. **全案章节重构与实施里程碑更新**：顺延核心 Agent 时序（第 5 节）、连线拓扑（第 6 节）、现有系统配合（第 7 节）、用户侧体验与调试（第 8 节）、实施里程碑（第 9 节，新增 Milestone 3）。

## 2. 改动动机

响应用户提出的核心诉求：“UI呢？可能需要一个UI编辑器，然后允许toolcall填充或修改模板数据，同时允许UI常驻显示在会话的某处，而不是每轮放在最新回复下”。
原设计将结构化卡片当作消息附件，既无法支撑连续 RPG 游戏的全局状态感知，又污染了对话气泡流。通过构建常驻响应式 HUD 与 UI 模板编辑器，实现了真正现代游戏化的界面体验。

## 3. 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | UI 模板仅根据后端下发的 `GameState` 进行响应式渲染，所有数值计算与道具判定留在 Rust |
| C2 Zero-Fallback Errors | √ | 模板语法错误或字段绑定缺失显式弹窗报错，严禁静默吞错 |
| C3 Responsiveness | √ | 采用细粒度 Signal 局部更新，无全局重绘，消息打字机动画零卡顿 |
| C4 AI UI Isolation | √ | 自定义 HTML/Tailwind 模板严格物理隔离在 `iframe`/`Shadow DOM` 中，零污染 SolidJS 宿主 |
| C5 Mobile Frontend Independence | √ | PC 侧边/吸顶仪表盘与移动端吸顶条/底部抽屉完全物理隔离独立实现，零共享 UI 代码 |
| C6 Project Cache Location | √ | 纯内存事件驱动与轻量 SQLite 状态同步，不向磁盘写入多余碎文件 |
| C7 PC/Android Coverage | √ | 常驻 HUD 与模板在 PC 宽屏与移动端竖屏均有专门的停靠规范与交互闭环 |
