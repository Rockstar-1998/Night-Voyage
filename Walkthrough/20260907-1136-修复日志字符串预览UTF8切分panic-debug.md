# 修复日志字符串预览UTF8切分panic - debug

## 一、改动摘要

### 1. `stream_processor.rs`
- 在 `stream_llm_response` 打印 `structured_output_schema` 日志预览时（原第 617 行），由裸字节切片 `&s[..80]` 改为基于 `char_indices().nth(80)` 的安全字符边界切片；
- 避免当 Schema 内含有中文描述（如“正文”“思维过程”等多字节 UTF-8 字符）且字节 80 恰好处于多字节字符中间时，触发 `end byte index is not a char boundary` 导致 tokio runtime worker panic。

### 2. `commands/providers.rs`
- 在 `log_text_preview` 中，将原本的字节切片 `&normalized[..MAX_PREVIEW_LEN]` 同步重构为 `normalized.char_indices().nth(MAX_PREVIEW_CHARS)`，彻底杜绝任何类似的多字节切分隐患。

---

## 二、改动动机

- 用户在发起流式聊天请求时，`tokio-rt-worker` 报错崩溃：
  ```
  thread 'tokio-rt-worker' (4064) panicked at src\services\stream_processor.rs:617:111:
  end byte index 80 is not a char boundary; it is inside '文' (bytes 79..82 of string)
  ```
- 经定位，该日志打印代码使用 `&s[..80]` 试图截断前 80 个字节作为简要预览，但在多字节中文字符处截断不是合法的 UTF-8 字符边界，直接引发运行时 panic。
- 本次改动通过字符迭代器 `char_indices()` 确保所有截断点 100% 落在合法字符边界上，彻底根除此类崩溃。
