# 蓝图 Schema 字段：根据 Gate 配置动态生成

## 改动摘要

| 文件 | 改动 |
|------|------|
| `测试预设/gen_default_preset.py` | 新增 `schema_field()` 节点工厂；新增 3 个 SchemaField 节点；调整 12 条边 |
| `测试预设/Night Voyage 默认预设.nvpreset.json` | 重新生成（30 节点 / 41 边 / 15854 bytes） |

## 改动动机

用户指出原版默认预设两个问题：
1. **缺少 schema 字段**：编辑器里默认 SchemaField 是空的占位符，没有真正声明过 schema
2. **没有 Gate 驱动的 schema**：当用户在 GroupGate 里勾选「内心独白」/「行动选项」时，下游 schema 不应变化——但它们应该有变化

修复方式：在 GroupGate 选项后插入 SchemaField 节点，让蓝图执行器只在该 Gate 选中时遍历到 SchemaField，进而把字段加入 `structured_output_schema`。

## 新增节点

```
n_thinking_schema   ← 基础 schema，始终在场
                     field_name: "thinking"
                     field_type: "string"
                     description: 角色思维链
                     sub_schema: null

n_options_schema    ← 「行动选项」Gate 开启时才被遍历
                     field_name: "options"
                     field_type: "array"
                     sub_schema: { "items": { "type": "string", ... } }

n_monologue_schema  ← 「内心独白」Gate 开启时才被遍历
                     field_name: "monologue"
                     field_type: "string"
                     sub_schema: null
```

## 拓扑变化

```
[GroupGate 选项]
  out_anti_spoil    → n_mod_anti_spoil  ────────────────────┐
  out_lang_real     → n_mod_lang_real   ────────────────────┤
  out_env_rich      → n_mod_env_rich    ────────────────────┤ 直连 ModeSwitch
  out_inner_mono    → n_mod_inner_mono  → n_monologue_schema │
  out_actions       → n_mod_actions     → n_options_schema   ┘
```

`n_rules → n_thinking_schema → n_params`：基础 schema 必经
`n_mode → {n_mem_stateless | direct | n_mem_mem0} → n_thinking_schema`：三条记忆路径都汇入基础 schema

## 验收记录

- 蓝图图：30 节点 / 41 边，全部 SchemaField 配置合法
- Wiring 校验通过：
  - `n_thinking_schema`：4 条入边（n_rules + 三条记忆模式分支），始终在场
  - `n_options_schema`：仅从 n_mod_actions 入边，Gate 关闭时不遍历
  - `n_monologue_schema`：仅从 n_mod_inner_mono 入边，Gate 关闭时不遍历

## 已知限制

- 所有 SchemaField 的 `db_mapping` 都为 null（不持久化）。如需持久化某些字段到 `world_variables` 或 `plot_summary`，可在编辑时手动设置
- response_mode 仍为 `pseudo_xml`，schema 字段作为辅助输出结构提取，与 XML content 标签并行存在
