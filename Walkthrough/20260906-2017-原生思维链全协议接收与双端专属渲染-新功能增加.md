# 原生思维链全协议接收与双端专属渲染

## 改动摘要

1. **后端数据模型与持久化层**：
   - `src-tauri/src/models/mod.rs`：在 `UiMessage` 结构中新增 `pub thinking: Option<String>`，支持序列化到前端。
   - `src-tauri/src/repositories/message_repository.rs`：
     - 在 `list_by_conversation` 和 `find_by_id` 中增加对 `message_content_parts` 表的关联子查询，精准获取 `part_type = 'thinking'` 的思考内容并映射至 `UiMessage.thinking`。
     - 在 `row_to_ui_message` 映射解析中引入 `thinking: row.try_get("thinking").ok()`。
2. **后端流式接收与分发引擎**：
   - `src-tauri/src/services/stream_processor.rs`：
     - 在 OpenAI 兼容协议流式解析主循环中，级联嗅探 `reasoning_content`、`reasoning`、`thinking` 字段，严格防御 `null` 值；
     - 发现思维链增量时，自动通过 `ensure_content_part_by_key` 记录进 `message_content_parts` 表（`part_type: "thinking"`），并即时向前端发射 `thinking_delta` 流事件；
     - 在流结束落盘时，保证纯文本流在没有结构化 JSON 覆盖时，依然规范沉淀 `text` content part，并完整保留已写入的 `thinking` content part；
     - 结合 Anthropic 原生流协议（此前已有的 `content_block_start(type="thinking")` 与 `thinking_delta`），实现双协议无缝覆盖。
3. **前端类型与 PC 端专属 UI**：
   - `src/lib/backend/types.ts`：更新 `UiMessage` 类型定义，包含可选 `thinking?: string`。
   - `src/lib/icons.ts`：导出 `Brain` 与 `BrainCircuit` 脑力专属图标。
   - `src/components/NativeThinkingBlock.tsx`（新增专属组件）：
     - 遵循用户关于“独立 UI 渲染，不复用现有组件，保持视觉独特性”的要求；
     - 采用深靛冷灰暗调玻璃拟态设计（`bg-gradient-to-b from-indigo-950/40 via-slate-900/50 to-slate-950/60`，`backdrop-blur-md`，`border-indigo-500/20`）；
     - 思考中状态：Pulsing 呼吸流光灯点、流式打字光标、动态字数统计；
     - 思考完成状态：静态微光徽标与字符计数；
     - 使用 Motion One（`animate`）实现流畅折叠/展开过渡。
   - `src/components/MessageItem.tsx`：
     - `ChatMessage` 接口扩充 `thinking?: string`；
     - 在 AI 回复的消息体顶部独立挂载 `<NativeThinkingBlock>`。
   - `src/App.tsx`：
     - `toChatMessage` 增加 `thinking: message.thinking` 字段映射；
     - `listenLlmStreamEvent` 接入 `case 'thinking_delta'`：实时累加思维链流式增量至消息状态并触发响应动画。
4. **移动端独立专属 UI**：
   - `src-mobile/components/MobileNativeThinkingBlock.tsx`（新增移动端专属组件）：
     - 严格遵循 C5 移动端零 UI 代码复用约束，独立编写；
     - 针对触屏优化交互热区与触感反馈；
     - 具备独立的流式呼吸灯、字数统计及折叠展开交互。
   - `src-mobile/components/MobileChatView.tsx`：
     - `handleStreamEvent` 接入 `case 'thinking_delta'` 实时累加；
     - 在消息卡片 `renderAssistantBody` 中独立挂载 `MobileNativeThinkingBlock`，并在流式思考中智能避让正文占位提示。

## 改动动机

- 此前系统流式接收引擎将原生思维链视为“隐藏中间数据”并在前端忽略，且在 OpenAI 兼容协议下缺乏对 `reasoning_content` 的字段提取和安全过滤，导致 DeepSeek-R1、Claude Extended Thinking 等支持原生思考链的模型输出无法持久化与展示。
- 结构化输出折叠与正文标签不能满足深度思考过程的视觉呈现需求，需要专属的科技感/暗调玻璃拟态 UI 与丝滑流式动画。

## 约束合规审计表

| 约束 | 合规 | 说明 |
|------|------|------|
| C1 Frontend Render-Only | √ | 前端仅监听 `thinking_delta` 和渲染 `thinking` 字符串，协议嗅探、SSE 解析、`message_content_parts` 写入全部由 Rust 后端完成 |
| C2 Zero-Fallback Errors | √ | 显式处理字段提取，严格防御 `null` 值，不静默丢弃真实报错，无伪造成功 |
| C3 Responsiveness | √ | 动画使用 Motion One 与 Web Animations API（WAAPI）驱动合成器属性，折叠过渡不引起主线程卡顿；长思维链设有限高与局部滚动 |
| C4 AI UI Isolation | √ | 原生思维链属于宿主渲染组件，不破坏既有沙箱边界 |
| C5 Mobile Frontend Independence | √ | `src/` 与 `src-mobile/` 各自实现独立的专属 ThinkingBlock 组件，零 UI 代码互引，无 `isMobile` 分支 |
| C6 Project Cache Location | √ | 构建与工具链均运行在 `D:\data\Night Voyage\.cache` 及本地配置，未向系统盘写入缓存 |
| C7 PC/Android Coverage | √ | 后端单套接口同时支持 PC 前端与移动端前端，两端均具备完整的实时流式接收与历史记录持久化还原能力 |

## 验收记录

### 1. 真实接口实验（对照组 1 & 对照组 2）
- **对照组 1（AMD 平台 DeepSeek-V4-Flash-Vision-Exp）**：
  - 实测验证非推理模型在 OpenAI 协议下返回 `choices[0].delta.reasoning_content: null`；
  - 后端 Rust 通过 `.and_then(|rc| rc.as_str())` 成功防御，避免 `null` 导致的空指针或虚假 delta。
