# 20261025-1701-审查二轴反馈治理与穷尽匹配引脚类型严格校验-修改

## 1. 改动摘要

- **`src-tauri/src/services/blueprint_executor.rs`**:
  - `output_port_priority`: 消除 `_ => return 0` 通配兜底，穷尽枚举 `NodeConfig` 所有变体分支，彻底遵循 `AGENTS.md` Rust 代码规范要求。
  - `inline_single_macro_instance`: 移除 `n.id == "inputs" || n.id.starts_with("outputs_")` 等字符串启发式匹配残留，严格按 `matches!(n.config, NodeConfig::MacroInputs/Outputs)` 与 `NodeType` 强类型识别代理节点，消除 Primitive Obsession 代码异味。
  - `test_macro_pin_type_validation`: 新增 Spec Line 196 显式断言测试（`Number` 连向 `Object` 必须失败），验证宏引脚类型的严格校验。
- **`src-tauri/src/models/blueprint.rs`**:
  - `PinType::is_compatible`: 严格对齐 Spec Line 196 规定（`Number` 连向 `Object` 必须在编译校验期报错），数据引脚实施严格同构类型匹配 `self == other`，杜绝通配宽容放行。
- **`src/components/blueprint/nodeLayout.ts` & `src-mobile/components/blueprint/mobileNodeLayout.ts`**:
  - `isPinTypeCompatible`: 双端前端同步对齐严格匹配规则（`a === b`），禁止 `Number` / `Object` 交叉混用。

## 2. 改动动机

- 依据 Code Review 审查反馈：
  1. Standards 轴指出 `output_port_priority` 中存在 `_ => return 0` 通配匹配违规，且宏展开存在字符串启发式判别。
  2. Spec 轴依据 Spec Line 196（*Confirm that invalid data pin connections (e.g. Number wired to Object) fail compile validation*）指出此前将 `Object` 视为宽松 `Any` 允许连接 `Number` 违背了规范中的静态编译阻断要求。
