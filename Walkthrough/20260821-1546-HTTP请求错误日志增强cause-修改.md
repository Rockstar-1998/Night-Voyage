# [修改] HTTP 请求失败日志增强：补出底层 cause

## 1. 改动摘要

- 文件：`src-tauri/src/services/stream_processor.rs`
  - 函数：`execute_provider_http_request` 内 `.send().await.map_err(...)` 的错误格式化闭包。
  - 改动：在原有 `connect/timeout/request/body/decode/redirect` 布尔标记之外，新增对 `std::error::Error::source(&err)` 的提取（最多取两层 cause 链），拼接到报错字符串末尾：`| cause=<底层原因>`。
  - 仅扩展错误信息文本，不改变任何控制流、重试逻辑、fallback 路径。

## 2. 改动动机

此前 NVIDIA 自定义 provider 请求失败，应用只报：

```
HTTP 请求发送失败: error sending request for url (https://integrate.api.nvidia.com/v1/chat/completions) | connect=false timeout=false request=true body=false decode=false redirect=false
```

`{}` 对 `reqwest::Error` 的 Display 未携带底层 cause，布尔标记 `connect=false` 仅说明 TCP+TLS 握手成功、失败在建连之后，但**真正的根因（connection reset by peer / broken pipe / TLS alert / 中间代理拒绝）被吞掉**，永远定位不到。

本次增强让下次同类报错直接显示真实原因，一眼区分是本地杀软/透明代理拦截、还是服务端 WAF 在连接层重置。属于 C2（零静默回退/不吞错误）的正向加固。

网络侧已实锤排除：本机 `curl` 直连同一 URL（HTTP/1.1，应用同样仅用 HTTP/1.1）TCP+TLS+HTTP 全通，服务端回 405；DNS 正常、无代理环境变量。故该故障属软件/中间层，非网络。
